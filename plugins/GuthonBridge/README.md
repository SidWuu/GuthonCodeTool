# Guthon Bridge

Guthon Bridge 是面向 Guthon 在线开发页面的本地辅助扩展，由 Chrome 扩展和本地 HTTP 桥接服务组成，与 Guthon Nexus 配合使用。

## 功能

- 标签排序：拖动顶部功能标签或模块开发、过程函数的编辑标签，在同一排内调整顺序；首页和右侧菜单固定。上层顺序按平台地址保存在当前 Chrome 扩展中，下层顺序在本次页面使用期间保留；刷新后不恢复下层顺序。兼容已识别的 Element 卡片标签栏，无需本地 Bridge 服务。操作见[使用手册](../../docs/GuthonCodeTool_使用手册.html#bridge-tab-sort)，适用范围见[全功能说明](../../docs/GuthonCodeTool_全功能说明.html#bridge-tab-sort)。
- 谷神管理列表滚动优化（主要适配 2.0，1.5 复用相同控件，未知或不匹配布局跳过）：数据表管理主列表（表格和卡片视图）及表字段列表、开发日志和增量发布保留顶部操作按钮；模块参数、系统脚本和视图管理固定查询区与左侧树，列表独立纵向滚动，并支持横向滚动访问小屏幕上的操作列。数据字典保留左侧分类树；数据字典和单据类型保留查询、操作和分页区，列表独立滚动并支持小屏横向滚动。定时任务管理的横向滚动条保留在列表可视区域内。安装或更新 Chrome 扩展后刷新平台页面生效，无需连接本地 Bridge 服务。
- 快捷跳转：在过程函数和模块后台脚本中，按住 Ctrl（Mac 为 Cmd） 点击高亮的静态过程方法名可打开对应过程函数，支持 `proc.invoke`、`thread.run`、`thread.runFutureTask` 及 `proc.find` 绑定调用（目标包名、函数名须为静态字面量），同样支持函数内子方法跳转。`$vs.proc.runServiceComp`、`$vs.thread.runServiceComp` 支持在静态组件 ID 上点击，按精确 PAGE ID 打开模块开发中的服务组件；目标须在当前应用系统的对象树中。
- 签出列表定位：过程函数“由我签出的页面”中，点击勾选列与签出者列之间的“操作”列的“打开”按钮，按完整过程与函数身份打开源码；筛选或刷新后继续可用，打开不改变勾选状态。
- 复制模式：在模块开发页打开复制模式，按页面块展示字段信息，便于复制和整理。
- 字段平移：在模块开发页的字段平移按钮组中复制字段并粘贴到另一个已选组件。
- 当前源码拉取：在过程函数页识别当前脚本，并保存为本地文件。
- 函数定位：在过程函数脚本中点击谷神自带的定位按钮；高亮过程函数名时，页面滚动到对应的过程函数。

### 当前对象刷新与定位

页面按钮或 Chrome 弹窗的“刷新当前对象”将 PAGE、过程函数、选中的表、视图或系统脚本身份交给工作区的 API 定向刷新。表、视图和系统脚本须只选择一个具体对象；未选择或选择多个时提示，不会自动拉取全部。单据类型目前不在 API 源码目录中，刷新会明确提示不支持。定向刷新、对象类型及本地文件冲突处理依赖后端 API 实现；存在冲突时查看返回的结果并处理本地修改。

过程函数弹窗底部的“导出页面当前源码”从平台读取当前已保存源码，保存到 Bridge 的独立导出目录，与工作区 API 刷新是两个操作。已有同名文件内容不同时拒绝覆盖，请先备份或移走。该导出不会采集编辑器中尚未保存的内容。

在模块开发或过程函数页点击“在 Nexus 中打开…”或“在 Nexus 定位”，将完整 PAGE ID 或过程包名与函数名发送给 Nexus，由 Nexus 根据 API 目录选择工作区和源码。若 VS Code 已被唤起但没有工作区选择或报错，重新安装包含 URI 入口的 Nexus 并执行 `Developer: Reload Window`。

页面按钮先挂载，后台再尝试识别页面身份和发布上下文；未选对象或本地 Bridge 暂不可连接时自动识别保持安静，用户点击时报告原因。

### Nexus → 平台定位与页面上下文

在 Nexus 的“谷神源码”树选择 PAGE 或过程函数，执行右键“在谷神平台定位源码”，也可从命令面板对当前源码文档执行。先在 Chrome 打开平台、完成 Bridge 配对并选择对应工作区；仅操作已有平台页签，多页签由当次选择。PAGE 按完整编码定位，过程函数按精确包名、函数名和当前平台数据源匹配；多份候选报错并要求在平台选择数据源。导航复用平台路由和对象树，不构造未经验证的对象 URL，不保存平台数据。

Bridge 的带令牌 `GET /pageContext?workspaceKey=...` 返回该工作区的有界元数据快照：平台 origin、去掉查询参数的 hash、PAGE/过程函数身份、数据源/系统身份、选中页签及最多 32 个打开页签。正文、SQL、选中文本、编辑令牌及本机路径不进入快照。最多保留 64 个页签，租约 150 秒；关闭或跳离平台时删除，服务重启后等待浏览器重新发布。

浏览器后台通过 Bearer 头订阅 `GET /events?clientId=...`，接收定位指令；本机客户端可按明确 `workspaceKey` 订阅快照变化与定位回执。令牌不放在 URL，网页 Origin 被拒绝。导航请求、当前平台身份和工作区在服务端及浏览器分别校验；过期、断线、来源或工作区改变均拒绝，重连不重放导航。定位指令和工作区快照变化通过事件推送，60 秒元数据租约心跳用于恢复 MV3 worker 或重启的 Bridge；浏览器 DOM 页签变化仍由浏览器事件处理。Nexus 当前命令以有界查询等待定位回执，持久拉取任务继续沿原异步任务协议恢复。

## 目录

```text
plugins/GuthonBridge/
  bridge/       本地 HTTP 桥接服务
  extension/    Chrome 扩展
  package.json  启动和测试脚本
```

扩展的 Popup、页面按钮、弹窗、复制面板和导航高亮样式统一维护在 `extension/bridge.css`；JavaScript 只设置显示状态、拖拽坐标和动态列宽。

## 启动 Bridge

普通用户在 Guthon Nexus 左侧面板单击“启动 Guthon Bridge”。Nexus 会传入当前运行模式和显式本地数据目录，并使用 VS Code 自带的 Node 运行环境启动服务，不需要安装 Node.js、设置环境变量或打开终端。发行模式使用打包应用，开发模式使用仓库 `.venv` 与源码，调试模式使用本地 Python 与经校验的 Release pyz。Bridge 在自身生命周期内复用一个常驻 ToolHost；开发源码修改后需重启 ToolHost 才生效。切换本地数据目录或运行模式时，运行中的 Bridge 会自动重启。

Bridge 请求携带 `workspaceKey` 时会验证页面身份；未携带时按 `pageOrigin + dataSourceId + systemId` 匹配产品、项目配置。唯一候选直接使用，多个候选由 Chrome 扩展下拉选择，并按 `协议 + 主机 + /guthon` 记住最近一次选择；切换谷神地址或候选失效时重新选择。

工作区摘要包含服务端计算的 capabilities。Bridge 在执行定向刷新前重新验证工作区身份和 `api.pull` 能力；PAGE 平台写入还需 `api.edit`。

以下命令只用于仓库源码调试：

```bash
npm run start:bridge
```

直接启动 Bridge 时必须显式设置绝对路径 `GUTHON_TOOL_HOME`。未设置 `GUTHON_TOOL_PATH` 时，开发环境可使用仓库中的 Python 脚本；Nexus 启动时会传入所选运行入口。

默认监听：

```text
http://127.0.0.1:17361
```

健康检查：

```text
http://127.0.0.1:17361/health
```

临时切换端口：

```bash
GUTHON_BRIDGE_PORT=17362 npm run start:bridge
```

Chrome 扩展默认访问 `127.0.0.1:17361`。可在 Nexus 设置 `gushenCompletion.bridgePort`，重启 Bridge 后在 Chrome 弹窗“Bridge 配对设置”填写相同端口，不需要修改扩展代码。Nexus 等待带令牌的 `/status` 成功后才报告启动成功。端口被占用时服务明确报错，不能用其它服务的 `/health` 冒充本实例。

首次连接：在 Nexus 启动通知中点击“复制配对令牌”，打开 Chrome 扩展弹窗的“Bridge 配对设置”，粘贴令牌并点击“保存并连接”。再次执行 Nexus 的启动命令也可复制现有令牌。直接运行服务的维护者可读取 `<toolHome>/var/nexus/bridge/token`，该文件仅供本机用户读取；不要公开令牌。服务重启保留令牌，停止服务并删除令牌文件后重新启动可撤销旧配对。

除不返回本地信息的 `/health` 外，请求均需 Bearer 令牌。服务拒绝网页 Origin，不返回跨域授权头；扩展后台核对消息发送者和实际标签页地址，页面不能指定其它 origin。MAIN world 为平台编辑器访问层，与网页共享 JavaScript 环境，无法隔离平台自身的恶意脚本；它没有访问 Bridge 令牌的接口，页面发起的调用方提示需用户点击查询后才访问本地后端。

## 安装 Chrome 扩展

1. 打开 `chrome://extensions`
2. 开启“开发者模式”
3. 点击“加载已解压的扩展程序”
4. 选择 `plugins/GuthonBridge/extension/`

修改扩展代码后，需要在 Chrome 扩展页重新加载扩展，并刷新开发平台页面。

## 允许的开发平台地址

编辑独立 `extension/host-settings.js` 配置后重新加载扩展；托管更新保留该文件，程序校验逻辑由新版本提供：

```js
globalThis.GuthonBridgeHostSettings = {
  protocols: ["http:", "https:"],
  ipRanges: ["192.168.0.0/16", "192.0.2.0/24"],
  domainSuffixes: ["dev.example.com"],
  pathPrefixes: ["/guthon/"]
};
```

`ipRanges` 支持显式 IPv4 或 IPv6 CIDR（如 `fd12:3456::/32`）；默认允许范围不变，访问仍须同时满足协议、路径和 Chrome 权限。`domainSuffixes` 同时匹配配置域名及其子域名，例如 `dev.example.com` 也允许 `team.dev.example.com`。

## 使用

### 快捷跳转到过程函数

在过程函数或模块后台脚本编辑器中，按住 `Ctrl` 并点击 `$vs.proc.invoke("包名", "方法名", ...)` 的方法名，或 `$proc=$vs.proc.find("包名")` 对应的 `$proc.方法名(...)`。动态包名和动态方法名不会跳转。

模块开发跳转后：原编辑器会保留，页面内悬浮可拖动标题框，双击返回模块开发编辑器。

### 刷新当前对象

1. 启动并配对 Bridge，在平台选择 PAGE、过程函数、表、视图或系统脚本。
2. 点击页面悬浮按钮或 Chrome 弹窗中的“刷新当前对象”；表、视图、系统脚本须选择一个对象。
3. 查看结果；匹配不到对象、权限不足或出现冲突时按提示处理，不会自动扩大刷新范围。

API 定向刷新需要对应后端支持。本地已保存文件的合并与冲突保护由后端负责；VS Code 中尚未保存的编辑器内容需要 Nexus 和后端共同协调，完成联调前先保存并检查修改，再执行刷新。

### 导出页面当前源码

在过程函数页面打开 Chrome 扩展，确认当前包名和函数名及导出目录后，点击“导出页面当前源码”。已有不同内容的同名文件会被保留，操作会提示先备份或移走该文件。

### 打开复制模式

1. 打开模块开发页面。
2. 点击页面上的 `复制模式` 按钮，或点击 Chrome 扩展弹窗中的 `打开复制模式`。
3. 在弹窗中查看字段结构。
4. 从右侧文本框复制纯文本内容。

### 字段平移

1. 在模块开发页面选中来源组件，点击 `复制字段`。
2. 在弹窗中勾选字段并点击 `复制`；隐藏字段也会列出，以灰色和“隐藏”标识区分，支持全选。
3. 选中目标组件，点击 `粘贴字段`。

仅支持输入组件的字段和表格组件的列。粘贴保留显示／隐藏状态，并在目标的显示与隐藏字段中按 `fieldId` 统一跳过重复项。项目字段的 `inherit()` / `@inherit()` 脚本会按同字段的产品源码展开后复制；展开结果为空时保留空源码。缺少产品来源或无法安全展开时提示错误，不复制未解析的继承脚本。缓存只保留到页面刷新前，平台保存仍需由用户单独执行。

## 本地保存规则

- 页面导出目录默认是 `<toolHome>/var/nexus/bridge/exports`，由服务创建并显示在弹窗。
- 维护者可通过本机环境变量 `GUTHON_BRIDGE_EXPORT_ROOT` 设置另一个绝对导出目录；HTTP 请求不能选择其它目录。
- 不允许符号链接文件，读取本地映射也核验路径归属。
- 文件名来自当前函数名或片段名。
- 文件名会过滤路径非法字符。
- 同名页面导出文件内容不同时拒绝覆盖。
- 文件直接保存到服务配置的导出目录下，不按包名创建子目录；只允许 java、js、gss、sql、json、xml、txt 扩展名。

本地映射文件：

```text
<本地数据目录>/var/nexus/bridge/manifest.json
```

## 原生平台接口与回读

配对平台上下文中的 `POST /nativeMetadata` 必须绑定 workspaceKey、contextId、数据源及稳定 idempotencyKey。元数据动作包括 `inspect-guid`、`set-guid`、`inspect-page-guid`、`sync-page-guid` 与只读的 `inspect-runtime`。GUID 修复额外绑定精确表和字段，写入要求原生检查快照仍一致，仅允许将现有非空 BIGINT 主键从未配置改为平台 GUID（`isIncrement=2`）；不修改类型、数据库自增、默认值，不调用建表、物理结构同步或 SQL。

页面 GUID 同步要求先完成表字段修正，检查指定页面的主键投影并冻结原生源码版本与摘要；仅补齐同一主键的 `isIncrement=2`，通过原生页面保存请求启用自动编译，再独立回读整页核对仅包含预期修改。页面不属于当前系统、版本漂移或字段身份不唯一时拒绝派发；不提供任意源码上传或版本提交。

操作复用当前登录身份和平台 `getTableFields` / `saveTableField` API；保存后重新读取同一字段核验。`GET /nativeMetadataResult` 按原 workspaceKey 和 idempotencyKey 恢复回执。同键不重复派发；断连或丢失回执保持 UNKNOWN，只核对原字段，不自动重试。原生元数据维护不会修改本地 SVN `tables/` 只读副本，也不构成任意业务服务执行入口。`inspect-runtime` 只读取平台既有运行入口并返回同源静态脚本路径，不导出 Cookie、查询令牌或任意脚本执行能力。

`save-native-record` 只通过已核对的原生 `editpage/save` 新增一个对话框的单一 `inputForm`，并用 `editpage/get` 独立回读。必须绑定页面、原生声明该对话框的父主页、保存按钮及原生源码版本，拒绝明细网格、更新、SQL、任意服务组件与调用者提供的主键、身份和时间戳；`prepare-native-record` 先只读核验父页、必填字段和候选；正式调用携带原生页面、父级和菜单上下文请求头。机构等候选沿原生下拉接口及数据权限核验，操作人取自业务运行时的原生会话接口。平台后端保存校验、取号、事务及钩子继续生效，64 位整数回执保持原值。该能力必须有具体业务新增授权，不随元数据检查自动执行。

`inspect-page-script` 只读核对一个既有保存按钮的钩子；`apply-page-script` 只发布同一按钮的钩子，支持主表保存按钮与对话框保存按钮。新增缺失钩子以 `expectedContent=null` 绑定不存在的原状态，已存在脚本仍须逐字核对，要求原生页面版本、原脚本文本和经 SVN MCP 租约、预览、更新及差异核验的 `sourceOperationId`。调用前必须回读该源码操作为已验证状态；平台派发再次比对原脚本与页面版本，原生保存启用自动编译，并独立回读整页核对仅有该节点变化（允许原生字段描述省略零长度/小数位默认值）。不执行开发测试脚本端点，不提交 SVN，也不上传本地整页覆盖平台并行修改。

`inspect-declared-step` / `run-declared-step` 只有在服务显式配置 `GUTHON_NATIVE_STEPS_FILE` 时启用。该私有静态 JSON 冻结开发环境、工作区、平台来源、系统/数据源、组件/页面及父页、原生源码版本、全部业务参数和读写属性；请求只选择已声明的步骤名，不能传 URL、组件别名、任意参数、身份、凭据或 SQL。执行前再次核对注册组件和源码版本，服务沿原生 `jscomp/run` 调用；`page-query` 仅对已登记主页/选择页的精确表格与搜索控件执行原生 `mainpage/findPage` 只读查询（首批最多 100 行，不代表全集）。请求带原生页面/菜单上下文头；不新增后台编排器。未知结果保留原回执，后续只读核验，不自动重放。

开发维护需正常重连已更新的 Bridge 服务并重新加载扩展，原配对令牌保持不变。离线接口测试不代表平台修改已经生效；真实调用必须分别核对平台身份、写入回执及原生字段回读。

`inspect-native-source` / `apply-native-source` 仅在服务显式配置 `GUTHON_NATIVE_SOURCE_PLAN_FILE` 时维护本机冻结的开发函数、MCP 登记及隐藏保存字段。请求只选择步骤名；工作区、系统、数据源、父过程、函数、参数、原版本及原脚本均由私有计划绑定。使用设计器原生创建、参数与脚本保存接口并回读。大函数可按精确片段发布，要求已验证的过程源码操作、原生版本、每段原文唯一命中，并完整回读最终源码；不传输重复的整份原文，不扩大事件帧上限。新建函数及保存参数可显式冻结事务与返回模式（严格为 0/1），省略时仍为 0/1；MCP 工具登记保持 0/1。函数源码保存保留并核对既有模式。过程函数按数据源及精确父过程身份归属，不要求当前界面系统包含该函数；PAGE 与 MCP 登记仍核验系统归属。服务组件源码可绑定受控保存后的源码哈希、原生版本、完整原文及唯一片段发布，只修改组件脚本，保存前后核对事务模式并完整回读；检查和保存均只由本机冻结计划选择。 不调用脚本测试端点、不直接写库。已存在函数及工具不覆盖创建；隐藏字段追加绑定受控源码操作、原生版本及原字段清单，只接受无脚本的原生字段默认属性，不覆盖既有字段。未知回执不重放，整页比较未通过时保留未知状态并独立检查目标字段。

## 不支持

- 本地文件回推到开发平台。
- 自动签出过程函数。
- 自动签出页面源码。

收到签出或回推命令时，插件会直接返回错误，不调用平台保存接口。

## 已知限制

- 复制模式依赖开发平台页面 DOM 和 Vue 实例结构，平台页面结构大改时需要同步调整。
- 模块开发主页面中复杂 tab/form/table 组合仍在继续兼容。
- 页面导出目录由本机服务配置，弹窗只展示目录。

Chrome 弹窗的最近拉取保存最多 20 条成功任务元数据及上次导出目录，按浏览器当前平台来源筛选；重拉以新请求进行，剥离正文、凭据及输出目录覆盖。UNKNOWN/失败任务只按原请求恢复核验，不成为成功重拉记录。页面导出仍使用当前固定导出根，历史目录不能扩大服务端写入范围。

明确工作区的导出/拉取任务在同一工作区内串行，跨工作区最多 4 个并行。队列最多 32 项，独立工作区客户端最多 8 个，回收闲置客户端；未解析的旧请求串行。status 提供 activeWorkspaces，所有任务仍重新验证来源和固定 workspaceKey。

## Nexus 托管更新

首次安装支持三组件更新的 Nexus 2.5.0 后，按其管理指引从固定目录加载 Chrome 扩展并完成配对。可导入旧版主机规则；不要覆盖源码仓库中的扩展目录。新端核验正常后再移除旧端，后续保持固定路径。主机规则保存在独立 host-settings.js，令牌、端口和历史继续使用当前扩展的 Chrome storage。

扩展通过配对服务报告实际 manifest 版本和托管安装身份，空闲心跳时按已安装目标重载；未知或未恢复拉取任务会延后重载。安装文件与运行版本分别显示，未连接不视为已生效。更新不会自动刷新平台页面；保存编辑后可手动重载扩展及刷新页面。

## 统一安装与基础环境配置

GuthonCodeSetup 仅负责从零安装工具、插件和基础环境。一次性安装确认完成后，后续在 CodeBuddy 使用 GuthonNexus；产品／项目接入与索引属于后续业务操作。套件工作区自动启动 Bridge，日常不再显示安装助手。

GuthonCodeSetup 将扩展放到本地数据目录的 `var/nexus/updates/chrome/extension`，与 Nexus 更新共用固定托管目录。沿用现有 Chrome，首次通过 Nexus 向导加载目录并复制配对令牌。仅检测到当前托管安装的真实浏览器心跳才记为已连接；安装文件存在不代表已加载或已配对。见 [首次配置教程](../../docs/GuthonCodeTool_Windows安装步骤.html#one-click)。
