# Guthon Bridge

Guthon Bridge 是面向 Guthon 在线开发页面的本地辅助扩展，由 Chrome 扩展和本地 HTTP 桥接服务组成，与 Guthon Nexus 配合使用。

## 功能

- 快捷跳转：在过程函数和模块后台脚本中，按住 Ctrl（Mac 为 Cmd） 点击高亮的静态过程方法名可打开对应过程函数，同样支持函数内子方法跳转。
- 复制模式：在模块开发页打开复制模式，按页面块展示字段信息，便于复制和整理。
- 字段平移：在模块开发页的字段平移按钮组中复制字段并粘贴到另一个已选组件。
- 当前源码拉取：在过程函数页识别当前脚本，并保存为本地文件。
- 函数定位：在过程函数脚本中点击谷神自带的定位按钮；高亮过程函数名时，页面滚动到对应的过程函数。

### 源码拉取（仅 DATABASE）

- 通过本地 HTTP 服务保存文件，并记录远端对象、本地路径和版本元数据。
- 在模块开发页或过程函数页通过 Bridge 调用 GuthonCodeTool，从源码表拉取已保存源码并生成工作副本。
- 在数据表管理页拉取当前数据源的表结构，支持只拉取选中的数据表。
- 在单据类型页拉取当前数据源的单据类型，支持只拉取选中的单据类型。
- 在视图管理页拉取当前数据源的视图源码。
- 在系统脚本页拉取当前应用系统的选中脚本或全部脚本。

以上源码拉取和数据库资料导出只适用于工作区摘要为 `sourceMode=database` 的项目。Bridge 会先读取工作区摘要；SVN 工作区隐藏旧的源码拉取和导出按钮，左下角保留 Nexus 定位入口。旧版扩展直接调用拉取接口时，服务端也会返回明确的模式错误。SVN 初始化、刷新、扫描和虚拟写回统一从 Guthon Nexus 操作。

在模块开发页选中 PAGE 或过程函数页签，点击 Chrome 弹窗的“在 Nexus 中打开…”或页面左下角的“在 Nexus 定位”，即可将当前对象交给已安装的 Nexus。PAGE 只传完整 PAGE ID；过程函数只传完整包名和函数名，不使用平台的 PR 编号代替函数身份。Nexus 当次要求选择 SVN 工作区，只接受索引中的精确匹配；多份源码还需选择路径和 working copy。这个入口只打开本地虚拟源码，不写入平台或 SVN。若 VS Code 已被唤起但 Nexus 没有工作区选择或报错，重新安装含 `onUri` 入口的 VSIX 并执行 `Developer: Reload Window`；相同版本号也可能对应旧构建。还可在 Nexus 命令面板运行“按页面编码定位本地 PAGE”或“按包名和函数名定位本地过程函数”，检查本地定位流程。

左下角按钮组在开发页签出现后立即挂载，页面桥接和工作区模式查询随后进行；页签切换由页面变化触发刷新。首次显示按钮不依赖本地 Bridge 服务响应。编辑器导航随 DOM 挂载、聚焦及点击安装，不再每秒扫描。

### Nexus → 平台定位与页面上下文

在 Nexus 的“谷神源码”树选择 PAGE 或过程函数，执行右键“在谷神平台定位源码”，也可从命令面板对当前 SVN 虚拟文档执行。先在 Chrome 打开平台、完成 Bridge 配对并选择对应工作区；仅操作已有平台页签，多页签由当次选择。PAGE 按完整编码定位，过程函数按精确包名、函数名和当前平台数据源匹配；多份候选报错并要求在平台选择数据源。导航复用平台路由和对象树，不构造未经验证的对象 URL，不保存平台数据。

Bridge 的带令牌 `GET /pageContext?workspaceKey=...` 返回该工作区的有界元数据快照：平台 origin、去掉查询参数的 hash、PAGE/过程函数身份、数据源/系统身份、选中页签及最多 32 个打开页签。正文、SQL、选中文本、编辑令牌及本机路径不进入快照。最多保留 64 个页签，租约 150 秒；关闭或跳离平台时删除，服务重启后等待浏览器重新发布。

浏览器后台通过 Bearer 头订阅 `GET /events?clientId=...`，接收定位指令；本机客户端可按明确 `workspaceKey` 订阅快照变化与定位回执。令牌不放在 URL，网页 Origin 被拒绝。导航请求、当前平台身份和工作区在服务端及浏览器分别校验；过期、断线、来源或工作区改变均拒绝，重连不重放导航。定位指令和工作区快照变化通过事件推送，60 秒元数据租约心跳用于恢复 MV3 worker 或重启的 Bridge；浏览器 DOM 页签变化仍由浏览器事件处理。Nexus 当前命令以有界查询等待定位回执，持久拉取任务继续沿原异步任务协议恢复。

## 目录

```text
plugins/GuthonBridge/
  bridge/       本地 HTTP 桥接服务
  extension/    Chrome 扩展
  package.json  启动和测试脚本
```

扩展的 Popup、页面按钮、弹窗、复制面板和导航高亮样式统一维护在 `extension/bridge.css`；JavaScript 只设置显示状态、拖拽坐标和动态列宽。

## 启动 Bridge

普通用户在 Guthon Nexus 左侧面板单击“启动 Guthon Bridge”。Nexus 会传入当前运行模式和显式本地数据目录，并使用 VS Code 自带的 Node 运行环境启动服务，不需要安装 Node.js、设置环境变量或打开终端。发行模式使用打包应用，开发模式使用仓库 `.venv` 与源码，调试模式使用本地 Python 与经校验的 Release pyz。Bridge 在自身生命周期内复用一个常驻 ToolHost；开发源码修改后需重启 ToolHost 才生效。切换本地数据目录或运行模式时，运行中的 Bridge 会自动重启。

Bridge 请求携带 `workspaceKey` 时会验证页面身份；未携带时按 `pageOrigin + dataSourceId + systemId` 匹配产品、项目配置。唯一候选直接使用，多个候选由 Chrome 扩展下拉选择，并按 `协议 + 主机 + /guthon` 记住最近一次选择；切换谷神地址或候选失效时重新选择。

工作区摘要包含 `sourceMode` 和服务端计算的 capabilities。前端只按这些能力显示操作；配置关闭后，Bridge/CLI 仍会再次校验，不把前端隐藏当权限边界。

以下命令只用于仓库源码调试：

```bash
npm run start:bridge
```

直接启动 Bridge 时必须显式设置绝对路径 `GUTHON_TOOL_HOME`。未设置 `GUTHON_TOOL_PATH` 时，开发环境可使用仓库中的 Python 脚本；Nexus 启动时会传入所选运行入口。

默认监听：

```text
http://127.0.0.1:17361
```

健康检查：

```text
http://127.0.0.1:17361/health
```

临时切换端口：

```bash
GUTHON_BRIDGE_PORT=17362 npm run start:bridge
```

Chrome 扩展默认访问 `127.0.0.1:17361`。可在 Nexus 设置 `gushenCompletion.bridgePort`，重启 Bridge 后在 Chrome 弹窗“Bridge 配对设置”填写相同端口，不需要修改扩展代码。Nexus 等待带令牌的 `/status` 成功后才报告启动成功。端口被占用时服务明确报错，不能用其它服务的 `/health` 冒充本实例。

首次连接：在 Nexus 启动通知中点击“复制配对令牌”，打开 Chrome 扩展弹窗的“Bridge 配对设置”，粘贴令牌并点击“保存并连接”。再次执行 Nexus 的启动命令也可复制现有令牌。直接运行服务的维护者可读取 `<toolHome>/var/nexus/bridge/token`，该文件仅供本机用户读取；不要公开令牌。服务重启保留令牌，停止服务并删除令牌文件后重新启动可撤销旧配对。

除不返回本地信息的 `/health` 外，请求均需 Bearer 令牌。服务拒绝网页 Origin，不返回跨域授权头；扩展后台核对消息发送者和实际标签页地址，页面不能指定其它 origin。MAIN world 为平台编辑器访问层，与网页共享 JavaScript 环境，无法隔离平台自身的恶意脚本；它没有访问 Bridge 令牌的接口，页面发起的调用方提示需用户点击查询后才访问本地后端。

## 安装 Chrome 扩展

1. 打开 `chrome://extensions`
2. 开启“开发者模式”
3. 点击“加载已解压的扩展程序”
4. 选择 `plugins/GuthonBridge/extension/`

修改扩展代码后，需要在 Chrome 扩展页重新加载扩展，并刷新开发平台页面。

## 允许的开发平台地址

编辑 `extension/host-config.js` 顶部配置后重新加载扩展：

```js
const config = {
  protocols: ["http:", "https:"],
  ipRanges: ["192.168.0.0/16", "192.0.2.0/24"],
  domainSuffixes: ["dev.example.com"],
  pathPrefixes: ["/guthon/"]
};
```

`ipRanges` 支持显式 IPv4 或 IPv6 CIDR（如 `fd12:3456::/32`）；默认允许范围不变，访问仍须同时满足协议、路径和 Chrome 权限。`domainSuffixes` 同时匹配配置域名及其子域名，例如 `dev.example.com` 也允许 `team.dev.example.com`。

## 使用

### 快捷跳转到过程函数

在过程函数或模块后台脚本编辑器中，按住 `Ctrl` 并点击 `$vs.proc.invoke("包名", "方法名", ...)` 的方法名，或 `$proc=$vs.proc.find("包名")` 对应的 `$proc.方法名(...)`。动态包名和动态方法名不会跳转。

模块开发跳转后：原编辑器会保留，页面内悬浮可拖动标题框，双击返回模块开发编辑器。

### 拉取页面当前源码

1. 启动本地 bridge。
2. 打开过程函数开发页面。
3. 点击 Chrome 工具栏中的 `Guthon Bridge` 图标。
4. 确认弹窗识别到包名和函数名。
5. 完成 Bridge 配对，弹窗显示本机配置的页面导出目录。
6. 点击 `拉取页面当前源码`。

过程函数页面上的 `源码拉取` 按钮不使用页面保存目录，会直接走源码表版本拉取。

### 拉取源码表版本

1. 启动本地 bridge。
2. 打开过程函数开发页或模块开发页。
3. 点击 `拉取源码表版本`。

拉取成功后会显示工作副本路径。`sync.yaml` 的 `rules.pull_diff_check` 缺省为 `true`：直接比较 readonly 与 workcopy，存在差异时保留 workcopy 并生成 `diff.md`。设为 `false` 时直接覆盖 readonly/workcopy。

### 拉取表结构

1. 启动本地 bridge。
2. 打开数据表管理页。
3. 选择数据源。
4. 可选：选中一个或多个数据表。
5. 点击页面悬浮按钮或 Chrome 扩展弹窗中的 `拉取表结构`。

弹窗会显示当前数据源的编码和名称。未选中数据表时，拉取当前数据源下全部表结构；选中数据表时，只拉取选中的表结构。

### 拉取单据类型

1. 启动本地 bridge。
2. 打开单据类型页。
3. 选择数据源。
4. 可选：选中一个或多个单据类型。
5. 点击页面悬浮按钮或 Chrome 扩展弹窗中的 `拉取单据类型`。

弹窗会显示当前数据源的编码和名称，以及当前选中的单据类型编码。未选中单据类型时，拉取当前数据源下全部单据类型；选中单据类型时，只拉取选中的单据类型。

### 拉取视图源码

1. 启动本地 bridge。
2. 打开视图管理页并选择数据源。
3. 点击页面悬浮按钮或 Chrome 扩展弹窗中的 `拉取视图源码`。

未选中视图时拉取当前数据源下全部视图；选中视图时只拉取选中视图。源码保存到匹配工作区的 `database/views/`，并按 `pull_auto_add_git` 规则自动暂存本次新生成的 SQL。

### 拉取系统脚本

1. 启动本地 bridge。
2. 打开系统脚本页并在左侧选择应用系统。
3. 单击脚本行可选中或取消选中当前脚本。
4. 点击页面悬浮的 `选中拉取` 或 `全部拉取`；Chrome 扩展弹窗也提供相同操作。

readonly 使用 `<脚本序号>-<脚本类型>[-<脚本描述>]` 目录名，例如 `20000-系统私有JAVASCRIPT-图片预览`。选中拉取按 `SYSTEM_ID + SCRIPT_TYPE` 精确导出，并在匹配工作区的 `source/workcopy` 创建或安全刷新对应工作副本；全部拉取只更新该工作区当前应用系统的 readonly。两种拉取都会按 `pull_auto_add_git` 规则自动暂存本次新生成的系统脚本文件。

### 打开复制模式

1. 打开模块开发页面。
2. 点击页面上的 `复制模式` 按钮，或点击 Chrome 扩展弹窗中的 `打开复制模式`。
3. 在弹窗中查看字段结构。
4. 从右侧文本框复制纯文本内容。

### 字段平移

1. 在模块开发页面选中来源组件，点击 `复制字段`。
2. 在弹窗中勾选字段并点击 `复制`。
3. 选中目标组件，点击 `粘贴字段`。

仅支持输入组件的字段和表格组件的列。粘贴按 `fieldId` 跳过重复项；缓存只保留到页面刷新前，平台保存仍需由用户单独执行。

## 本地保存规则

- 页面导出目录默认是 `<toolHome>/var/nexus/bridge/exports`，由服务创建并显示在弹窗。
- 维护者可通过本机环境变量 `GUTHON_BRIDGE_EXPORT_ROOT` 设置另一个绝对导出目录；HTTP 请求不能选择其它目录。
- 不允许符号链接文件，读取本地映射也核验路径归属。
- 文件名来自当前函数名或片段名。
- 文件名会过滤路径非法字符。
- 同名页面导出文件会覆盖。源码表版本的“强制刷新”需输入完整工作区键确认，会先备份原工作副本。
- 文件直接保存到服务配置的导出目录下，不按包名创建子目录；只允许 java、js、gss、sql、json、xml、txt 扩展名。

本地映射文件：

```text
<本地数据目录>/var/nexus/bridge/manifest.json
```

## 不支持

- 本地文件回推到开发平台。
- 自动签出过程函数。
- 自动签出页面源码。
- 由 Bridge 自动执行 `svn commit`。

收到签出或回推命令时，插件会直接返回错误，不调用平台保存接口。

## 已知限制

- 复制模式依赖开发平台页面 DOM 和 Vue 实例结构，平台页面结构大改时需要同步调整。
- 模块开发主页面中复杂 tab/form/table 组合仍在继续兼容。
- 页面导出目录由本机服务配置，弹窗只展示目录。

Chrome 弹窗的最近拉取保存最多 20 条成功任务元数据及上次导出目录，按浏览器当前平台来源筛选；重拉以新请求进行，剥离旧 force/confirmation、正文、凭据及输出目录覆盖。UNKNOWN/失败任务只按原请求恢复核验，不成为成功重拉记录。页面导出仍使用当前固定导出根，历史目录不能扩大服务端写入范围。

明确工作区的导出/拉取任务在同一工作区内串行，跨工作区最多 4 个并行。队列最多 32 项，独立工作区客户端最多 8 个，回收闲置客户端；未解析的旧请求串行。status 提供 activeWorkspaces，所有任务仍重新验证来源和固定 workspaceKey。
