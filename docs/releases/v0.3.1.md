# GuthonCodeTool v0.3.1

GuthonCodeTool 与 Chrome Guthon Bridge 为 0.3.1，Guthon Nexus 为 2.5.0。

## 新功能

- Nexus 新增三组件更新，入口位于“运行模式 → 检查更新”。每天首次激活后后台检查；只检查，点击确认后才安装。角标显示可更新数量，列表展示当前与目标版本。
- 发行模式与调试模式检查所选 GitHub/Gitee 更新源。发行模式更新 Windows x64 或 Apple Silicon 应用；调试模式更新 pyz、校验信息及依赖清单，核验现有 Python，不自动安装依赖。
- 开发模式从明确配置的 developmentRoot 本地源码构建 Nexus 与 Chrome，保留后端源码，不访问发行源。相同版本号的代码变化由构建标识检测。
- 新增签名保护的发行清单，从实际 VSIX 与 Chrome 包提取各自版本，核对同批附件哈希和编辑器兼容条件。
- Chrome 扩展使用固定托管目录，保留主机规则及安装身份。已托管扩展通过配对的本机服务核对运行版本，空闲时重载；未恢复的任务会延后重载。
- 发行及调试模式先下载并检查全部所需附件；开发模式先构建并检查本地安装包。随后切换适用的后端和 Chrome 文件，最后安装 Nexus。Nexus 自安装前释放磁盘锁，安装状态按 IDE 单独记录；安装后提示立即重新加载或稍后。

## 修复

- 开发/调试模式显示实际版本或明确未确认状态，取消不准确的“最新”显示。
- 更新缓存经过签名复验；多窗口共同安装目录使用互斥锁。损坏附件、危险 ZIP 路径、符号链接及版本不一致阻止安装。
- 更新源仍是已签名旧发行、尚无三组件清单时，显示当前组件版本及正常发行提示，不据此安装。清单未被签名覆盖或签名无效时阻止更新。

## 重构

- 本地构建和发行打包共用扩展资源清单与 Bridge 打包逻辑，统一构建标识计算，减少源码与安装包差异。
- Chrome 主机规则独立保存，托管更新保留配置和安装身份；更新协调、清单验证与归档处理分别维护。

## 安装与验证边界

- 安装记录保留已完成部分，失败可继续；Chrome 目录交换中断可在锁内恢复。异常退出留下的安装锁仍需先确认相关进程已停止，再按提示核查。
- 现有应用回退保留；调试模式可通过“当前入口”选择已保留的旧 pyz。Nexus 和 Chrome 更新状态分别核验，不承诺跨编辑器/浏览器的原子回滚。

## 首次启用

1. 现有 2.4.0 Nexus 不含自更新协议，首次手动安装本批 2.5.0 VSIX 并重新加载 IDE。
2. 在“运行模式 → 检查更新”中准备 Chrome 托管目录，从 chrome://extensions 加载该目录并完成配对。旧目录有自定义主机规则时，在首次托管提示中选择导入。
3. 新托管扩展核验正常后再移除原扩展；以后保持固定目录。不要将源码仓库中的扩展目录交给自动覆盖。
4. 更新前保存平台编辑内容。重载 IDE 和重载 Chrome 扩展是不同动作；必要时手动重载扩展并刷新平台页面。

开发模式需要已安装的 vsce 与所选 .venv Python。构建在独立快照目录中进行，不覆盖仓库里的 VSIX；缺少构建工具时明确提示，不自动联网获取工具。

实际安装后，请分别核对当前 IDE 与浏览器的运行版本回执。
