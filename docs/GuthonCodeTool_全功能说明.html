1. 产品定位与设计原则

1.1 功能边界

GuthonCodeTool 把谷神平台的源码与元数据整理为按产品或项目隔离的本地工作区。开发人员可以同步 PAGE、过程函数、系统脚本及数据库元数据，也可以从已授权的 SVN 仓库检出源码；随后通过本地索引完成搜索、跳转、调用关系分析、差异审阅和受控修改。

工具负责工作区路由、源码同步、索引、受控编辑、差异与交付证据，以及 Nexus、Bridge 和 SVN MCP 所需的共享本地能力。
平台负责谷神页面中的编译、发布、运行和业务验证。这些结果按需要另行核验；源码交付以成功提交的 SVN revision 为准。
本地私有真实配置、凭据、源码、索引、日志和业务资料只保存在显式选择的本地数据目录中。

1.2 核心设计选择

设计原因
一个工作区只选择一个源码 provider
DATABASE 或 SVN。		防止同一对象同时出现两个事实来源，避免同步、编辑和交付时无法判断哪一份有效。
产品与项目使用稳定 workspaceKey
products.<id> 或 projects.<id>。		目录名、显示名和当前窗口都会变化；稳定键能让 CLI、Nexus、Bridge、MCP、数据库目标和索引指向同一边界。
工具源码与运行数据分离升级或切换开发/发行入口时不搬迁私有数据，也不会把业务源码和凭据误带入公开仓库。
DATABASE 与 SVN 使用不同写入模型数据库导出是快照，适合 readonly/workcopy；SVN checkout 本身已有版本基线，再复制一份会制造额外冲突。
AI 默认读取索引与有界证据减少扫描和上下文体积，同时保留路径、对象身份、调用位置和 hash，使结论可回到源码核验。
所有高风险操作显式触发源码覆盖、SVN 更新、提交、撤销和工具升级都会改变本地或远端状态，必须由开发人员明确选择范围。

2. 运行架构

2.1 组件职责

text
Guthon Nexus（VS Code） ──┐ 展示工作区、源码、索引与 SCM；管理 Bridge
Guthon Bridge（Chrome） ──┼─→ GuthonCodeTool（Python CLI 与共享实现）
AI 客户端 → SVN MCP ──────┘    ├─ 工作区解析、同步、索引、Workcopy
  独立 stdio 进程              ├─ DATABASE provider
                             └─ SVN provider → 授权 checkout + context/index.db
  • 统一 CLI：scripts/guthon_tool.py 负责编排命令；scripts/common/gusen_hub.py 复用工作区解析、同步状态、索引和 Workcopy 规则。
  • DATABASE provider：读取配置的数据源，导出源码及元数据，并提供受限的只读数据库排查。
  • SVN provider：管理根检出、授权清单、虚拟对象投影、文件写入、SCM、冲突和交付回执。
  • Nexus：只通过参数数组启动工具，不经过 Shell；因此路径、空格和 Windows/macOS 参数行为一致。
  • Bridge：由 Nexus 使用 VS Code 自带的 Node 运行环境启停，普通用户无需另装运行时。
  • SVN MCP：由已配置的 AI 客户端独立启动 stdio 服务；对显式 SVN 工作区调用共享 PAGE/过程函数查询与受控修改服务，默认暴露写入工具，但每次写入仍需授权和编辑租约。

Nexus 复用常驻 ToolHost。Bridge 使用有界工作区客户端池，同一工作区串行、不同工作区最多四个并行。工作区列表可由 Nexus 视图共享；普通界面刷新不扫描全部 SVN working copy，本地状态刷新与远端检查使用不同命令。

2.2 目录与调用链

text
<toolHome>/
├── GuthonCodeTool/                 # 可公开、可替换的工具源码
├── config/                         # 真实运行配置
├── docs/private/                   # 本机私有资料
└── var/                            # 独立的私有工作区
    ├── AGENTS.md
    ├── tools/guthon-lint
    ├── nexus/{bridge,tool-runtime.json}
    ├── checkout/<配置 ID>/         # SVN working copy
    └── workspace/<工程>/
        ├── source/{readonly,workcopy}/  # 仅 DATABASE
        ├── database/                   # 仅 DATABASE
        └── context/{index.db,state.json,source-mode.json,logs}/

toolHome 只能由 --home、运行描述文件或 GUTHON_HOME/GUTHON_TOOL_HOME 环境变量显式提供。源码不能沿父目录猜测 config 或 var，因为这种猜测会让开发仓库、发行应用和用户数据相互污染。

Nexus 将当前应用入口、toolHome 和运行模式写入运行描述文件，Bridge 据此使用同一工作空间。MCP 客户端需单独配置可执行入口及显式 toolHome；它不会因 Nexus 切换模式而自动重写客户端配置。配置和工作区分别按请求加载，不使用全局“当前工作区”。

公开仓库与业务开发入口

公开仓库中的 config/ 只保存示例与 schema，scripts/ 实现 CLI 和 provider，plugins/GuthonNexus/ 与 plugins/GuthonBridge/ 分别提供编辑器和浏览器组件，skills/guthon-testing/ 提供谷神开发与只读验证流程。维护工具先读 AGENTS.md，再用 代码导航索引 定位模块；业务开发则从独立私有工作区的 <toolHome>/var/AGENTS.md 进入，不把业务源码复制进工具仓库。

DATABASE 工作区包含 docs/、source/readonly/、source/workcopy/、database/{schema,billtype,views}/ 与 context/；SVN 工作区只在工作区目录保存说明和派生资料，源码位于唯一 checkout。目录前缀 PRD/PRJ 只控制显示顺序，不是工作区身份。私有 Git 忽略根级 checkout/，SVN 源码差异、更新、撤销和提交由 SVN 管理，不将其强制纳入第二套 Git 历史。

3. 工作区与配置

3.1 稳定身份与配置

  • datasource.yaml：数据源注册和 DATABASE 连接引用。
  • products.yaml：产品名称、稳定 ID、数据源、子系统范围和可选 SVN 根地址。
  • projects.yaml：项目快照的独立配置。项目与产品并列管理，不保存产品工作区引用。
  • source-tables.yaml：DATABASE 源码表及语义字段映射。
  • sync.yaml：公共同步规则、SVN 用户名、拉取校验和白名单；不保存默认工作区。
  • database-testing.yaml：只读数据库目标、连接引用、环境身份与正式验证范围。
  • context/source-mode.json：当前工作区的 DATABASE/SVN 选择；缺失时采用 DATABASE。

所有调用方必须传递同一 workspaceKey。Bridge 在缺少该键时只能根据页面身份查找候选；如果存在多个匹配项，选择仅对当前请求有效，不写入全局状态。这样多个产品、项目和窗口可以同时工作而不串线。

配置字段与故障隔离

产品和项目分别声明数据源与系统映射。下例只展示公开字段，完整格式见 配置参考：

yaml
products:
  demo-product:
    name: 示例产品
    aliases: [示例简称]
    datasource: demo-product-dev
    systems:
      include:
        mappings:
          demo.system:
            system_id: SYS-DEMO
            data_source_id: "0000"
    page_origins: []

mappings 的键为系统 alias，每项对应一对 system_id/data_source_id。SVN 用它识别与分组完整检出的源码；DATABASE 按 alias 查询并使用本地 system-data.json 缓存。项目拥有自己的数据源 ID，不复用产品值。源码模式不写入产品/项目 YAML，而保存在各工作区的 context/source-mode.json。

工作区列表以 configErrors 返回单项配置错误，不阻断无关工作区；冲突身份和重叠 SVN 授权范围仍拒绝使用。不要通过更换目录名绕过身份校验。

aliases 是可选的工作区名称数组，用于名称与任务 prompt 定位；与系统 mappings 的 alias 不同，不改变稳定 ID、源码来源或目录。名称按规范化后的完整文本匹配，不以模糊子串猜测；重名或别名冲突返回候选，指定产品/项目类型可缩小范围。

3.2 创建、切换与删除

  1. 首次设置：setup 只创建缺失的公开模板和空注册表，不覆盖已有配置。
  2. 添加工作区：向导收集产品/项目、名称、稳定 ID 和源码模式，随后原子写入相关注册表。DATABASE 和 SVN 的连接细节在对应模块继续配置。
  3. 切换 toolHome：Nexus 先在候选目录执行设置与验证，通过后才保存新目录。失败或取消不会破坏当前可用配置。
  4. 切换源码模式：只更新目标工作区的 source-mode.json，不会影响其他工作区。
  5. 删除工作区：先显示目录、配置和独占资源的精确范围；项目 docs/ 下有文件时提示检查是否需要备份。确认后把工作区目录移入系统废纸篓，并只删除对应注册项和专属配置。

项目删除不会连带删除产品；共享数据源也不会因某个工作区删除而被误删。该设计把“身份”“物理目录”和“可共享资源”分别核对，避免用目录递归推断业务关系。

拉取历史与归档

“查看源码拉取历史”按固定观察快照分页，可导出 JSON 或 Markdown。归档先预览候选，再确认完整工作区键；只处理明确归属的本地终态记录，保留备份。恢复前核验归档 ID 与当前日志状态；日志已变化时拒绝覆盖。无身份、损坏或未知状态的记录保留，共享 Bridge 日志仅导出、不清理。

4. DATABASE 模式

4.1 源码与元数据同步

DATABASE provider 根据目标工作区的数据源、子系统范围和语义映射读取 PAGE、过程函数与系统脚本，生成结构化的 source/readonly。PAGE 保存原始 JSON，同时拆出 GSS、JavaScript、SQL、事件和组件脚本；过程函数按包与函数组织；项目快照内的继承关系只使用同一快照的数据，不跨到产品工作区。

元数据导出包含表结构、单据类型、系统脚本和视图。sync-all 固定执行“源码与索引 → 表结构 → 单据类型 → 系统脚本 → 视图”。任一步失败或执行期间配置摘要改变，后续步骤都会停止；只有全部成功才把工作区标记为 SYNCED。这样“同步完成”代表一个一致快照，而不是五个时间点不同的局部结果。

4.2 Workcopy 开发

  1. 从 readonly 创建目标对象的 Workcopy，并保存来源身份。
  2. 开发人员只修改 source/workcopy，readonly 始终表示最近一次数据库导出。
  3. workcopy status 汇总状态，diff 生成差异，package 生成可交付清单。
  4. 再次拉取时，默认直接比较新 readonly 与现有 workcopy；存在差异便保留 workcopy，防止覆盖开发修改。

rules.pull_diff_check 默认启用。只有显式关闭时才允许拉取覆盖 workcopy。自动 Git 暂存也只处理本次新生成且原本未跟踪的目标文件，不会暂存已有修改、其他工作区文件或被忽略内容。

采用双目录是因为数据库导出没有版本控制工作副本。readonly 提供可重建基线，workcopy 保留人工修改，两者的差异就是需要审阅和回填平台的内容。

JSON 请求的 force=true 需同时提供完整工作区键作为 confirmation，并先备份到相邻 .guthon-trash/<时间戳>/；workcopy trash-list 列出备份，workcopy restore <backup> --check 预览恢复范围，正式恢复确认完整工作区键并先备份当前副本。远程未找到源码时返回失败及缓存可用提示，不修改 Workcopy；确需从缓存创建副本时使用 create-workcopy。PAGE 业务修改落在拆分脚本，原始 raw.json 不作为编辑入口。

源码镜像写入与 SQLite 更新保留恢复记录，失败回滚，下次同步先处理未完成事务。导出内容相同则保留原文件，变化时原子替换；不据此宣称已使用数据库远端增量水位。私有 Git 暂存加锁，只处理本次明确生成且原先未跟踪的文件，排除回收站、日志及同时手工新增文件；路径按原始字节传递以保留中文名称。

4.3 只读数据库排查

工具可按工作区、开发/测试环境和私有目标配置解析数据库连接，支持 MySQL、PostgreSQL 与 Oracle。查询必须核对 database/schema 和实际可见表；正式测试计划另有声明的验证范围。密码默认写入系统凭据库，配置只保存连接引用。

  • database-probe：验证驱动、连接和只读能力。
  • database-describe：核对目标 database/schema 后读取可见表结构，避免猜测字段；快速排查不以静态表列表代替目标身份和实际可见性验证。
  • database-query-readonly：只接受单条 SELECT，限制返回行数并始终回滚事务。
  • 可选 DBX 连接只在配置了 connectionId 时使用；缺失绑定会明确报告，不自动猜测其他连接。

diagnose 还提供配置驱动的源码逻辑排查：它只允许显式标记为测试、启用只读诊断并声明数据库白名单的数据源，按模板逐步执行绑定参数的单条 SELECT，在首个不满足条件的位置停止并生成本地排查报告。该能力适合重复执行的固定检查链；临时问题则使用目标解析、结构描述和有界查询逐步取证。

数据库快速排查从当前工作区和开发/测试环境解析明确目标；未指定环境时使用配置中的诊断默认目标，而“测试一下”只是连接探测，不代表已切换到测试库。功能验收、回归和交付应使用正式测试目标与测试计划/结果证据，不能把一次只读查询当作完整验证。可选的 Guthon Testing Skill 提供该工作流指导，其安装与数据库连接配置是两个独立步骤。

Nexus 的“配置数据库只读目标”区分快速排查与正式只读验证。正式目标还需声明系统、数据源、表范围、租户字段和证据。Oracle 登录 schema 与业务 schema 分别核验；生成 DBX 交接文件只说明交接信息已准备，不能作为查询已执行的证据。

“查看最近诊断历史”读取已有记录，不重新执行查询。查询可导出 CSV 或带证据页的 XLSX，结果与目标、SQL、执行时点一并保存到当前私有工作区。

这些限制使数据库能力适合诊断和验证，而不会把开发工具变成任意 SQL 执行器。查询命中只证明数据库证据，不等同于页面结果或已部署版本验证。

目标、凭据与适配器

database-target-list 列出工作区目标；database-connect-test 测试明确环境的连接，database-probe 核验目标身份和只读能力；database-target-resolve 及 runtime descriptor 按 cwd 和环境解析默认目标：未指定环境用 defaults.diagnosisTargetId，明确开发/测试环境用 defaults.byEnvironment.dev/test。显式 --workspace 优先于 --path。database-target-configure 可更新已有目标的密码或属性；database-target-remove --check 先预览，正式移除确认精确 target ID，只清理不再被引用的连接和凭据。

有 connectionRef 时优先用内置只读连接器；仅有 connectionId 时使用当前实际可用的 DBX。database-dbx-import 只导入有来源说明的公开连接元数据，database-dbx-handoff 生成先核身份的调用交接，不读取 DBX 密码或伪装查询已执行。--profile 可选择已有目标配置。

密码默认保存在 keyring；维护者可显式配置 passwordEnv 环境变量或 passwordFile 绝对路径密码文件。更换来源不会自动删除旧 keyring 记录。database-credentials-export/import 要求明确工作区、已注册凭据引用和确认，使用 AES-GCM 加密迁移，不把解密明文落盘；加密文件也应保存在私有位置。

查询、输出与诊断历史

database-diagnose 默认只探测身份；提供 --sql、--sql-file 或 --stdin 才执行查询。快速排查使用 database-*，固定源码诊断案例使用 diagnose。内置查询只接受经验证的单条 SELECT，最多返回 100 行，并回滚只读事务。

SQL 校验支持普通字符串中的邮箱、分号和井号、SELECT CTE 及对应引擎的允许函数/类型；拒绝跨库、未知副作用函数、注释、引用标识符和不支持的转义。Oracle 替代引号、PostgreSQL dollar-quote、嵌套 WITH 与反斜线字面量仍不支持，复杂值应使用绑定参数。MySQL/PostgreSQL 可用 --explain 读取有界估计计划，不执行 ANALYZE，返回 queryExecuted=false；Oracle 因需计划表写入而拒绝该操作。

查询结果保留行列截断位置；CSV/表格输出还在 stderr 提示截断。--format xlsx --output <私有文件.xlsx> 生成“结果”和“证据”两页，字符串按文本保存、长整数保留精度；空列名或重复列名明确拒绝。连接探测和 DBX 交接不生成伪空结果。导出摘要最多保留最近 100 条。

database-history-list/show 提供脱敏查询历史，database-compare 提供目标间计数对比，diagnosis-template 生成查询模板；计数不同不直接代表功能错误。描述缓存绑定完整目标摘要、TTL 及 probe 失效 epoch。diagnosis-list/show 供 Nexus 查看最近最多 100 条诊断摘要或精确详情，不读取 SQL、参数或结果行，也不重新运行查询。固定案例报告默认隐藏绑定参数，只有明确 --include-params 才写入原文；报告位于私有 var/docs/业务排查文档/，模板见公开的 source-diagnosis 示例。

正式只读验证计划

database-test-artifacts 提供 validate-config、init-plan、run-readonly、export-dbx-plan 和 import-dbx-results 等子命令。正式目标和计划需声明系统、数据源、表范围与租户证据，当前计划校验器以 allowedTables 核对计划 SQL 的表引用；快速诊断则核对目标 schema 的实际可见性，不把该列表当作库内排查禁区。执行器先核身份，前置条件失败或结果截断时停止相应用例；平台结果用例还需与源码和目标绑定的版本及触发证据。内置连接可执行只读计划，DBX-only 目标通过交接、结果导入和本地 evaluate 完成证据处理。

bash
.venv/bin/python scripts/guthon_tool.py database-test-artifacts -- \
  run-readonly /absolute/private/plan.json \
  --config /absolute/toolHome/config/database-testing.yaml \
  --out-dir /absolute/private/new-run

每次运行使用新的私有目录，保存结果和报告，不覆盖旧运行；执行器不发布、不触发平台或清理数据。diagnose case.json --dry-run 只做未绑定 SQL 的静态校验，不连接也不写报告。模板的 --case-out 产生不能直接执行的案例草稿，并保留调用方的 --max-rows。

5. SVN 模式

5.1 检出与认证

每个 SVN 工作区用 svn.url 配置一个仓库根地址，并完整检出为一个 repository-root。systems.include.mappings 中的系统和数据源映射只负责对象身份、中文名称与业务分组，不裁剪检出目录。完整根检出保证跨子系统引用、公共源码和同名对象都有共同 revision 基线。

  • 可从文件选择或粘贴 checkout 内容导入根地址；工具只解析字面量地址，不执行脚本。
  • 变量、多个根地址或不安全的本地目标会被拒绝，避免把导入功能变成命令执行入口。
  • 公共用户名保存在同步配置；密码经标准输入交给 SVN 认证缓存或系统钥匙串，不进入 YAML、日志、命令参数或编辑会话。
  • 登录验证只使用当前配置地址及同一根地址下已有明确授权的子目录，路径权限拒绝时可继续检查下一个地址；密码、证书、网络错误立即返回。验证不会修改检出布局，登录成功也不代表根目录拥有完整 checkout 权限。
  • 兼容谷神旧 HTTPS 自签证书：检出、更新、远程检查和提交默认允许 expired,cn-mismatch,unknown-ca,not-yet-valid,other，可通过 GUTHON_SVN_TRUSTED_CERT_FAILURES 缩小允许集合。该策略只作用于 SVN，发行附件下载和验签继续保留现有校验。
  • 检出、更新、清理和重建索引都显示实际处理范围；同一工作区的重叠操作通过操作锁阻止。
  • 大型仓库的检出或更新包含后续索引扫描；扫描期间会定期显示已扫描文件数，中断后应先读取工作区与索引状态。

SVN 工作区要求客户端 1.10+。平台下载的 svnCheckoutHere.sh/svnCheckoutHere.bat 只在显式导入时解析一次，不执行，也不从其他工作区自动发现。预览显示新增、移除与变更数量，确认后写入工作区 context/authorized-scope.json 并检出；后续以配置为准，移出配置的旧 working copy 不会自动删除。

兼容读取旧 svn.scope/checkoutPaths 及 sync-from-script/sync-from-bat 命令；高级手工接入可用 import-svn-scope，日常不要求维护 svn.scope_manifest。SVN 模式的 sync-all 只更新本地索引与摘要，不执行 svn update；远程更新显式使用 svn refresh。

5.2 业务目录与虚拟文档

PAGE JSON 的逻辑身份来自内部 pageId，缺少时使用文件名。谷神导出文件名与该编码不同也可正常索引，物理路径仍用于授权定位和写回；原文件名及页面编码保持原样，保存期间继续校验身份、路径和内容哈希。后端解析规则升级后需完整重建 SVN 索引。

SVN checkout 是唯一源码事实。工具从其中识别系统、数据源、PAGE、过程函数、系统脚本、表和视图，写入工作区独立 SQLite 索引。Nexus 的“谷神源码”树只读取索引；展开单个 PAGE 时才解析目标 JSON，因此大型仓库不会在每次展开树节点时全量扫描。

对象与展示编辑边界
PAGE：按索引中的模型、模块和页面顺序展示，内部固定分为 GSS、JavaScript、SQL、字段及服务事件。脚本与 SQL 以虚拟文档投影，可受控写回原始 JSON；本地页面编辑器提供支持范围内的字段属性与同容器排序。
过程函数：按包名和函数名组织，支持复制稳定身份、跳转与调用位置。函数源码可以受控编辑，写回对应物理文件。
系统脚本：按业务子系统分组。可受控编辑和提交。
表与视图：作为结构和引用事实进入索引。视图仅允许编辑已有的 viewSql SQL 字符串；表格定义（含字段新增、修改）、视图字段和其他元数据保持只读。视图字段由平台解析 SQL 自动生成。

业务分组优先使用显式系统映射；缺失时根据系统/数据源根目录的 $.中文名称、pages/index.md 和 procedures/index.md 保守推断。证据不足的系统或数据源保留独立分组，Skill/Public 归入“公共源码”。页面目录、叶子顺序及 SCM 中文名复用页面索引，过程函数包与包内函数分别按名称排序；过程函数节点可复制函数名或 包名.函数名。

PAGE 脚本标签显示页面、节点标签与事件名；完整 PAGE_ID、JSON Pointer 和工作区可从路径与源码悬浮提示核对。Quick Diff 按完整脚本身份隔离差异基线。

5.3 受控编辑

打开可写虚拟文档时，后端创建独立编辑租约，记录 workspace、对象身份、授权相对路径、文件 hash、SVN BASE revision、JSON Pointer、编码、BOM 和换行风格。保存时按以下顺序处理：

  1. 重新核对工作区、provider、对象身份和路径，拒绝越出授权 checkout。
  2. 检查物理文件、当前片段、文件 hash 与 BASE 状态；缓存标签缺少会话或仍显示只读时，Nexus 先强制重新加载一次，再由后端作最终判定。
  3. 同一 PAGE 的其他片段发生变化但当前片段未变时，在最新 JSON 上安全重放；同一片段已经变化则拒绝旧租约覆盖。
  4. 保留编码、BOM、换行和文件权限，以最小范围原子替换，再按物理文件增量刷新索引。

svn read-batch 可以一次读取多个对象；write-batch 会先预检全部目标，拒绝同一物理文件出现两次，任一写入失败时恢复已写文件，全部成功后统一更新索引。短时读写使用带超时的跨进程锁，长操作使用工作区操作锁，解决 Nexus、CLI 和自动化同时访问同一 checkout 的竞争。

精确批量写入

已知“旧文本 → 新文本”时，svn write-batch 可直接接收对象身份和 replacements，由后端打开目标并取得租约；先读多个对象或生成完整候选时，用 read-batch 返回正文和文档 ID。旧显式会话写法仍兼容。命令不允许同一物理文件在批次中重复出现；不要自行遍历 checkout 或循环重试锁。

bash
.venv/bin/python scripts/guthon_tool.py svn --home "$GUTHON_HOME" \
  --workspace products.demo -- write-batch < /absolute/private/change-plan.json
json
{
  "changes": [{
    "sourceType": "procedure",
    "sourceId": "demo.pkg#save",
    "funId": "save",
    "replacements": [{"old": "return true;", "new": "return false;", "expectedCount": 1}]
  }]
}

编辑账本仅在文件不存在时新建；损坏 JSON、错误身份或记录类型会报错并保留原文件。共享操作日志记录 schema 和各阶段时间，实体写回与不同语义仍分别校验。已有文件的直接修改会标记为外部修改，并交给“管理本地源码变更”重新检查。

本地页面编辑与预览

此功能适用于 SVN 工作区的 JSON PAGE。字段、按钮和代码管理可独立使用；原版布局显示另需对应平台的设计器静态资源。具体操作见使用手册。

能力与源码树的关系

单击 PAGE 打开本地编辑器，双击或点击展开箭头继续展开原有事件与字段节点。源代码管理中对 JSON PAGE 文件执行“在 Nexus 中编辑”也进入本地编辑器；明确指定的脚本或字段分块仍进入共用代码编辑器。本地编辑器默认不自动打开原版设计视图，查看布局需主动点击对应按钮。预览标题、标签页和树根显示“页面名称 · PAGE ID”；名称优先采用源码树目录索引中的有效名称，PAGE ID 占位值不作为名称。

预览树隐藏行、列、匿名容器及没有业务标题的单项页签包装，保留表单、表格与有业务标题的页签。页面事件、区域脚本与 SQL、按钮和字段按归属组织，只显示已有事件。点击区域定位清单，点击字段或按钮显示已有属性，点击事件进入共用代码编辑器。

对象支持范围
字段修改已导出的标题、宽高、标签宽度、输入最大长度、隐藏和只读等受支持属性；调整同一字段集合内的顺序。
区域按钮在所属区域的字段清单上方按名称显示，不展示内部按钮 ID；可修改已有名称、别名及受支持的显示属性，调整同一区域按钮顺序，并进入已有前端脚本和服务事件。查询表单的首个按钮配置对应平台“重置”；“查询”由原版组件绘制，不作为新增的可编辑按钮。
事件与 SQL与源码树共用代码标签、继承解析和受控保存流程。仅修改项目段时保留继承标记；修改产品段按既有规则校验并物化到项目源码。
高级字段配置属性面板不等价于完整字段 JSON；数据源字段集合、复杂嵌套配置和未开放属性仍需原有源码分块入口。
草稿与保存边界

布局和属性调整进入页面草稿，已有属性、代码及排序操作可联合预检，经现有页面租约原子写回、刷新索引并验证差异。源码身份、授权范围及内容哈希继续由原有写回流程校验。保存到本地不触发平台同步、编译或 SVN 提交。

代码标签的未保存输入由 IDE 管理。代码通过共用编辑器保存后，与外部源码更新共用三方比较：在当前文件版本上保留互不冲突的属性、按钮及脚本草稿，双方已改成相同值的操作从未保存差异中移除。排序保存需关闭相关已保存代码标签，以免位置变化后旧标签指向其他对象。

页面草稿保存在 IDE 私有工作区存储。字段和脚本使用身份索引定位，撤销历史按修改记录保存，避免每次编辑复制整页；最多保留 50 步撤销，批量调整作为一步，失败时回退该批次。源码变化时保留旧草稿用于导出比较；保存结果不明确时保留请求并提供恢复检查。预览内现有字段或按钮身份不唯一时限制修改；未知控件的属性保持只读，同集合排序独立校验身份。

字段与代码管理首次载入页面基线，后续按序传递变化和状态；缺失中间消息时重新取得基线，旧消息不覆盖新画面。普通属性修改局部更新字段及导航标记，排序、脚本、基线和比较范围变化时重新渲染相应视图。原版设计器仍按其模型初始化契约更新，不将这项优化等同于实际平台渲染性能。

恢复历史存于 IDE 私有存储的 page-recovery/，按页面身份保存带内容校验的独立记录；完整临时记录同步后，以同目录硬链接原子发布正式文件，已存在的文件只在内容一致时复用。工作区状态仅保存引用，界面只接收恢复摘要，导出时才读取完整历史。记录缺失、损坏或保存失败时明确报错并保留原状态，不以空历史替代，也不自动删除历史。已保存且无待核对操作的关闭会话，仅在最新状态持久化完成后按数量和含撤销、重做历史的估算大小回收；未保存草稿或代码、待核对源码及写入、原版候选和运行中任务继续保留，避免改变保存全部草稿的范围。

“比较改动”提供两个只读视角：SVN BASE → 本地已保存源码，与 SCM 使用同一本机基线，不包含窗口未保存输入；本地保存版本 → 当前窗口草稿，只包含尚未保存的页面调整。前者在左侧树使用与 Nexus 源码树相同的 SVN 修改主题色和 M 标记，后者使用蓝色主题色和 ● 标记，可同时存在；标记向所属区域和页面汇总。已删除项保留独立比较入口。中间按属性、事件及排序显示修改前后内容，退出比较不修改草稿。

SVN 比较在工作区授权范围内读取本机 BASE，不访问服务器 HEAD、不新建编辑租约。字段与按钮按唯一原生身份匹配，保留大整数精度；匿名等长集合按位置比较，身份不明确且长度变化的集合整体展示。忽略 JSON 格式与键顺序差异时会明确提示，详细原文仍可从 SCM 查看；超过 1000 项时保留全部标记并提示仅展示前 1000 项。没有可读 BASE 或超出响应预算时明确显示不可用，不以空页面替代。

外部更新时，干净会话自动载入；存在草稿时，按原先加载的值、当前文件值和窗口值进行三方比较。仅在页面来源、工作副本、区域及控件身份唯一且结构、顺序和可编辑范围保持一致时迁移；匿名数组成员、结构增删或移动、身份和属性类型变化均保留旧草稿，要求人工核对。未保存代码、原版未确认对话框及结果待核对的写入不会自动迁移。

同一属性或完整脚本节点被双方改成不同值时，“外部修改冲突”保留三方内容，由用户逐项选择；全部选择完成前不替换原草稿，完成后重新读取文件，只有文件版本仍匹配才迁移。文件再次变化时重新比较并清除旧版本选择。脚本按完整节点比较，不自动合并同一脚本内部的不同行。迁移只调整窗口草稿，后续保存继续执行租约、源码及差异预检；迁移后的撤销针对新基线上的本地调整。

冲突预览每份内容最多显示 8000 字，完整三方值保存在 IDE 私有恢复记录并随草稿导出；旧版本记录在重新载入或显式冲突选择后保留。重开 IDE 时，旧基线草稿及报告供导出核对，不按历史选择自动覆盖当前文件。原版设置对话框发生外部更新时保留当前画面并暂停保存，需先保留输入、关闭对话框后处理。本地保存清除 ●，不会清除尚存的 SVN 差异。操作步骤见比较修改并到平台验收。

平台资源、缓存与版本

Nexus 使用 IDE 自带运行时读取平台入口 HTML，动态解析实际引用的脚本和样式地址，再下载同源静态依赖。文件名中的构建后缀不写死；普通使用无需开发者工具、独立 Node.js 或手工填写资源目录。

静态文件由 Nexus 直接获取，不共享浏览器 Cookie。是否允许匿名下载取决于平台部署；浏览器已登录不保证 Nexus 能取得受保护资源，此时可导入已有资源包。在线“去平台对照”仍需要浏览器登录。

资源自动存于当前显式本地数据目录 <toolHome>/var/nexus/page-designer/：

  • platforms/<平台标识>/<构建指纹>/：保存 snapshot.json 校验清单与 guthon/ 静态文件；同平台同构建复用，不同平台或构建隔离。
  • workspaces/<工作区标识>.json：记录 workspaceKey 对应的平台入口和所选资源版本；切换只影响当前工作区。

构建指纹包含入口 HTML 及入口脚本、样式的实际摘要，不能只凭版本名称或主程序文件名判断。下载先进入临时目录，完整校验后才激活；失败、不兼容或缓存损坏时不覆盖现有可用资源，也不改用其他平台的快照。

打开已绑定页面时，成功的版本检查结果在 24 小时内复用；到期再次打开会检查平台构建。检查失败时保留已校验缓存并标明离线状态，短时间内不重复失败请求。发现新构建时提示下载切换或继续旧缓存，不静默替换；支持手动检查、导入和选择缓存版本回退。

从资源菜单到下载、校验及打开视图，同工作区重复点击复用当前任务。资源按钮在处理期间禁用，完成或失败后恢复；通知与“Guthon Nexus SVN”输出显示阶段、逐文件进度、累计大小及完成结果。

限制与效果验收

图形面板不提供字段或按钮增删、跨容器移动及新增属性或事件；AI 可通过下文的受控结构接口新增字段、区域按钮及缺失事件。两类入口都不执行业务脚本或 SQL 查询。静态快照不包含自动采集的工作区系统样式、字典或自定义组件元数据，缺失内容不视为完整支持。

原版设计器负责布局显示，字段与代码管理页不模拟平台外观。原版资源校验成功只证明文件与构建符合检查条件，不证明与在线平台效果一致；系统动态样式、组件、运行时行为及业务结果仍需客户端和平台验收。对照应使用相同 PAGE 版本、内容区宽度、缩放和设计/运行模式。

维护者准备资源包

维护脚本与 Nexus 共用资源下载和校验实现。准备新快照可执行 node scripts/prepare_page_designer.mjs --platform-url https://platform.example/guthon/index.html --output /absolute/new-directory；已有快照可用 --source /absolute/platform-assets 校验，或同时指定新的 --output 复制。已有输出目录不覆盖，资源不进入公开 VSIX。

项目与产品继承

独占一行的 inherit() / @inherit() 标记支持带分号或省略分号；注释、字符串和其他表达式内的相似文本不作为继承入口。解析版本变化后，应完整重建目标 SVN 工作区索引。

SVN 项目过程函数将普通 .gss 与同目录的 .inherit.gss 关联为一个逻辑函数；后者作为只读产品层。Nexus 默认在项目可编辑标签页显示展开后的完整源码，以低饱和度整行背景区分产品与项目段，编辑器差异基线也同步展开，避免把继承段误标为修改。只改项目段时保存仍保留继承标记；改动产品段时将完整候选保存到项目文件或 PAGE 项目事件，并复核产品哈希。return @inherit(); 等不能证明控制流等价的标记需在保存产品改动时显式核对。

PAGE 产品事件集合存在时，省略的事件键按空源码处理；仅含继承标志且展开后为空的事件不生成 Nexus 源码分块。项目附加代码与非空产品代码仍保留；产品集合缺失或结构异常仍提示继承诊断。原始 PAGE JSON 不因索引投影而改变。

PAGE 服务组件的项目 .gss 与同目录同名 .inherit.gss 也按项目层和只读产品层关联；父文件独立索引，不参与 PAGE 别名去重，也不能取得编辑权限。全量重建、单文件刷新和变更批次刷新均保持该分层，编辑与保存始终落到项目子文件。只读来源视图仍可用于查看两层物理来源；旧解析版本的索引需完整重建。

5.4 SCM、冲突与交付

  • 每个工作区注册一个 SCM provider；内部按中文业务子系统分组，同组可聚合数据源与多个系统 working copy，公共源码单独成组。
  • 本地差异比较 SVN BASE 与 working copy；远端差异比较 working copy 与 SVN HEAD。PAGE 默认显示脚本、SQL 和字段的可读差异，也可查看原始 JSON。
  • 支持全部、业务组、原生多选和单文件范围的提交或更新。提交前复核 selection token、文件 hash、当前 SVN 状态和目标文件远端变化，不使用 Git 暂存区。
  • 放弃修改只回退所选文件到 BASE；远端已有新 revision 不会阻止本地撤销，但提交仍会检查目标文件远端安全性。
  • 重叠文本冲突可用三方合并处理，保存并确认后才标记 resolved；新增、删除、未跟踪、属性和树冲突继续阻断。

跨 working copy 的提交按组依次执行，会产生多个 revision，不伪装成原子事务。每次成功提交都追加持久交付回执，记录交付编号、revision、文件和时间。目标文件成功提交并取得 revision，即视为本次源码交付成功；编译、发布和业务运行按需要另行验证。

跨组保存中断时，交付记录保留已确认提交的 revision、剩余文件与结果不确定标记。恢复前重新预览并取得新令牌，只选择仍有本地差异的候选，再核对文件 hash 和远程状态；不把历史 PARTIAL 回执直接改成全部成功。平台保存执行真实 SVN commit，受独立 svn.platform_save 能力限制；MCP 的本地结构与节点更新不执行提交。

6. 索引与 AI 上下文

6.1 工作区事实索引

每个工作区维护自己的 context/index.db，DATABASE 从 readonly 建索引，SVN 从授权 checkout 流式建索引。索引保存：

  • 源码对象身份、真实相对路径、物理 working copy、内容 hash 和对象定位信息。
  • 静态调用、低置信动态调用、调用位置和目标身份。
  • PAGE 片段、字段到表列、单据路由、表读写、条件、赋值和异常事实。
  • SVN PAGE 的可重建脚本、SQL、字段集合节点目录与界面字段目录，包含当前 JSON Pointer、局部语义身份、区域、解析版本与索引 generation；正文仍从授权 working copy 按需读取。无原生身份的数据源列不进入界面字段目录。
  • SVN 对象的 JSON Pointer、BASE 信息和支持增量刷新的文件关联。

SQLite 不支持原生表/字段注释；索引初始化会在 gusen_schema_comment 中保存中文说明。按 table_name 查询时，column_name='' 是表说明，其余行是字段说明；已有索引再次初始化时会补齐。

索引存储与空间整理

字段集合的派生正文采用紧凑 JSON，保留属性值及字符串内部空白；脚本和 SQL 正文保持原样。正文搜索的行号与偏移属于保存的索引片段，字段集合的格式可与虚拟文档不同，应通过 JSON Pointer 回读当前源码。原始 PAGE 和片段定位元数据不受存储精简影响。

index-compact 默认只预览文件大小、空闲页和可精简字段正文；加 --apply 后整理字段正文、优化可用的 FTS 检索索引并执行 SQLite VACUUM；SVN 模式共用工作区操作锁，DATABASE 模式由 SQLite 序列化写入，完成后检查数据库完整性。已截断的字段正文跳过，继续保留部分覆盖标记。字段整理失败时事务回滚；压实失败会报错，已提交的正文精简仍保留。操作不重建源码索引、不连接业务数据库、不修改源码或 Git，保留对象身份、片段哈希、索引代次和变更历史。压实时需预留临时磁盘空间，实际回收量以结果为准；操作步骤见使用手册。

完整重建与增量维护

  • 身份与提交：同名对象以数据源、working copy 和业务身份区分，PAGE ID 保持工作区全局身份。全量重建在事务内完成；身份或授权错误回滚，个别坏文件或未解决的 SVN 冲突会形成带错误清单的 PARTIAL 索引，日志列出被阻断的文件供人工合并。取消或失败时保留旧索引。
  • 首次重建：完整扫描授权文件并建立明细，检索索引在同一事务末尾批量构建。首次使用或解析版本不兼容时需显式完整重建；不把后台监听当作版本迁移入口。
  • 日常更新：按 SVN 实际变更路径批量增删索引；新增目录只扫描相应子树，无变化时跳过解析和写入。删除 PAGE 时重新核对授权页面目录，继承来源变化联动刷新项目文件。
  • 编辑与监听：虚拟保存、撤销和提交按物理文件增量刷新。文件监听按工作区合并、串行处理，哈希与状态已发布的文件跳过；SVN 更新和索引发布共用操作锁。
  • 失败恢复：监听批次失败时先保留该事务涉及的全部文件路径。明确定位到本批文件的 JSON/编码解析错误会隔离失败文件，其余路径另起事务继续维护；身份冲突、关联文件错误及无法定位的错误保留批次边界，要求人工核对。SVN 文本冲突和树冲突按文件阻断：其余文件照常发布，日志逐条输出“冲突阻断”及目标路径；被阻断文件保留上一次索引内容并暂停自动重试，完成三方合并并标记已解决后重新索引。未版本化的冲突产物（.mine、.r<版本>）不是授权源码，不参与解析也不阻断批次。暂时性读取故障最多自动重试两次，分别等待 1 秒和 5 秒；解析、权限或身份错误暂停自动重试，其他文件变化不会重置其重试次数。失败文件自身变化或用户点击索引行、执行“重试 SVN 索引失败文件”时重新检查。未成功部分保留旧索引并显示“待恢复”，每次后端请求最多 1000 个路径。恢复记录保存在 IDE 私有工作区状态，按工作区及工作副本身份隔离；重开 IDE 后校验路径并显示待恢复记录，由用户定向重试。首次建索引或索引版本不兼容仍需完整重建。
  • 任务与日志：排队超时只取消尚未发送的请求；工作区等锁有超时和阶段提示，不中断未知写入。日志记录实际后端构建、毫秒时间戳、批次汇总和完整耗时，失败保留目标路径。
  • 模式隔离：SVN 更新、预览、提交与索引不执行 DATABASE 的 Git 自动暂存扫描，也不清理旧 readonly/workcopy。

svn init 全量建索引，svn refresh 通常按更新结果增量维护；无法安全定位范围的结构变化退回完整扫描。日常 SCM 只执行必要的 svn info --xml/svn status --xml，写回与更新仍使用完整安全检查。普通浏览、虚拟编辑和调用查询仅访问本地 working copy，不查询源码数据库。

索引保存只读派生片段与可选正文/标签 trigram FTS，完整重建后提供有界检索；结果带来源身份、哈希和覆盖缺口。源码编辑仍以授权文件为准，索引不提供第二个可编辑副本。

SVN MCP、Nexus 和 CLI 使用同一份可重建索引，MCP 的独立入口、工具能力和开发边界见第 9 章。PAGE 语义投影与 SVN 对象目录分别报告就绪状态；旧索引需由目标工作区显式全量重建后才提供对应查询；索引 generation 变化会使旧分页游标失效。

排队超过 120 秒只取消尚未发送的请求；工作区阻塞等锁默认最多 60 秒，并输出等待阶段。源码内容与状态未变化时 generation 不空转。坏文件产生的 PARTIAL 索引不等于完整同步成功；授权或身份错误保留旧索引。

Nexus 的 SVN“重建索引”支持协作式取消，ToolHost 通过 cancel-index-v1 声明支持：扫描检查点可回滚当前索引事务，发布屏障后以真实完成结果为准，初始化元数据可能已经完成。DATABASE 重建、SVN 更新/提交和源码写回不适用该扫描取消语义；旧 ToolHost 不接收新控制帧。启动或写入期间切换运行环境会报忙，原请求的工作区不变。

6.2 检索与有界上下文

统一搜索search 同时查询源码身份和事实索引；结果可打开精确源码位置。
关系查询svn definition/callers/find/context 提供定义、引用、调用链和局部上下文。
事实解释svn facts/explain 返回写入位置、控制条件、表关系和有界调用者链。

context-pack 默认生成精简上下文，只保留少量直接关系、高价值事实、路径和短 hash；需要更多证据时再请求详细版本或 continuation token。该流程让 AI 先根据稳定身份和事实缩小范围，再读取准确片段，避免把整个业务仓库塞入上下文后凭相似名称猜测。

“导出 AI 上下文文件”在当前私有工作区的 context/ai/ 创建新 Markdown 文件，默认仅包含有界索引摘要；影响证据或继承正文须明确选择。文件带来源身份与截断提示，不自动上传，也不覆盖已有上下文文件。

Markdown 源码索引和调用索引只在显式执行导出命令时生成，不属于 Nexus 日常运行链路。运行时以 SQLite 为事实来源，可以快速增量更新，也避免大量派生文件污染私有 Git。

7. Guthon Nexus

7.1 工作区驾驶舱

Guthon Nexus 是统一 VS Code 扩展，DATABASE 与 SVN 工作区同时出现在同一侧边栏。每个节点绑定自己的 workspaceKey，菜单由 CLI 返回的有效 capabilities 决定，因此没有配置的功能不会显示为可执行操作。

VS Code 与 CodeBuddy 的扩展设置各自保存；“设置/切换工作空间”可让另一端选择同一 toolHome，读取已有产品/项目配置、状态和 SQLite 源码索引，不新建工作区或重建索引。“刷新已有工作空间状态”会清理 Nexus 的工作区及源码树缓存并重读本地数据，不执行 SVN 更新或全量扫描。

“检查此工作区环境”只检查指定工作区关联的本地依赖，“维护 → 检查本地环境”覆盖全部已配置工作区。数据库驱动按 DATABASE 源码数据源及内置只读目标确定；纯 SVN、仅 DBX 的目标不要求无关本地驱动，系统凭据库仅按凭据来源需要检查。配置失败时依赖范围标为未确认，不用“本次未使用”替代错误；源码数据源仍按原契约只支持 MySQL/PostgreSQL，内置只读目标可使用 Oracle。备用密码来源存在时，凭据库不可用可显示提醒，但不核验备用值。

Nexus 展示检查项和固定处理入口，配置文件限定为工具已知文件；运行入口或数据目录在检查期间变化时，需重新检查后再处理。检查只读取本地配置和依赖、探测本机 Bridge 健康端点，不取用系统凭据库中的密码或密码文件，不执行数据库连接或平台业务验证。CLI 原有 doctor --json 仍返回检查列表，含 FAIL 时退出码为 1；新增 doctor --report 返回完整报告，检查执行完成时退出码为 0，结果需读取 health、summary 和 checks，报告的 ok=true 不表示环境检查全部通过。可用显式 --workspace 或 --workspace-key 限定范围，两者同时提供时必须一致。--bundle 继续只导出允许的元数据，不与 --report 合用。

  • 配置或切换 toolHome、添加/删除产品和项目、切换源码来源、打开配置与目录。
  • 显示同步状态、索引就绪度、SVN working copy、本地/远端变更和最近交付回执。普通本地修改不计入健康问题；索引未就绪、同步失败、资料部分完成及跳过的 SVN scope 仍提示处理。本地修改数按工作副本统计，实时文件状态从 SVN 变更入口查看。
  • 执行 DATABASE 同步、元数据导出、Workcopy 管理和只读数据库排查。
  • 执行 SVN 检出、更新、索引、业务目录浏览、虚拟编辑、差异、冲突处理和精确提交。
  • 搜索当前工作区完整索引，并复制精简或详细 AI 上下文。

完整索引搜索与 SVN 快速打开共用输入即查询的搜索窗口；完整搜索回车打开源码，结果按钮分别复制精简、详细 AI 上下文或导出文件。查询按输入合并并串行执行，迟到的旧结果不覆盖新关键词；关闭窗口后不再更新结果。结果达到查询上限时显示截断提示，需细化关键词，不能把当前列表视为全部匹配；操作步骤见使用手册：驾驶舱与工作区管理。

SCM 顶部及业务分组提供刷新本地状态、提交全部本地修改、更新全部远程变更。“更新全部远程变更”先检查远程并展示文件列表，再弹窗确认；取消保留列表供查看差异，不保存文档或执行更新，普通本地刷新也保留远程列表。确认后才保存未保存的 SVN 文档，根据保存后的本地状态执行更新或 SVN 原生合并；单文件更新使用相同流程并保持精确路径范围。

“谷神源码”树支持展开、收缩、刷新、水平滚动、索引搜索、从树跳到资源管理器，以及从当前虚拟文档或物理文件反向定位树节点。顶部展开、收缩按钮作用于所选容器；选中源码分块或单文件节点时作用于其父节点。收缩递归收起目标子树并选中目标节点，恢复焦点时保持收起，其他页面保持原状态；未选中节点时不执行操作。路径跳转会核对 workspace、checkout 和 sourcePath，拒绝越界。

7.2 语言与导航

  • .gss 是独立 Guthon GSS 语言，在 Java 语法基础上注入 Velocity/GSS 指令和变量；兼容的 .vm 保持 Java 关联。
  • Java、JavaScript、SQL 提供谷神 API 补全与悬停说明；路由规则根据上下文选择 sqltools、sql 或 sqlh 等 API 族。
  • 过程函数调用支持静态字面量形式的 $vs.proc.invoke、$vs.thread.run、$vs.thread.runFutureTask，以及 proc.find 绑定后的方法调用；在函数名上转到索引中的定义。变量或字符串拼接目标不做猜测；过程函数内的 @子方法(...) 可转到当前源码的 #function 声明。定义跳转与“谷神源码”树使用同一虚拟文档，支持从编辑器定位树节点；索引对象也支持查找引用与调用位置。
  • SVN 虚拟 GSS 根据当前文档的 #function 声明补全 @ 调用，并提示重复的本地函数名；PAGE 字段集合分块先用当前有效 JSON 的 fieldId 补全 selectCodefieldId，再按精确 PAGE 身份和字面前缀查询其他集合的有界候选，标明来源；候选较多时继续输入前缀缩小范围。同一集合重复值会警告；兄弟分块有未保存修改时不引用其旧索引。这些提示不替代平台语法或业务校验。
  • 源码树中的 PAGE JSON 和过程函数提供“预览源码影响”及“浏览影响证据”。PAGE 展示索引中的表访问、显式字段关系与逻辑事实，可跳转到字段关系所属集合或表访问、逻辑事实的源码片段与索引行；过程函数展示静态调用边与动态调用线索，并可跳转到索引行。预览显示 PAGE 索引代次及源码哈希，结果按上限截取，索引文件身份不一致时拒绝归因。PAGE 字段关系只覆盖显式 selectBox 证据，不能用于自动删除判定。
  • PAGE 节点的“查找其他 PAGE 的字段”在同一工作区与命名空间内按 fieldId 字面前缀有界分页检索，返回 PAGE、工作副本、字段集合与表列 ID 来源；所有跨 PAGE 关系标为未验证，不自动补全或推断引用。命令面板和 Chrome Bridge 弹窗、页面左下角按钮共用本地精确定位：PAGE 只传完整 PAGE ID，过程函数只传包名与函数名；由用户明确选择 SVN 工作区，多份源码当次选择，再打开受控虚拟文档。浏览器入口要求已安装包含 URI 处理器的 VSIX，并在安装后重载 VS Code。
  • 补全索引、人工片段和路由规则分别维护，使自动生成 API 与项目特定规则可以独立更新。
  • SCM 使用 VS Code Quick Diff 以 SVN BASE 标出增删改，点击装饰即可内联查看。

跨对象定义与引用依赖工作区索引，不扫描所有文件；当前虚拟文档的本地函数与字段提示读取编辑器正文。过程函数调用按索引证据定位，遇到同名身份无法确认时仍须核对目标源码。

过程函数补全可为 proc.invoke 提供包名/函数，为 proc.find 提供包名；各命名空间分别显示。索引不可用时仍保留当前文档本地建议。PAGE 的不同事件即使 BASE 正文相同，内联差异也按完整脚本身份隔离；已有标签按完整身份复用，升级后关闭重开旧标签可更新标题。仅独立 PAGE GSS 服务组件使用中文标签，有函数名的过程函数仍显示英文函数名。

7.3 工具更新

“运行模式 → 检查更新”统一检查后端、Nexus VSIX 与 Chrome Bridge。默认每天首次激活后后台检查，角标显示候选数量；安装由用户确认。发行与调试模式从 GitHub / Gitee 取得候选，开发模式从显式 developmentRoot 构建本地 Nexus 与 Bridge，后端继续使用源码。

  2. 候选后端在临时数据目录执行自检，通过后再切换受管入口；失败保留已有安装。
  3. Nexus 自安装最后执行，安装后可立即重新加载窗口或稍后；各 IDE 分别核验实际安装。

更新与回退共用跨窗口锁；新候选自检通过前保留原安装，中断的半安装目录保留为 recovery 备份。版本探测失败明确报错并允许重试，缓存不覆盖回退状态。调试模式使用用户选择且校验通过的 Python，不能将源码构建能力写成已交付的一键隔离运行环境。

8.2 路由与安全边界

  • 请求携带 workspaceKey 时，Bridge 继续核对页面身份；缺失时按 pageOrigin + dataSourceId + systemId 查找候选。
  • 存在多个候选时由用户为当前请求选择，不写入全局默认，也不影响其他页面。
  • 允许访问的页面范围由扩展的来源、域名后缀和路径规则限制。
  • 本地服务默认监听 127.0.0.1:17361，扩展须使用相同端口并完成令牌配对。
  • Nexus 把当前应用入口和 toolHome 传给 Bridge，用户无需手工配置环境变量或安装 Node.js。

首次连接时从 Nexus 复制配对令牌，在扩展弹窗保存；两端默认端口为 17361。服务重启保留令牌，页面不能读取令牌。Nexus 以带令牌的状态请求确认实例，未认证的 health 只说明有服务在线。

/pageContext 最多保留 64 个浏览器页签快照，每个快照含最多 32 个平台内部页签，租约 150 秒。快照只含有界身份元数据，不含正文、SQL、选中文本和本机路径。Bearer SSE 推送快照变化、定位指令及回执，60 秒元数据心跳恢复暂停的扩展后台或重启的服务。来源、工作区或租约失效时拒绝导航，重连不重放。

长任务通过 /submitJob//jobStatus 提交持久请求并短轮询，扩展重启后可从“查询待恢复任务”回查；Bridge 重启把未完成任务标记 UNKNOWN，不自动重放。弹窗只记录最近 20 次成功拉取对象和上次导出目录，按同一平台来源显示；UNKNOWN 不进入成功历史。再次拉取创建新请求，丢弃旧 force/confirmation。pull-log tail/summary 只观察工作区与 Bridge 保留日志的有界窗口，返回坏行与缺口提示；日志在 5 MiB 轮转一份。

有明确 workspaceKey 的任务按工作区串行，最多 4 个工作区并行、32 个队列项和 8 个工作区客户端；闲置客户端按近期使用回收。未解析工作区的旧请求仍走单队列，每条命令重新核对归属。/status 返回 activeWorkspaces，不以一个全局“当前工作区”描述并行任务。写入期间 Node 可为读取启动独立只读 ToolHost，执行与排队超时按请求参数传递；MCP 工具调用保持 FIFO，协议线程仍可即时回应 ping。

独立 host-settings.js 保存允许的平台主机规则，托管更新保留该文件。web_accessible_resources 使用 Chrome 要求的 HTTP/HTTPS 来源模式，内容脚本与页面脚本另行校验 /guthon/ 路径及允许主机，不能只凭资源声明推断访问权限。

导出根固定为 <toolHome>/var/nexus/bridge/exports，维护者可显式设置 GUTHON_BRIDGE_EXPORT_ROOT；历史目录不能绕过约束。平台提示不展示本机路径或原始异常，详细信息保留在扩展弹窗和本地输出。端口占用时报错，不接管另一实例。令牌仅保存于本地运行目录与扩展存储；网页和 MAIN world 仍共享页面脚本环境，配对本身不能证明平台没有 XSS。

Bridge 的普通拉取不自动向平台写回源码，也不执行 SVN commit；SVN 检出、编辑和提交从 Nexus 或明确的受控接口完成。明确发起的整页新建、复制和删除会调用平台原生接口，范围见PAGE 生命周期。

9. Guthon SVN MCP

SVN MCP 与 Nexus、Bridge 同属 GuthonCodeTool 的用户入口，但职责不同：Nexus 服务 VS Code 中的开发与 SVN SCM，Bridge 服务受限谷神网页，MCP 服务 AI 客户端对已授权 SVN PAGE 和过程函数的定位、证据读取和受控源码修改。MCP 是共享服务的协议适配，不建立第二套索引、授权清单或文件写回路径。推荐客户端别名为 guthon-svn；旧 guthon-page 别名仍可指向同一入口，迁移不应重复启动两个服务。

9.1 入口与能力

客户端以 mcp --stdio --home <toolHome> 启动独立进程；stdio 握手支持 MCP 2025-03-26、2025-06-18 与 2025-11-25；不支持无握手的新版协议，客户端须确认服务端返回的版本。--home 明确目标数据目录，每次工具调用再传 workspaceKey；PAGE 查询还需精确 sourceNamespace、sourceId，必要时带 funId；过程函数需带 sourceNamespace + sourceId + funId；唯一命中时可省略 workingCopyId，多候选必须补全。运行入口可用发行应用、Release pyz 或源码开发环境，但客户端配置分别指向各自实际存在的可执行文件和绝对路径。

默认发现 66 个工具；加 --read-only 时发现 49 个只读工具（包括操作回查和候选预览），隐藏 17 个写入源码、租约或恢复状态的工具。

客户端配置参考

客户端配置始终分开传递 command 和 args。发行模式的 command 是应用文件；pyz 模式为 Python，args 以 pyz 路径开头；源码模式为仓库 Python，args 以 scripts/guthon_tool.py 的绝对路径开头，再接 mcp --stdio --home 和数据目录。包含空格的路径仍是一个参数，不使用 Shell 展开 ~ 或环境变量。

9.2 共享索引与安全边界

  • MCP 只面向显式配置的 SVN manifest 工作区。PAGE 需完整页面身份；过程函数唯一命中时可省略 workingCopyId，多候选或继承读取须提供准确工作副本身份。不能只凭显示名称或目录位置猜测。
  • context/index.db 保存可重建的 SVN 对象目录、PAGE 节点、界面字段和保守关系投影；PAGE JSON、过程函数、脚本与 SQL 正文仍以授权 working copy 为准。无原生身份的数据源列仍通过字段集合按需读取。对象目录就绪不依赖 PAGE 语义投影就绪。
  • 字段关系仅确认显式 selectCodefieldId 等有证据的子集，并保留未解析 otherSetFields 诊断。动态、继承与反射组引用尚未形成完整闭包，check_page_field_references 不能批准字段删除。
  • MCP 不自动安装到客户端，不修改既有 MCP 配置，也不决定 AI 何时调用。工具是否可见及是否主动调用取决于客户端连接和 guthon-team 的工具路由规则。

MCP 风险注解按副作用区分：查询和预览为只读；租约创建、续期、释放、写后核验恢复与可恢复日志归档为非只读、非破坏性；源码写入保留破坏性标记。工具声明不访问开放世界，注解不替代客户端审批和服务端授权。--read-only 隐藏所有非只读工具。

9.3 写入范围与验证

PAGE 提供 open_page_node_edit、preview_page_nodes、update_page_nodes、get_page_operation、resume_page_operation 五个工具，限定稳定的同页脚本/SQL 字符串节点；另支持已有字段 label / disName 的受控显示文本修改；提供 open_page_field_insert、preview_page_field_insert、insert_page_field，只允许同一已识别 UI 字段集合内的单字段新增或拷贝，并共用 PAGE operation 查询/恢复。过程函数提供 open_procedure_edit、preview_procedure、update_procedure、get_procedure_operation、resume_procedure_operation 五个工具，限定完整身份匹配的一份授权物理文件。工具可见不等于目标可写：编辑令牌绑定授权、会话和源码快照；预览不落盘，正式写入重新校验 edit 能力、当前源码、索引及 SVN 状态，再以 idempotencyKey 记录操作。只改本地 SVN working copy，后续记录索引与 diff 核验，不执行 SVN commit。受控结构接口支持字段/按钮增改删、同页同类型复制与区域移动、事件、数据源及原生行列/TAB 布局。整页新建、复制和删除通过已配对 Bridge 使用平台原生接口；平台提交发布、菜单管理及任意根元数据修改仍不提供。

具体安装版本应在客户端核对握手、工具清单、目标索引和实际源码差异。一个工作区索引就绪不能代表其他工作区也就绪；PARTIAL、REBUILD_REQUIRED 与 INDEX_STALE 应按目标身份重新取证。字段删除和移动不会自动修正脚本引用；完整字段关系闭包不在当前能力范围内；复杂映射需逐项核验，预览保留未解析证据；使用默认写入能力时应人工核对 SVN diff，不把工具响应当作平台运行证明。具体配置和调用顺序见使用手册第 5 章。

9.4 调用流程与参数约束

定位与有界读取

  1. 重启或重载 MCP 客户端，确认发现 guthon-svn 及包含结构编辑入口的工具清单。先调用 get_runtime_status，再以明确 workspaceKey 调用 PAGE 的 get_index_status 或过程函数的 get_source_index_status。
  2. 用 search_sources 搜索 PAGE 名称或 ID，并设 sourceType=page、较小的 limit。从结果复制真实 sourceNamespace、sourceId 和 funId；同名对象不猜第一个。
  3. 以完整身份调用 list_page_nodes 或 list_page_fields；从目录选择稳定的 semanticNodeId/semanticFieldId，再用 read_page_nodes/get_page_field 定点读取。若改用 jsonPointer，同时传目录返回的 indexedSourceHash。
  4. 需要局部证据时调用 get_source_context 或 list_page_field_relations；check_page_field_references 只提示显式和未解析引用风险，不能证明字段可安全删除。
json
{"name":"get_index_status","arguments":{"workspaceKey":"products.<id>"}}
{"name":"search_sources","arguments":{"workspaceKey":"products.<id>","sourceType":"page","keyword":"页面名或 PAGE ID","limit":20}}
{"name":"list_page_nodes","arguments":{"workspaceKey":"products.<id>","sourceNamespace":"从搜索结果复制","sourceId":"从搜索结果复制","funId":"从搜索结果复制","limit":20}}

过程函数先以 sourceType=procedure 调用 search_sources，复制结果中的完整 sourceNamespace、sourceId、funId 和 workingCopyId，再用 read_procedure 按 offset/maxChars 有界读取；如需调用方证据，用 list_procedure_callers。同名或多 working copy 不猜第一个；调用方索引无法区分同别名目标时会拒绝归因。

PAGE 脚本与 SQL

默认 MCP 允许 AI 对已授权 SVN working copy 中的稳定脚本/SQL 字符串节点发起本地修改；已有字段显示文本可用专用更新工具；同一集合的单字段新增/拷贝见下文。这些节点接口不创建缺失结构；字段、按钮及事件新增使用下文的结构入口，任意 JSON 元数据和字段集合整体替换仍不开放。操作前应确认目标 workspaceKey、PAGE 身份、当前文件差异和工作区 edit 能力；仅仅发现写入工具不代表某个对象已获写入许可。

  1. 从 list_page_nodes 的结果选定 identityStability=STABLE 且 nodeType=SCRIPT 或 SQL 的目标，调用 open_page_node_edit 获取绑定当前源码与授权状态的短期 editToken。
  2. 用 preview_page_nodes 提交 editToken 和新 content，检查候选 hash、变更摘要和错误；预览不落盘，也不保证后续写入时源码仍未变化。
  3. 确认修改后用同一批 token 和内容调用 update_page_nodes，提供调用方生成并保存的唯一 idempotencyKey（8–128 个无空格的可打印 ASCII 字符）。多个节点必须属于同一份 PAGE，服务会重新预检并一次写入本地文件。
  4. 保存返回的 operationId。响应丢失时先用 get_page_operation 按原 idempotencyKey 查询，不要换 key 盲目重试；后置索引或 diff 核验未完成时按 operationId 调用 resume_page_operation。
  5. 最后在 Nexus 的 SCM 中人工审阅 SVN diff，并按项目流程验证；MCP 不执行 SVN commit，也不把本地写入当作谷神平台提交或运行成功。

过程函数

过程函数写入只针对完整身份确定且获授权的 SVN working copy 物理文件。调用 open_procedure_edit 获取短期 editToken，以 preview_procedure 提交完整 content 或精确 replacements 检查候选 hash（预览不落盘），再以同一 token、候选和唯一 idempotencyKey 调用 update_procedure。响应丢失时用 get_procedure_operation 按原 key 查询；后置索引或 SVN diff 核验未完成时，用返回的 operationId 调用 resume_procedure_operation。最后人工审阅目标文件 diff；不可将本地写入等同平台运行成功，也不可通过 MCP 提交 SVN。

SVN MCP 风险标记按副作用区分：查询和预览为只读；编辑租约创建、续期、释放、写入后的索引与差异验证恢复及已完成日志的可恢复归档为非只读、非破坏性；源码写入保留破坏性标记。平台上下文查询、整页生命周期租约和派发标记访问外部平台，其余操作限定本地授权工作区。客户端仍可根据实际请求和授权策略要求审批；风险标记不替代服务端校验，--read-only 仍隐藏所有非只读工具。

Bridge 的 web_accessible_resources 按 Chrome 要求使用 http://*/* 和 https://*/* 来源匹配；该字段不能用 /guthon/* 限制路径。内容脚本仍仅自动注入 /guthon/*，页面脚本继续校验允许的地址。若出现 Invalid match pattern，请更新扩展目录后重新加载。

!

写入依赖编辑租约、源码/索引 hash、授权范围和 SVN 状态的再次核对。实际使用时核对客户端工具清单、版本与目标工作区状态；出现未完成或外部改动时先查看 operation 状态和实际 diff，不强行覆盖。删除、移动或改绑定前核对显式关联和未解析映射；工具不自动改写业务脚本引用。

同集合字段新增与拷贝

仅支持一份 PAGE 中同一个已识别 UI 字段集合的单字段新增或拷贝；不支持跨 PAGE、跨区域/集合、反射组、删除或移动。先用 list_page_fields 获取字段的 collectionPointer、semanticFieldId 和 indexedSourceHash；空集合可从 list_page_nodes 的 FIELD_COLLECTION 节点取 Pointer。目标必须属于表单、查询、主表或明细表组件，且当前索引与源码一致。

  1. 调用 open_page_field_insert，传完整 PAGE 身份、collectionPointer、indexedSourceHash 和 action=add 或 copy。新增时传完整 field 对象（至少有 fieldId、type）；拷贝时传同集合来源的稳定 sourceSemanticFieldId、新的 newFieldId，可选 newLabel。可用 afterSemanticFieldId 指定同集合插入锚点，否则追加。服务始终生成字段自身的新 id；若候选带 guid 键则重生成，否则保持无 guid，不会把缺失值当成重复身份。返回固定候选和短期 editToken；不要自行改写 token 内的候选。
  2. 调用 preview_page_field_insert 核对候选 hash、字段编码和插入位置。预览不落盘，且不是正式写入的并发保证。
  3. 确认后以同一 editToken 和唯一 idempotencyKey 调用 insert_page_field。响应丢失先用共享的 get_page_operation 按原 key 查询；后置索引或 SVN diff 核验未完成时用 resume_page_operation，不要换 key 再插一次。
  4. 人工审阅目标 PAGE 的 SVN diff，确认字段配置、顺序、引用与平台行为；MCP 不执行 SVN commit。

本阶段拒绝字段编码重复、来源身份不稳定、双重编码 PAGE、疑似反射或未解析字段引用。复制生成字段自身的新身份，并重建附属按钮身份；不自动修正脚本和关联关系。保存后核对实际 SVN diff；平台运行与业务行为另行验证。

PAGE 设计契约与结构编辑

先调用 get_page_design_contract 获取操作参数、字段类型、事件和属性路径；使用 inspect_page_design 检查精确授权页面，或用 validate_page_design 在内存检查 AI 生成的候选。诊断包括表格列缺失/重复内部 ID、同区域重复字段编码、错误对象形状和不符合原生 views.rows 的布局。结果有界且明确不代表平台往返编辑或业务运行已通过。

调用 open_page_structure_edit，核对 insertTargets、eventOwners 及 owner 的 properties/allowedEvents。租约绑定不可变页面身份，已创建的空白 PAGE 不再需要字段或占位脚本。整页新建、复制和删除见下文生命周期入口；本结构接口只修改已有授权文件。

操作 kind参数与行为
insert / copy新增传 collectionPointer,item；同页复制传来源 collectionPointer,fieldKey、可选 targetCollectionPointer 及设置新字段编码/别名的 patch。缺失 ID 和原生默认结构由共享构造器补齐；复制重建字段和附属按钮身份。
patch传 ownerPointer,patch，按返回的属性路径修改字段、按钮、控件或页面设置，例如 selectBox.forceSelection。内部 id/guid 和产品层不可改。编辑保留原生身份。
remove / move传精确 collectionPointer,fieldKey；移动另传 targetCollectionPointer，只允许同页同类型区域。产品字段/按钮不能删除或移出。操作不会自动修正 SQL、脚本或外部引用。
event / removeEvent传 ownerPointer,eventType,eventName；增改事件另传 content。只支持 owner 返回的导出键；继承事件通过既有继承编辑入口处理。
datasource传控件 ownerPointer 和原生数据源 value，包含 dsType,fields,pks 及 sql 或 script。声明来自平台元数据；不执行 SQL、不调用在线 SQL 解析或编译，继承数据源走继承入口。
repairIdentities传 collectionPointer，只补齐缺失内部 ID 或重建重复项的 ID，保留首个有效 ID、字段编码和属性；产品成员不自动修复。先预览并核对受影响列，不能以该操作自动合并重复业务字段。
grid传栅格表单 ownerPointer,rows，设置原生 gridRows，由 cell.control.ctrlId 绑定字段；新增字段需同批放入单元格，否则平台保存会丢弃未放置字段。删除或移动栅格字段时，用 layout 同步调整字段和单元格。
layout传完整原生 rows 行列/控件/TAB 树，调整控件增删和布局；同步派生 views.ctrls。新控件需显式名称和已核对的配置；新增字段补齐原生结构，保留已有成员身份及产品层。
property / text / order沿用常用显示属性、已存在脚本/SQL 和同集合排序入口。参数以契约返回值为准。

preview_page_structure 与 update_page_structure 接收相同 operations。预览返回候选 hash、createdNodes 和 designDiagnostics；缺失身份在同一源码快照下确定生成，保存与预览一致。删除、移动、事件删除、身份修复和布局替换单独用一次单操作批次，新增与排序分开保存并重新取得租约，防止数组位置变化误改对象。以唯一 idempotencyKey 正式保存，未知结果按原 key 查询 operation，后置核验未完成按 operationId 恢复。

事件按真实控件区分：表格列有 formaterScript/onChangeScript/getCellStyleScript；表格后台 SQL 前事件为 beforeSqlSelectScript。按钮前台点击为 pageEvents.onClickScript；提交按钮后台事件按保存、删除、导出动作返回，保留平台的 complateSaveScript/complateDeleteScript 拼写。按钮别名可空，仅填写时要求区域内唯一；启用权限隐藏时必须同时配置别名和权限。

字段集合直接保存也会补齐新成员并拒绝已有成员的身份被悄悄更换。表格列必须具有唯一内部 ID：平台编辑按 ID 定位替换，缺失或重复可能改错列并出现原字段与改后字段并存。显式 selectCodefieldId 需在目标集合唯一命中；复杂映射仍须逐项核验。源码检查和本地预览不等于已安装客户端或平台验证。

CLI 共用 svn page-editor JSON stdin：contract 查询契约，inspect 检查精确页面，validate 检查候选，structure-open 取得租约，preview/save/resume 预览、保存与恢复。遵循 runtime descriptor 的命令及显式 home/workspace 契约。更新后重启 MCP 才能发现新工具。

整个 PAGE 的新建、复制与删除

整页生命周期直接影响谷神平台，和本地结构编辑分开。需更新本地工具、Bridge 服务及 Chrome 扩展，重启 MCP，在平台登录并选择正确系统、展开目标模块树，Bridge 弹窗绑定工作区和配对令牌。工作区必须启用 svn.edit；服务和扩展分别核对目标页签来源、工作区、当前系统及已加载模块。无连接或身份不匹配即拒绝，不改用猜测的配置路径或凭据。

  1. 调用 get_page_lifecycle_context，传 workspaceKey，可选 contextId,pageId,bridgePort（默认 17361）；多个页签时先从返回候选选择 contextId。获取平台模块的 systemId/mkId 和来源 PAGE 元数据/源码版本。
  2. 调用 open_page_lifecycle_edit，指定 action=create/copy/delete、页签和属性。新建需真实 systemId,mkId,pageType,pageName，按类型补齐 pageAliasId,title，可指定权限、事务和原生页面模板；页面类型为 0–6。复制/删除需精确来源 pageId，复制可覆盖目标模块、名称、别名等，不能改变原页面类型。未指定复制别名时沿平台规则追加 .copy。产品页禁止删除。
  3. 调用 preview_page_lifecycle 审阅冻结的来源、目标、平台来源和 candidateHash；再以同一 hash、editToken 和唯一 idempotencyKey 调用 apply_page_lifecycle。平台自行分配 PAGE ID，并通过原生复制逻辑处理内容与身份，不伪造 checkout 文件。派发前复查来源元数据和源码版本，并拒绝目标平台未保存的草稿。
  4. 按返回的 page-life:v1: operationId 用 get_page_operation 查询，或 resume_page_operation 继续等待原回执；恢复只查询，不重发。租约只消费一次，换 key 也不能重复派发。PENDING/UNKNOWN/APPLIED_UNVERIFIED 均不能视为创建或删除已完整验证，必须先对照平台模块树及原操作记录。
  5. 平台操作完成后刷新模块树并按现有同步流程更新本地 SVN 源码与索引；生命周期响应明确返回 localSourceSynchronized=false，不自动提交 SVN、发布或覆盖已有本地差异。

平台接口调用成功不等于已安装环境、跨版本平台或业务验收。当前生命周期不自动管理菜单，不自动保存设计器草稿；复制完成后仍应检查绑定、权限、事件和字段属性的后续编辑。与他人同时编辑时，版本复查不能代替平台服务端事务级并发保证。

已有字段显示文本

通过 open_page_field_update 指定稳定 semanticFieldId、当前 indexedSourceHash 与仅包含 label / disName 的 patch；preview_page_field_update 检查冻结候选，再以 update_page_field 和唯一幂等键写入。共用 PAGE 操作回查与后置核验。该接口不修改字段编码、类型、绑定或脚本。

结果带 nextCursor 才继续翻页。CURSOR_STALE 从第一页重查；SOURCE_STALE / INDEX_STALE 先刷新目标源码与索引，不能沿用旧 Pointer。响应不明先按原幂等键回查，不换键重复写入。

10. guthon-team 治理

10.1 安装与更新

团队治理通过团队 Marketplace 中的 guthon-guard 插件分发。插件在新任务的 SessionStart 阶段检查工作区并幂等初始化：已是当前版本时不重复写入，缺失或版本更新时补齐规范、Linter、API 索引和配置。支持 Hook 的客户端还需对插件 Hook 完成信任；不支持 Marketplace 或 Hook 的环境可使用同一发行物中的独立安装器。

治理安装面向业务 var 工作区，不写入 GuthonCodeTool 源码仓库。核心 AGENTS、规范正文和 guthon-lint 即使没有 Marketplace 或 Hook 也能使用，Hook 只负责自动选择检查时机。

Release 中的 guthon-testing.zip 可单独安装到客户端 Skills 目录；普通用户可使用工具内置只读连接器，无需为此安装 DBX/MCP。首次在 Nexus 为目标工作区配置专用只读数据库账号，Skill 安装不代替连接与环境身份配置。其源码与适用范围见 Guthon Testing Skill。

10.2 规范门禁

规范层AGENTS 与权威标准说明业务语义、开发模式、方言 API 和允许的写入范围。
判定层guthon-lint 用稳定诊断码检查受保护路径、非法 API、Velocity 结构、赋值、重复保存和 SQL 兼容性。
时机层Agent Hook 在任务与工具生命周期检查，Git Hook 在提交前兜底；需要时可把同一 CLI 接入 CI。

版本清单和文件哈希用于判断规范是否完整、是否被本地修改以及升级是否安全。人工修改不会被静默覆盖；强制更新前先备份。私有 API 索引使工具能明确判断函数是否存在，避免用通用语言经验猜测谷神方言。

治理采用“语义规范 + 可执行 Linter + 生命周期 Hook + Git/CI 兜底”，因为提示词只能提醒，不能稳定证明每次修改都经过同一规则。Linter 通过只代表已覆盖的静态规则通过，不代表数据库、平台编译、SVN 或业务流程已经验证。

从业务 cwd 执行 Linter 的 --changed 时只检查当前工作区；Git pre-commit 的 --staged 检查整个暂存集合。两者使用 runtime descriptor 的明确入口，静态门禁不扩大业务源码的发布或数据写入权限。

11. 构建、发布与验证

11.1 发行物

Windows 的 GuthonCodeSetup 下载清单与首次配置统一见 Windows 安装步骤第一章：一键安装配置。默认一键安装器采用精简联网模式：内置后端、Nexus、Bridge、独立 Python 与安装指南；复用已有 CodeBuddy、Git、SVN，仅对缺失工具从固定官方 HTTPS 地址下载并校验 SHA-256。下载失败可重新运行，已校验缓存会复用。首次安装缺失工具时需要联网；离线完整包仍可由维护者按原流程构建。单独安装或修复仍可采用手动流程。

Python 应用使用 PyInstaller 构建，并内置公开配置模板与版本信息：Windows 为单文件 EXE，macOS 为目录形态（onedir）。Nexus 发行模式统一选择可执行文件：Windows 选择 EXE，macOS 进入完整应用目录选择同名启动文件。构建必须在目标系统执行，以生成 Windows x64 应用和 macOS ARM64 应用。发布流程同时完成：

  • 运行 Python、Nexus 与 Bridge 的相关测试。
  • 打包 Guthon Nexus VSIX 和 Guthon Bridge Chrome ZIP。
  • 打包公开的 guthon-testing Skill。
  • 为应用与组件生成摘要和签名元数据，并发布 GitHub Release；Gitee 镜像单独同步并核验附件完整性。

Release 不包含真实配置、凭据、业务源码、私有索引、日志或 guthon-team 内容。工具应用可以替换升级，用户的 toolHome 保持不动。

平台支持与发行完整性

正式发行面向 macOS Apple Silicon 和 Windows x64，不提供 Intel Mac 包。根目录 VERSION 是统一版本来源；GitHub Actions 构建两平台应用、Python zipapp、依赖清单、VSIX、Chrome 扩展、Skill、checksum 及签名元数据。发布说明按私有模板准备，不把私有草稿提交到公开仓库；CI 使用经检查可公开的提交说明或手动传入正文。

更新仅允许 HTTPS 和受约束重定向，下载与哈希流式处理，核对 API digest、checksum 和实际文件。Nexus 从 data/release-trust.json 加载固定 Ed25519 公钥（当前 key ID 为 guthon-release-20261004），员工无需配置。签名缺失、伪造或哈希不一致时阻止新候选执行，保留已有安装；维护者的本机 globalStorage/release-trust.json 信任文件只能增加明确公钥，不可替换已有 key ID 或放宽包内强制策略。后端没有配置公钥的独立校验路径须明确报告“签名未验证”，不能冒充 Nexus 强制验签。

签名 CI 使用 GUTHON_RELEASE_SIGNING_PRIVATE_KEY 与 GUTHON_RELEASE_SIGNING_KEY_ID，私钥与包内公钥不匹配、或强制策略所需密钥缺失时拒绝发行。签名覆盖应用、pyz、VSIX、Chrome 扩展和 Skill；scripts/verify_release.mjs 可用从可信渠道取得的公钥离线验收。首次安装仍需可信分发渠道，发行签名不等同于 macOS/Windows 系统代码签名，也不能证明程序无漏洞。

Gitee 镜像与 GitHub 发行独立同步：scripts/sync_release_to_gitee.py --tag <tag> 先验签，补传缺失附件，再逐项下载核验 hash；中断可按同一 tag 继续，不重建已发布资产。令牌保存于系统钥匙串；维护流程和备用工作流见 镜像同步说明，Windows 构建入口见 统一安装器构建说明。
