1. 产品定位与设计原则

1.1 功能边界

GuthonCodeTool 通过谷神项目 API 接入源码，在各项目独立的本地目录中编辑、检索并按需上传；Nexus 提供开发界面，Bridge 提供浏览器增强。数据库诊断和测试是独立能力，需要明确连接和目标身份。

本地保存、API 上传回读、平台编译发布与业务验证分别确认。当前源码分支仍在集成，运行入口和端到端效果以实际构建与验证为准。

1.2 核心设计选择

每个产品或项目使用明确的 workspaceKey 和独立的源码目录、索引、API 配置与基线。拉取按选择的子系统和数据源执行；本地编辑与远端变更冲突时保留内容并要求处理。操作结果不代替业务验收。

2. 运行架构

2.1 组件职责

CLI 和 ToolHost 解析同一工作区登记，按 API、SVN、DATABASE 能力执行；Nexus 负责项目配置、源码界面、编辑与状态，Bridge 负责受信任页面的定位与辅助，MCP 提供按工作区限定的本地查询和编辑。数据库诊断通过独立连接或 DBX 操作。

API 接入与范围

源码 API 登录要求谷神平台主版本至少为 2.0.0，日期版本不早于 202611101305；平台未返回可核验版本或低于门槛时报告 API_VERSION_UNSUPPORTED。实际可用操作还取决于平台提供的接口、账号权限及当前项目有效会话；本地已同步源码的查询和编辑不要求平台在线。

API 支持项目地址、账号登录及验证码；勾选“保存密码”后，Nexus 在本机扩展存储中加密保存登录信息，不写入工作区配置或系统钥匙串。保存范围由明确的 toolHome、workspaceKey 和平台地址共同确定。Nexus 使用 AES-256-GCM 加密，随机密钥与加密记录分别存放于扩展全局存储的 api-login/encryption.key 和 api-login/<scopehash>.json；密钥也在本机，须限制同一账号对这些文件的访问，不能将其视为可抵御同账号文件访问的保护。API 保存密码只供本地 Nexus 使用；独立 CLI/MCP 不自动读取这份凭据；独立 MCP 的受支持在线工具可委派到同一项目的 Nexus 登录会话，具体动作见 API MCP。本地源码查询与编辑能力保留。数据库凭据存储独立于 API 登录，不受此变更影响。旧系统钥匙串中的 API 登录记录不会被读取、迁移或删除；升级后需要手动登录一次并勾选保存密码。卡片通过平台核验登录状态；临时网络或队列故障显示待核验状态并禁用主操作。后端仅在内存中保留会话及登录协议使用的凭据摘要；Nexus 可解密已保存的登录信息并通过标准输入发起合并的恢复登录。恢复失败后停止重复自动尝试，直到用户明确重新登录。收到明确登录失效应答后，可恢复登录并重试已登记的只读请求；上传、签出及保存请求不会自动重放。未保存密码且后端重启后，需要重新登录。选择范围和共享数据源的处理见源码连接与范围。

项目平台和谷神登录服务分别建立连接。HTTPS 使用 Python 默认信任，附加已安装的 certifi 公共根证书，并校验证书链和主机名。发行后端内置该证书包，调试模式使用 Nexus 隔离环境中的依赖。手动登录和自动恢复遇到证书错误时均显示失败的服务，后端返回 API_TLS_CERTIFICATE_ERROR。

2.2 目录与调用链

<toolHome>/
├── config/                         # 本地配置
└── var/                            # IDE 打开的开发根，可自定义名称
    ├── workspace/
    │   └── <新 API 项目>/
    │       ├── checkout/           # 当前源码
    │       ├── context/            # 索引、基线和恢复记录
    │       ├── runtime/            # 日志和缓存
    │       └── docs/               # 项目文档
    └── nexus/                     # 本机工具状态

新增 SVN 和 DATABASE 项目的登记目录也在 workspace/ 下。使用默认布局的 SVN 项目签出到项目内的 checkout/，显式配置的 checkout 及旧分类项目沿用既有路径。DATABASE 的原文和工作副本分别位于 source/readonly/ 和 source/workcopy/；真实配置、凭据和业务源码不放入公开工具仓库。系统关联的数据源以及显式选择的共享数据源可能包含共享对象，应确认范围后拉取。

平台 PAGE 的 fileName 和 superFileName 支持以单个 / 开头的站点路径，映射到对应页面身份目录内；原始平台元数据保留，路径穿越、空段及重复文件映射仍会拒绝。

公开仓库与业务开发入口

工具源码和工作数据分别管理；在业务窗口使用明确的 toolHome、workspaceKey 与项目目录，不从目录名猜测目标。

3. 工作区与配置

3.1 稳定身份与配置

每个工作区使用稳定的 workspaceKey；Nexus 在登记时要求明确选择项目同步方式，统一配置 schema 3 支持 API、SVN 和 DATABASE。API schema 2 可继续登记 API 项目。未指定 ID 时生成 ws_ 加 UUID；CLI 也可指定 ID、目录、别名和 sourceMode，省略同步方式时沿用 API 默认值。旧分类 YAML 沿用原产品／项目 key。各工作区独立配置 API 地址、系统和数据源范围。checkout、基线和操作记录绑定平台身份；已有基线后更换平台地址需另建工作区或明确迁移。CodeBuddy 打开 var/ 根并由 Nexus 在当前窗口切换；Nexus 使用 context.workspaceState 按 toolHome 保存和恢复工作区 key；根窗口未选择时不猜测目标，失效 key 会清除，运行中的窗口各自保持选择，不写共享 ACTIVE。后端请求仍传明确 key。Codex 可打开具体项目目录并继承开发根的 AGENTS.md。

配置字段与故障隔离

新目录使用 schemaVersion: 3 的 config/guthon.json，包含 workspaces、sync、datasource、databaseTesting、apiWorkspaces 与 sourceTables；登记项明确 sourceMode。新增登记的 directory 保存为 workspace/<项目目录>。既有单级 directory 和显式 root 按原路径解析。已有 API schema 2 保持原版本和默认 API 语义，不在加载时升级。完整旧分类 YAML 可只读解析，保留 key、路径、有效模式及源码字段映射；setup 不为旧空间补建 Git 或改写目录。项目总览、当前卡片及源码入口按已解析的同步方式路由。配置格式可离线预览并显式升级至 schema 3。源码同步方式另行处理。新 API 工作区包含 checkout/、context/、runtime/ 和 docs/；兼容项目按登记和授权范围解析实际路径。context/ 中索引可重建，基线、冲突与回执需保留以便恢复；runtime/ 为日志和缓存，两者默认由根 Git 忽略。平台继承和只读保护根据对象元数据判断。var/ 是唯一 Git 根；首次初始化新空间时创建空 workspace/、rules/ 与 docs/；已有空间重跑 setup 保留原规范布局。团队规范优先使用已存在的 rules/，没有时沿用 docs/，解析摘要的 rulesDir 返回实际目录。共用参考继续放在根 docs/；工具生成的方言 API 参考缓存位于 nexus/api-reference/谷神方言API/，与团队管理的规范文件分开。根 AGENTS.md 非覆盖式生成。.gitignore 只更新受管块，并忽略 workspace/ 任意层级下的 checkout/、readonly/ 和 database/ 目录。共用 nexus/、tools/、.guthon/ 等运行目录继续遵循既有契约并由根忽略规则覆盖。API 登录信息由 Nexus 单独加密存储。旧 JSON schema 1 和不支持的版本明确报错；活动统一 JSON 与旧 YAML 并存时报告 CONFIG_AUTHORITY_CONFLICT，不混读或自动转换。局部配置错误通过 configErrors 返回，其他无冲突项目继续解析。公共摘要区分 providerCapabilities 配置声明、capabilities 当前可用入口与 executionReady；workspaceBinding 供核对同 key 的来源绑定变化。SVN/DATABASE 使用旧索引格式和本地就绪检查。各索引按工作区隔离。真实地址、密码和业务内容不应写入公开示例。

源码连接与范围

API、SVN 和 DATABASE 的范围选择只保存意向，手动“更新源码”才拉取、处理退出范围并更新索引。共享数据源仍被保留的子系统使用时，其共享源码继续留在有效范围内。

同步方式来源与范围缩小范围后的处理
API通过谷神开发平台登录。选择全部或指定子系统，自动纳入关联数据源。CLI 可显式配置额外数据源。公共文件及项目配置按项目设置纳入。发布和索引达到清理条件后，备份并移除与基线一致的退出范围文件。草稿、冲突、本地修改或未登记文件会阻止相关清理。详见API 拉取与合并。
SVN清单模式根据仓库 URL 枚举可读目录。Nexus 依配置或目录名称把同一数据源及关联子系统合并为一项。“公共源码”和“开发建议”可独立选择。由范围向导管理的项目检出新增范围，清理退出范围的干净工作副本，再更新索引。退出范围存在本地变更或未登记文件时保留原工作副本。专用授权清单和旧 sparse 布局沿用各自配置。
DATABASE通过只读 MySQL 或 PostgreSQL 连接读取谷神主库，按主库子系统与数据源身份确定范围。清理退出范围的只读源码、生成的导出和相应索引。用户 Workcopy 保留。

SVN 和 DATABASE 在统一配置下可从项目卡片登录，密码由系统凭据库保存。SVN 原有本地认证方式仍可用。DATABASE 新数据目录的 sourceTables 带标准谷神主库 PAGE、过程函数和系统脚本映射，重复初始化保留已有配置。自定义主库需配置相应映射。省略 sync.sync 时，增量同步使用 10 分钟回看窗口。

SVN 首次签出中断后，按同一授权清单重试会复用已完成的工作副本，清理遗留管理锁、续签未完成的副本并签出缺失项。发现本地源码修改或冲突时停止并保留现场。首次接入及重试入口见使用手册。

统一配置升级与恢复

在明确的本地数据目录中，用 configuration-upgrade plan 查看源文件、目标版本和保留的项目身份。关闭同一目录的其他写入入口后，执行 configuration-upgrade apply --offline --confirm <planId>。命令先核对预览和原文件摘要，再在 config/.configuration-upgrades/ 备份并发布统一配置。遇到 CONFIG_UPGRADE_PENDING 时运行 configuration-upgrade status，根据返回的事务 ID 执行 recover --offline --confirm <transactionId>。发布前恢复原文件，发布后以写入的统一配置完成登记。所有命令均使用已核对的 --home，动作参数放在 -- 后。

从原目录迁移项目文档

“当前项目 → … → 从原目录迁移”适用于重新登记后的 API、SVN 和 DATABASE 项目。选择同一本地数据目录下 backup/workspace/<原项目>，Nexus 使用当前项目已登记的文档路径，仅复制 docs/ 下的普通文件与目录，保留原文件内容、相对路径及空目录。备份原件保留在原处。源码、版本库、配置和索引由新项目各自建立。若目标存在同名同内容文件则跳过，遇到同名不同内容、文件与目录重名、符号链接或特殊文件时，在复制前停止。复制因磁盘或权限错误中断后，可处理问题并重新执行。操作步骤见重新登记项目并迁移文档。

SVN 切换 API 的命令和核对范围

源项目须登记在 schema 3 下。svn-api-migration 按 --home 和 --workspace 选择唯一项目；preflight 检查授权 working copy、仓库身份、本地状态和未解决的交付记录。操作者提交谷神平台最终生效依据，并在切换前确认所有旧写入入口离线。目标平台与项目依照已配置的来源地址（如有）、系统 ID、数据源 ID 及关联核对。

动作输入与结果
prepare标准输入 JSON 的 serverUrl、platformEvidence 与 login（userId、password、可选 randCode）。读取 API 候选，建立独立基线和索引，返回缺项、歧义或可审阅计划。凭据仅用于本次认证。
plan读取当前可审阅计划。对象按类型、所有者和稳定 ID 核对，继承来源独立检查；字节相同与需人工比较的对象分别列出。API 额外对象单列。缺项、歧义、读取或索引失败会阻断。
apply --offline --confirm <planId>标准输入 JSON 提供 login 和 manualReview，后者按待核对的 SVN 相对路径填写依据。再次检查旧侧状态、候选和平台范围及正文摘要。以原子更新当前登记作为切换点，保留原 key、项目根、文档、旧 SVN 工作副本和上下文。新源码进入项目根 checkout/，新基线和索引另存于 context/api-provider/。
status / recover --offline --confirm <transactionId>根据实际登记判断中断状态。发布前恢复候选位置，发布后确认现有 API 登记。备份与核对记录保存在 config/.svn-api-migrations/。旧 SVN 写入绑定在重新核验时失效。

自动核对覆盖可映射的受管对象及字节摘要。跨格式正文、旧平台最终提交、运行时效果和业务结果各自依据实际证据。DATABASE 项目仍按原模式接入；执行步骤见使用手册。

3.2 创建、切换与删除

添加项目。可复用开发根下尚未登记的同名目录 workspace/<项目目录>。登记按所选同步方式补齐所需目录，保留已有的 docs/ 和其他自管文件。项目根和已有 docs/ 须为实际目录。checkout/、context/、runtime/、source/ 或 database/ 等受管路径已有文件、链接或类型冲突时会阻止新登记，以免把同步数据绑定到新的 workspaceKey。操作见添加项目并登录。

删除工作区。统一配置下，项目总览的 API、SVN、DATABASE 项目共用删除入口。预览由稳定 key 绑定登记及目标路径。确认并完成未保存内容检查后，仍存在的项目目录先移入系统废纸篓，随后移除登记。目录缺失时可直接移除登记，若预览后目录重新出现则须重新确认范围。目录外单独配置的源码、文档和运行路径列入保留清单。删除当前项目会清空当前项目和源码视图，删除其他项目保留当前选择。

修改同步方式。没有源码、索引、操作历史或未保存草稿的项目，可在项目设置中切换，同步连接或待应用范围本身不阻止切换。已有源码或索引的 SVN、DATABASE 项目转为 API 时，Nexus 预览实际清理目录并要求确认平台改动已同步。清理包括旧 checkout 或 DATABASE 源码副本、索引与运行目录。它保留原 workspaceKey、项目目录和 docs/，API 连接及范围需重新设置。

旧框架默认的外置 SVN checkout 按项目 ID 清理，自定义外部路径及共享目录不纳入自动清理。登记发布失败时尝试恢复原目录；发布后送入废纸篓失败时保留暂存目录并显示位置。需要保留旧 SVN 工作副本及交付历史时，使用对照迁移。操作入口见迁移与删除步骤。

3.3 命令与运行描述

CLI 与 runtime descriptor 参考

执行“设置/切换工作空间”时，先确定本地数据目录，再确认该目录的后端入口。用户设置中的数据目录只用于打开该数据目录、所属开发根或开发子目录的窗口；工作区的显式连接优先。无关联的窗口显示初始化或连接入口。选择已绑定的开发根时，Nexus 按上一级配置核对归属并连接原数据目录。已保存的数据目录若指向该开发根，需重新连接，成功后运行描述写入原开发根的 nexus/。首次从当前开发目录初始化时，数据目录固定为其上一级。首次初始化可复用在当前工作区选定的运行入口。未选定时，Nexus 会优先识别上一级的发行应用。未找到后端时可以明确选择运行方式和入口。打开工作区时切换运行方式，Nexus 把所选模式和入口保存到当前工作区的设置层级，并用同一入口更新运行描述。项目列表读取失败时仍可打开运行方式选择。新配置通过 workspaceDirectory 记录开发目录名称，缺省为 var。目录、入口选择及执行确认阶段只准备选择结果；取消或目标目录读取失败保留原运行入口与目录配置，初始化或读取成功后才保存。“刷新当前状态”和窗口内工作区切换继续使用已配置入口。

使用 api <action> --stdin 传递结构化输入，CLI 与 ToolHost 共用工作区身份。动作包括配置、登录、拉取、定向刷新、状态、目录、读取、编辑、差异、冲突处理、上传、回读核对、索引和查询；完整参数以当前命令帮助为准。api pull --stdin 输入 {"checkOnly":true} 可只读下载并检查当前范围，不发布源码、不重建索引、不改变范围或拉取状态。凭据通过标准输入传递，不放入命令参数。

Nexus 刷新状态时只请求完整范围的汇总和非干净文件清单，避免大项目状态超出传输预算；api status 默认仍返回完整文件列表，changesOnly: true 可仅返回变更项及 summary 计数。状态刷新使用可重建的文件指纹/哈希缓存，仅重新读取发生变化的正文；每次仍检查范围、只读、冲突与删除状态。上传和受控写入保留原有实时校验。卡片先显示轻量项目信息，再异步恢复已保存的登录；平台认证不阻塞本地源码打开、检索或配置向导。自动恢复失败后不再重复尝试，需在卡片手动登录。登录完成后立即显示会话，源码状态在后台刷新；同项目并发刷新与会话恢复合并处理。文件事件先核对登记路径，排除配置/临时文件；无变化的重复索引事件不复制整个索引或改变代次。API 元数据与原文摘要匹配的极简 PAGE、无 SQL 视图会被识别为元数据型源码，不作为格式失败，也不生成不存在的结构或 SQL 事实。真正的身份冲突或无法解析内容保留原文与诊断，其他可解析对象继续处理。重新打开窗口后，可直接从源码树查看已保存的目录诊断，无需再次重建整个索引。

运行描述使用显式 toolHome 和命令数组；发行、源码及调试模式的入口不同。实际能力以当前安装版本为准。

4. 数据库诊断与测试

4.1 只读数据库排查

工具可按工作区、开发/测试环境和私有目标配置解析数据库连接，支持 MySQL、PostgreSQL 与 Oracle。查询必须核对 database/schema 和实际可见表；正式测试计划另有声明的验证范围。密码默认写入系统凭据库，配置只保存连接引用。

  • database-probe：验证驱动、连接和只读能力。
  • database-describe：核对目标 database/schema 后读取可见表结构，避免猜测字段；快速排查不以静态表列表代替目标身份和实际可见性验证。
  • database-query-readonly：只接受单条 SELECT，限制返回行数并始终回滚事务。
  • 可选 DBX 连接只在配置了 connectionId 时使用；缺失绑定会明确报告，不自动猜测其他连接。

diagnose 还提供配置驱动的源码逻辑排查：它只允许显式标记为测试、启用只读诊断并声明数据库白名单的数据源，按模板逐步执行绑定参数的单条 SELECT，在首个不满足条件的位置停止并生成本地排查报告。该能力适合重复执行的固定检查链；临时问题则使用目标解析、结构描述和有界查询逐步取证。

数据库快速排查从当前工作区和开发/测试环境解析明确目标；未指定环境时使用配置中的诊断默认目标，而“测试一下”只是连接探测，不代表已切换到测试库。功能验收、回归和交付应使用正式测试目标与测试计划/结果证据，不能把一次只读查询当作完整验证。可选的 Guthon Testing Skill 提供该工作流指导，其安装与数据库连接配置是两个独立步骤。

Nexus 的“配置数据库只读目标”区分快速排查与正式只读验证。正式目标向导收集系统、数据源、租户字段及范围/身份核验证据，不要求表名单；更新已有目标时不重写旧表名提示字段。Oracle 登录 schema 与业务 schema 分别核验；生成 DBX 交接文件只说明交接信息已准备，不能作为查询已执行的证据。

“查看最近诊断历史”读取已有记录，不重新执行查询。查询可导出 CSV 或带证据页的 XLSX，结果与目标、SQL、执行时点一并保存到当前私有工作区。

这些限制使数据库能力适合诊断和验证，而不会把开发工具变成任意 SQL 执行器。查询命中只证明数据库证据，不等同于页面结果或已部署版本验证。

目标、凭据与适配器

database-target-list 列出工作区目标；database-connect-test 测试明确环境的连接，database-probe 核验目标身份和只读能力；database-target-resolve 及 runtime descriptor 按 cwd 和环境解析默认目标：未指定环境用 defaults.diagnosisTargetId，明确开发/测试环境用 defaults.byEnvironment.dev/test。显式 --workspace 优先于 --path。database-target-configure 可更新已有目标的密码或属性；database-target-remove --check 先预览，正式移除确认精确 target ID，只清理不再被引用的连接和凭据。

有 connectionRef 时优先用内置只读连接器；仅有 connectionId 时使用当前实际可用的 DBX。database-dbx-import 只导入有来源说明的公开连接元数据，database-dbx-handoff 生成先核身份的调用交接，不读取 DBX 密码或伪装查询已执行。--profile 可选择已有目标配置。

密码默认保存在 keyring；维护者可显式配置 passwordEnv 环境变量或 passwordFile 绝对路径密码文件。更换来源不会自动删除旧 keyring 记录。database-credentials-export/import 要求明确工作区、已注册凭据引用和确认，使用 AES-GCM 加密迁移，不把解密明文落盘；加密文件也应保存在私有位置。

查询、输出与诊断历史

database-diagnose 默认只探测身份；提供 --sql、--sql-file 或 --stdin 才执行查询。快速排查使用 database-*，固定源码诊断案例使用 diagnose。内置查询只接受经验证的单条 SELECT，最多返回 100 行，并回滚只读事务。

SQL 校验支持普通字符串中的邮箱、分号和井号、SELECT CTE 及对应引擎的允许函数/类型，包括 Oracle/MySQL 的 INSTR 字符串定位；拒绝跨库、未知副作用函数、注释、引用标识符和不支持的转义。Oracle 替代引号、PostgreSQL dollar-quote、嵌套 WITH 与反斜线字面量仍不支持，复杂值应使用绑定参数。MySQL/PostgreSQL 可用 --explain 读取有界估计计划，不执行 ANALYZE，返回 queryExecuted=false；Oracle 因需计划表写入而拒绝该操作。估计计划返回完整 JSON，不按普通业务单元格长度截断；行上限仍保留，普通查询的单元格与行数截断规则不变。

查询结果保留行列截断位置；CSV/表格输出还在 stderr 提示截断。--format xlsx --output <私有文件.xlsx> 生成“结果”和“证据”两页，字符串按文本保存、长整数保留精度；空列名或重复列名明确拒绝。连接探测和 DBX 交接不生成伪空结果。导出摘要最多保留最近 100 条。

database-history-list/show 提供脱敏查询历史，database-compare 提供目标间计数对比，diagnosis-template 生成查询模板；计数不同不直接代表功能错误。描述缓存绑定完整目标摘要、TTL 及 probe 失效 epoch。diagnosis-list/show 供 Nexus 查看最近最多 100 条诊断摘要或精确详情，不读取 SQL、参数或结果行，也不重新运行查询。固定案例报告默认隐藏绑定参数，只有明确 --include-params 才写入原文；报告位于私有 var/docs/业务排查文档/，模板见公开的 source-diagnosis 示例。

正式只读验证计划

database-test-artifacts 提供 validate-config、init-plan、run-readonly、export-dbx-plan 和 import-dbx-results 等子命令。正式目标和计划需声明系统、数据源与租户证据，计划 SQL 按实际源码和业务键限定范围。allowedTables 是兼容旧配置的可选表名提示，用于生成计划草案，不作为查询授权名单。配置与 SQL 仍须满足已核验目标的 database/schema，内置查询对每个物理表核验实际可见元数据；DBX 交接由调用方先核验身份和表结构。静态工件校验不能代替真实身份、业务用户行权限或 WHERE 业务语义核验。执行器先核身份，前置条件失败或结果截断时停止相应用例；平台结果用例还需与源码和目标绑定的版本及触发证据。内置连接可执行只读计划，DBX-only 目标通过交接、结果导入和本地 evaluate 完成证据处理。

bash
.venv/bin/python scripts/guthon_tool.py database-test-artifacts --home /absolute/toolHome -- \
  run-readonly /absolute/private/plan.json \
  --config /absolute/toolHome/config/guthon.json \
  --out-dir /absolute/private/new-run

每次运行使用新的私有目录，保存结果和报告，不覆盖旧运行；执行器不发布、不触发平台或清理数据。diagnose case.json --dry-run 只做未绑定 SQL 的静态校验，不连接也不写报告。模板的 --case-out 产生不能直接执行的案例草稿，并保留调用方的 --max-rows。

5. API 源码与本地编辑

5.1 拉取与合并

普通更新按共同基线、本地已保存源码和本次平台源码做行级三方合并。以基线中的实际文本行区间判断是否重叠。同一源码表示下可合并的非重叠修改会自动保留，重叠修改或表示不兼容时保留本地内容并报告冲突。PAGE 可读差异中的解析结果供审阅，合并仍使用实际源码文本。定向更新只处理指定对象或节点，身份不唯一时提示核对。

全量更新按已生效范围拉取，或先应用已保存的待更新范围。后者在下载前检查将退出范围的内容，下载后再次核对配置及文件，再发布源码、建立索引并清理与基线一致的退出文件。清理前会保留备份。报告分别记录范围设置、源码发布、索引诊断及清理结果。发布阶段中断可能留下部分结果，可按操作记录核对后再处理。

已建立基线且范围一致时，全量更新仍获取完整远端清单。若源码、基线、对象元数据和只读状态一致，且没有待处理冲突，该文件直接计入保留项。现有索引与当前源码和目录核对一致时复用索引，少量差异按路径更新。首次拉取、范围变更、索引不兼容或差异较多时执行全量重建。

更新源码等 API 操作会在 GuthonCodeTool 输出中记录耗时、运行方式和后端版本。按已生效范围全量拉取时，分段记录更新前状态检查、远端下载、本地源码更新、索引和源代码管理刷新的耗时。本地源码更新进度按批次显示已处理文件数，涵盖更新、保留和发现冲突的文件。中断后可从操作记录核对已处理文件和中断位置。平台请求失败时保留已知接口路径、错误码和可用的系统错误类型。同步部分完成时记录已知阶段和错误码。索引问题最多输出 10 项相对路径和错误码，完整诊断见操作结果。项目状态扫描失败独立记录，文件信息不一致时列出相对路径和差异字段。

API 全量拉取、应用同步范围和定向刷新中的每次平台 HTTP 请求，默认超时为 300 秒。PAGE 批量拉取按子系统请求首批页面，以只读的 PAGE 下载表示建立索引。编辑结构化 PAGE 时按页取得原生模型，已有匹配版本的原生基线可复用。只有占位元数据的继承页面作为只读目录项收录；下载正文身份不匹配时保留原文并报告诊断。可检索范围见工作区事实索引。

API 工作区本地变更包 CLI

api export-changes --stdin 将当前项目范围内已登记、可写且有本地修改的对象导出为 JSON；请求必须给出 checkout 之外、尚不存在的绝对 output 路径，可选 paths 数组按源码相对路径筛选。不提供 paths 时导出当前范围内符合条件的对象。筛选是交集，返回的 fileCount 需与预期对象清单核对；没有可导出对象时报错。

变更包顶层包含 schemaVersion: 1、workspaceKey 和 files；每个对象包含 path、metadata、baseContent、localContent、baseHash 和 localHash。身份字段按对象类型包括 sourceType、pageId、systemId、procedureId、funId、dataSourceId、tableId、viewId、scriptType；正文摘要按 UTF-8 计算 SHA-256。正文可能包含私有源码，应保存在受控私有位置。导出只读取当前 API 工作区，不自动上传或修改原工作区。

api import-changes --stdin 接收绝对 input 路径，默认预览；输入文件不超过 64 MB，包内包含 1 至 200 个对象；超过导入上限时，应在导出前用 paths 分批选择并逐批核对。先在目标项目完成 API 范围配置与拉取，并确保目标是同一 workspaceKey 下已登记的可写对象。导入按包内相对路径读取当前已登记对象，再核对身份和正文摘要；不会仅凭身份自动匹配不同路径。预览按变更包的基线、本地修改与目标当前文件生成三方合并，返回 planHash、changes、conflicts 和 complete；changes 仅含路径和前后摘要，不包含合并后的正文或文本差异，因此预览不能直接审阅合并正文。预览不写源码。

审阅完整对象清单和无冲突结果后，使用相同输入文件、apply: true 和该次 planHash 应用。输入或目标状态发生变化时必须重新预览；存在冲突不能应用。应用前还会检查编辑器状态与文件哈希，随后逐项写入当前 checkout 并更新索引；它不会自动上传。中途中断、写入或后续索引更新失败时先检查操作记录与实际文件，核对已应用范围，再处理索引；不假定批次自动回滚或盲目重试。

bash
# 使用私有绝对路径；按实际项目替换 workspaceKey。
printf '%s' '{"output":"/absolute/private/changes.json"}' | .venv/bin/python scripts/guthon_tool.py api --home "$GUTHON_HOME" --workspace ws_demo -- export-changes --stdin
printf '%s' '{"input":"/absolute/private/changes.json"}' | .venv/bin/python scripts/guthon_tool.py api --home "$GUTHON_HOME" --workspace ws_demo -- import-changes --stdin
# 审阅预览并确认无冲突后，将下方占位符替换为本次返回的 planHash。
printf '%s' '{"input":"/absolute/private/changes.json","apply":true,"planHash":"<planHash>"}' | .venv/bin/python scripts/guthon_tool.py api --home "$GUTHON_HOME" --workspace ws_demo -- import-changes --stdin

变更包用于符合上述身份和路径契约的 API 工作区本地修改。已有 SVN 项目先在原侧完成交付，再按SVN 切换 API 参考核对并切换同一个项目。

源码资料与单据类型导出

export-schema、export-view 和 export-system-script 使用当前 API checkout 的已获取资料，输出到独立导出目录，导出结果不作为可上传源码。单据类型提供官方只读索引资料，完整定义的导出仍使用数据库连接；export-bill-type 使用单独配置的数据库连接，先核对目标和数据源范围。

操作记录与交付追溯

API 工作区保存本地同步、上传等操作记录及回执，可按操作编号检查结果并在支持的情形下只读回读恢复。它们依赖当前本地数据目录与工作区，记录从工具实际操作开始；它们不是平台全量版本历史，也不提供 SVN 全局 revision 的连续编号、跨对象提交集合或按历史 revision 重建、比较和交付的同等能力。变更包是本地修改的传递材料，不是平台提交或版本发布记录。需要追溯旧 SVN revision、确定交付范围或核验最终签入、编译与发布时，应结合原 SVN 记录、平台记录及实际交付证据核对。

5.2 上传、冲突与回执

上传审阅清单显示业务名称、类型、路径和状态，可逐项勾选及打开差异。确认后只发送所选文件；审阅期间文件内容改变时要求重新核对，取消不上传。结果继续按文件记录已回读、失败、未执行与未知状态。

上传前重新读取平台对象并预合并，检查身份和本地状态；确认后逐项上传并回读。结构化 PAGE（非服务组件 GSS）以原生编辑接口的 bean/version 为依据，保持现有 XML 路径和单一可编辑文件；本地 XML 是原生模型的无损表示，保存时解码为 JSON，使用带 pageVersion 的原生保存接口，并关闭自动编译，不回写下载接口的 XML。已核验的原生基线只在项目、对象路径与版本一致时复用。旧基线只有与当前原生模型一致才可升级；导出表示不同、无法无损表示或版本缺失时明确报告，不猜造身份、继承层或版本。原生元数据尚无源码版本的对象仅供查看。保存前核对原生签出归属，不强制覆盖他人签出。PAGE 回读独立读取原生模型，核对版本、非空脚本、控件身份和有效配置；只允许已知默认值与空配置的规范化，包括数据源字段及主键定义省略零小数精度，以及查询区文本字段、主表文本列和日期时间列的已知默认开关、未配置的选择框和派生类型。非零精度、控件身份、已配置选择框、非空脚本以及页面缩放等同名属性仍严格核对，不按关键词删除产品代码包装。其他源码沿用逐类型接口，应答和独立回读须一致。平台规范正文同步回同一 checkout，提交后的本地修改继续合并保留，重叠变化进入冲突处理。回执保存提交、原生接受版本及回读摘要；更新源码时，若当前同步范围内的 PAGE 曾收到保存版本但仍待核对，Nexus 会核对该版本与原提交模型。核对一致后，以已提交源码为共同基线合并现有本地文件并更新原回执。应答丢失时只读核对，不重发保存。回执可表示部分完成、失败或结果未知，未知时先查原操作和平台状态，不重复提交。上传回读与平台最终提交、编译、发布及业务结果是不同阶段。

表与视图支持明确确认后的平台结构同步，会执行 DDL；需核对数值身份和已上传状态，再独立验证数据库结果。过程函数可从已有过程包右键创建，使用官方新建接口分配平台对象后回读到本地；不能把未登记的任意本地文件当作新函数直接上传。创建需要明确包、数据源、函数编码与中文名称，并确认本次平台写入。

项目源码的文件右键与源代码管理使用同一套 API 冲突处理。比较窗口展示本地已保存内容和本次同步记录的平台内容。结构化 PAGE 优先按字段、SQL 和脚本生成可读差异，并使用上传回读的等价规则识别已核实的默认值。可切换到原文，解析失败时显示原始源码。确认使用两侧原文的版本校验，将平台版本设为新的本地比较基线，并按选择更新本地文件。继承只读文件只允许恢复平台原文。冲突记录来自批量下载 XML 时，处理入口会定向获取该页的原生源码，并重新判断冲突。处理只影响本地，上传需另行执行。操作见使用手册。

API 源代码管理暂存与上传

存储库以项目名称标识。文件按源码树中的业务分组组织，PAGE 优先使用页面名称，服务组件和过程函数优先使用其编码，其他类型保留文件名。查看差异、还原和上传使用工作区内的原始路径，可通过“查看原始路径”核对。

暂存区在当前 Nexus 会话中按项目记录已保存的源码版本，支持可上传的页面、过程函数、表、视图和系统脚本。分组操作只处理当前项目该组内符合条件的文件。还原在确认后恢复到本地同步基线。源代码管理支持按暂存或未暂存范围确认上传，单次上限为 200 个文件。未暂存范围只包括当前项目中已保存且可上传的本地修改。确认后重新核对文件和暂存状态。暂存后文件内容有变化时需重新暂存。已确认完成的文件退出暂存区，失败、未执行或待回读的本地修改仍可核对。模块参数使用独立的预览上传入口。

源代码管理中的上传备注随操作回执保存在当前项目的本地操作记录。谷神平台的最终提交沿用平台流程。操作步骤见使用手册。

5.3 PAGE 本地与在线编辑

源码树的“编辑页面”默认打开 Nexus 本地页面编辑器，提供字段和代码编辑；全量、子系统范围和目录同步使用官方分页下载的 PAGE XML，复用版本匹配的已核验原生基线。其余结构化 PAGE 的下载 XML 可只读查看。需要原生模型时，通过“编辑页面”或“更新指定 API 源码”只更新所选页面。取得可核验的原生基线后，可继续离线编辑。本地编辑器保留草稿撤销、恢复和比较能力。服务组件、仅含最简元数据或不支持设计的对象使用源码入口。

页面编辑范围

本地页面编辑器的“在线编辑器”打开当前 API 项目的官方在线设计器 iframe；需要登录当前 API 项目并能访问平台，无需下载、导入或配置设计器资源缓存。存在未保存的本地草稿时，须先成功保存到本地，才能打开在线编辑器；保存失败时保留输入并处理原因。官方设计器的字段、按钮、属性、事件和布局等可编辑范围由当前平台决定，返回的修改写入同一 checkout 文件。代码分块与字段集合 JSON 继续使用独立的源码编辑入口。

原生“重新打开方式”和资源管理器右键入口通过已登记项目及后端对象身份解析 PAGE，服务组件、只读或不支持的对象使用原文入口。原生编辑器与源码树入口复用同一页面会话、草稿和恢复记录，不创建第二套可上传源码。

保存、比较与冲突

保存前核对页面身份、文件版本、原文哈希和其他未保存输入；原生 XML 由后端校验，继承文件保持只读。保存后独立回读本地文件，源码管理显示与平台基线的差异。来源变化或保存结果未知时保留当前编辑，先核对文件与原操作，不直接重放保存。本地编辑器和在线编辑器的保存都只更新本地源码，上传仍需单独执行。官方消息未提供编辑中脏状态，在线窗口打开期间保留编辑登记；确认保存完成且没有后续修改后，关闭设计器再上传。

设计器连接

在线编辑器通过当前 API 项目的登录会话加载官方设计器并交换文档。首次连接、平台显示和实际保存应分别核验；本地编辑不依赖此连接。

限制

设计器未识别的格式或控件不能推定为支持；平台资源加载、Nexus 本地保存、上传回读和平台业务结果分别验证。项目过程函数的继承展开编辑继续核对父层来源及哈希，父层文件保持只读。

6. 索引与 AI 上下文

6.1 工作区事实索引

项目在其上下文目录的 index.db 保存已同步源码的对象、PAGE 节点、静态调用等可识别事实。查询受当前范围与结果分页限制。动态行为和业务执行结果以源码与平台核验为准。索引范围与平台或当前授权范围不一致时，API 拒绝使用旧索引。

  • 重建索引按当前已同步的全部本地源码重新解析。索引缺失、结构不兼容或范围过期时使用。
  • 修复索引是 API 索引诊断行的增量入口。它从当前索引找出未完成的记录，仅重新解析对应本地源码。正常记录保留，仍有问题的对象继续显示诊断，其他已完成的对象仍可检索。
  • 重试待更新文件处理文件监听检测到的待更新项，与解析诊断分别维护。已被当前索引覆盖的文件会跳过。

上述操作使用本地源码。“更新源码”才从对应来源读取文件。

索引空间

索引可重建；清理或重建前核对工作区并保留源码和基线。索引结果不代表平台或业务执行结果。

6.2 检索与有界上下文

有界查询入口

API 提供 catalog、search、context、callers、facts 和 explain；MCP 对同一工作区提供查询。读取时检查路径、源码哈希、覆盖范围与分页，不把未检出对象视为不存在。Nexus 的 API 源码搜索按需加载后续结果，每页最多 100 条；翻页期间索引变化时需重新搜索。后端仅在当前结果页生成命中摘要。

API、SVN 清单模式和 DATABASE 的 Nexus 源码搜索弹窗支持按类型检索。可选类型随同步方式变化。本地索引先匹配关键词和类型，再应用当前查询的结果上限。操作见当前项目卡片。

源码树复用类别图标与主题色。默认按本项目数据源 ID 排列分组，无法关联数据源的子系统排在后面。各组保留菜单、模块或对象顺序，也可设置按名称排序。名称与编码分开显示，页面节点可直接打开编辑器，展开箭头用于浏览解析后的子项。API 的继承页面、过程函数和系统脚本在树中显示项目侧条目，产品层源码通过继承入口只读查看。

模块参数编辑与受控上传

模块参数以系统编码和参数编码共同标识。同步时每个选中子系统调用一次 getConfigs 获取列表，汇总到一个只读的 otherconfig/module-parameters.json，不逐项预拉详情；条目数与生成的物理文件数分别统计。清单支持按身份、名称等列表信息查找，不能当作完整参数正文。需要加载具体条目详情时请求一次，写入原有 systems/<sid>/module-parameters/<id>.json 缓存，并通过既有基线和冲突保护保留本地修改。详情保留接口实际返回的完整 JSON，不将模板默认值和项目值合并，也不补齐缺失节点。源码树、搜索和定位共用当前项目索引；默认打开可编辑的 data JSON，完整接口原文仍只读。模板、对象身份、版本元数据及其他根节点不可通过参数编辑修改。

本地编辑共用文档租约、原文件哈希、预览与幂等保存记录；保存只替换同一快照的 data 节点，其他原文保留。本地保存不会修改平台。差异预览对比平台基线与当前编辑输入；源代码管理可比较已保存的本地修改。旧只读快照在明确打开编辑时升级本地编辑能力，保留内容、基线和已有修改。

模块参数上传使用独立预览计划，绑定明确路径、本地哈希、平台数据与模板版本、当前用户及签出者。确认提示提供按需查看这份计划的差异。用户确认后再次核对；必要时按原生接口普通签出，核实属于当前用户后保存 data，并独立回读核对。其他用户已签出的对象拒绝上传，不使用 force，也不自动签入或撤销签出。源码与模块参数同时有修改时先选择本次上传范围。平台最终签入仍从原生平台完成。

每次保存请求前持久化提交快照和阶段；超时或未知结果不重发。未确认操作阻止同一参数的新上传计划，核对原操作只读取平台状态；仅签出而未保存时也不会自动续传。平台已确认保存但本地同步冲突时，分别保留平台结果与本地输入，不能把本地失败当作平台没有保存。预览和结果不等同配置业务效果验收。

普通更新源码会同步模块参数，也可在“源码工具”或分类右键单独同步。独立同步更新该类型的汇总清单；详情按需加载，已有详情和本地修改按源码发布及冲突保护处理，不删除其他类型源码。编辑和上传均不执行数据库结构同步。

“源码工具 → 同步官方参考资料”独立请求官方配置与技能资料接口，登记匹配的本地文件；与平台版本不同的已有文件保留原文，按有来源标记的本地快照索引并报告，不重新拉取业务源码。平台参考使用当前工作区已登记的 skills/platform-kit/apis/，用于 API 补全、悬停、页面属性说明及参考阅读，并通过 read_platform_reference 提供按需读取。API 查询支持分页；事件继承组读取对应基组。上游清单引用的缺失文件显式列出，工程目录和文件后缀约定不覆盖本项目规则；结构字典和事件资料不作为未经平台核验的严格保存校验器。资料按索引代次更新，原文件保持只读。

SVN 工作副本管理锁会在源代码管理显示。点击锁提示可对该授权工作副本执行 svn cleanup，保留本地修改。远端有更新时继续进入预览与确认。

SVN 本地差异左侧为 SVN BASE，右侧为已保存的工作副本。远程变更比较的左侧为工作副本，右侧为 SVN HEAD。两侧均为只读快照。PAGE JSON 的可读差异将脚本和 SQL 展开为多行，并保留字段、按钮及其他页面定义供核对。可读视图无法生成时显示两侧原文，也可从本地变更的右键菜单选择“查看 SVN 原始差异”。提交和撤回根据入口限定到单文件、子系统工作副本或当前 SVN 项目。提交确认显示本次所选路径，点击源代码管理中的变更文件可查看差异。后端预览列出符合条件的修改和阻断项，执行前重新校验所选文件。子系统更新只检查该分组的 SVN 工作副本。

7.2 语言与导航

源码名称由下载元数据统一派生：表中文名、视图中文名及系统脚本用途说明进入索引、搜索、源码树与上传审阅；旧平台缺少描述时保留对象编码，不改变路径和身份。源码树过滤仅改变展示，原生资源管理器复用同一源码状态和目录汇总。

继承调用导航复用父层路径及哈希核验，仅打开只读父层；展开后的产品段提供来源入口。API、SVN 和 DATABASE 的定义跳转按源文档所属项目查询本地索引，以过程别名和函数 ID 匹配静态调用。支持 invoke、invokeWithGlobalTrans、线程调用（含 runFutureTaskWithGlobalTrans）及能从 proc.find 绑定中确定目标的调用。动态参数及本地索引中未找到的目标不显示定义链接。DATABASE 的可编辑目标使用原有 Workcopy 编辑入口。本地函数悬停只读取紧邻声明的注释。

GSS、JavaScript 和 SQL 的补全、悬停及定位结合官方语言资源和 Nexus 快捷输入。内置 API 与当前项目参考由同一补全入口合并，按完整 API 路径与参数签名去重，保留不同参数的重载及快捷前缀；无法确定类型对应关系的旧模板保持独立。PAGE 与过程函数可按精确身份定位；浏览器相关能力需要配对 Bridge。

视图 SQL 编辑

打开视图默认显示 SQL 虚拟文档，使用 SQL 语言服务、定位和行内差异。保存前核对视图编码、原文件哈希、租约和候选，只修改原文件的 /viewSql，其余 XML 或 JSON 原文保留；不会生成另一套可上传 SQL 文件。缺少 SQL 节点的官方视图默认展示原始 XML，不生成空 SQL；需要显式编辑完整定义时使用原始源码入口，并校验当前对象身份。真正的继承文件或身份冲突继续只读。保存只更新本地 checkout，上传与结构同步仍是独立操作。

7.3 工具更新

工具、Nexus 和 Bridge 按各自更新流程核验并生效。官方语言能力更新从 Open VSX 检查资源，临时编辑器比较更新日志、命令、编辑器声明、语言资源、可识别接口与最低平台版本，区分已有对应入口、待适配核验、无需采用及实际生效状态。命令对应不证明协议或实机验收；未知功能变化需随 Nexus 适配发布。报告分别列出 API 签名新增、移除和文档变化；该入口仅替换经验证的资源，不安装官方扩展或替换后端协议。下载、启用和实际生效分别确认。应用更新与回退使用互斥锁；仅当锁记录包含合法进程号且系统明确报告该进程不存在时，才尝试恢复遗留锁。进程仍存活、无权确认（EPERM）或锁记录损坏、未知时保留锁，不按锁龄抢占。

8. Guthon Bridge

Bridge 提供浏览器定位、网页增强及少数依赖已登录平台页签的操作。API 和 SVN 读取整页上下文以及准备或执行整页新建、复制、删除时，需要当前工作区的已登录页签。查询原回执需要连接原 Bridge 服务。缺少服务、配对或页签时，提示会说明当前动作。源码同步、本地编辑及静态检查由当前源码方式和本地工具处理。日常“环境检查”检查当前工作区的本地开发依赖。维护者可使用 doctor --bridge-port <端口> 显式探测本机服务，服务不可用时该项标为跳过，整体状态仍由开发依赖检查决定。

原生元数据维护接口 /nativeMetadata 绑定配对平台、工作区、数据源及精确字段，支持只读检查，以及将现有非空 BIGINT 主键的生成方式设为平台 GUID（isIncrement=2）。写入前要求字段快照一致，保存后以原生 API 回读。表字段修正后，可检查指定页面的同一主键投影，冻结页面版本与摘要，再仅补齐 GUID 标记并通过原生保存启用自动编译；保存后回读整页核对预期修改。页面版本漂移或系统身份不符时拒绝派发。同一请求不重复派发，结果未知时只检查原字段或页面。不修改字段类型、数据库自增或默认值，不执行建表、SQL或任意过程，也不写本地 tables/ 只读副本。只读运行入口检查仅返回同源静态脚本路径，不导出平台会话凭据。另有显式授权的 save-native-record 单表新增动作：绑定页面、父主页、保存按钮与源码版本，先只读预检，再带原生页面和菜单请求头保存并独立主键回读，候选与身份沿平台会话核验；不接受明细网格、更新、任意服务、SQL或调用者指定的主键、身份、时间戳。既有保存按钮的钩子发布支持原节点修改及明确缺失节点的新增，要求调用前完成 SVN MCP 源码租约、预览、更新及差异回读，携带源码操作标识；再以原生版本和原脚本文本比对，仅替换该钩子并自动编译、整页回读。该接口不执行任意测试脚本、不提交 SVN、不整页覆盖本地版本。显式配置的私有静态步骤清单可冻结有限的原生服务调用，绑定开发环境、工作区、来源、组件、父页、版本及全部参数；调用者只选步骤名，不能指定 URL、别名或参数。执行沿原生权限与业务服务；已声明的页面查询只读调用精确原生表格和搜索控件，不执行 SQL 或任意测试脚本，不自动重放未知请求。显式配置的 GUTHON_NATIVE_SOURCE_PLAN_FILE 可冻结开发函数的原生创建、参数和源码保存、MCP登记及隐藏保存字段追加；HTTP请求只选择步骤，不能提供源码、接口地址或SQL。新建函数及保存参数可显式冻结事务与返回模式（严格为 0/1），省略时仍为 0/1，MCP 登记保持 0/1。过程函数核验数据源及精确父过程身份，不要求当前界面系统包含该函数；PAGE 与 MCP 登记仍核验系统归属。函数发布逐字核对原版本与源码，并在保存前后核对既有事务与返回模式；服务组件源码发布绑定受控保存后的源码哈希、原生版本、完整原文与唯一片段，只修改组件脚本，保留事务模式并完整回读，检查及保存请求均只能选择本机冻结的步骤；大函数支持绑定已验证过程操作、原生版本及唯一命中原文的精确片段发布，保留未涉及源码，完整回读比对后只返回核验摘要；隐藏字段绑定受控源码操作、原生版本及原字段清单，仅追加无脚本字段，不覆盖既有字段。原生规范化导致整页比较未通过时，保留未知回执并独立检查目标，不重新派发。/nativeMetadataResult 按原请求标识查询回执。

8.1 页面能力

Chrome 扩展提供字段复制、列表滚动、页签排序、网页导航和当前对象定位；按需通过本机 Bridge 定向刷新已匹配的 API 对象。当前对象导出到独立目录，已有不同内容的同名文件不会被覆盖。

标签排序

拖动顶部功能标签或 PAGE、过程函数编辑标签可调整同一行内顺序，首页和菜单固定。上层顺序按平台来源保存在扩展中，下层仅保留本次页面会话；只移动标签头，不重建编辑器。仅支持已识别的标签栏。

8.2 路由与安全边界

服务使用本机 Bearer 配对；浏览器扩展校验来源，页面上下文和工作区路由需匹配。PAGE ID、过程包名和函数名通过 Nexus URI 传递，多个候选由当前项目目录消歧。未知或未匹配对象不扩大刷新范围。

9. 源码 MCP

9.1 入口与能力

Nexus 为 CodeBuddy、Trae 和 VS Code 生成 guthon-source-helper 配置。服务使用实际运行入口和 mcp --home <toolHome> -- --stdio --provider auto，按每次请求的 workspaceKey 从注册表解析同步方式。--read-only 限制为查询。get_workspace_source_capabilities 返回工作区的同步方式、源码根和可用工具，选错工具组时返回 SOURCE_MODE_MISMATCH。

  • API 使用 api_ 工具，通过租约、预览和幂等键受控修改 checkout，核验原操作和当前文件。
  • SVN 使用 svn_ 工具，使用授权清单和 workingCopyId 定位原生工作副本，保留原有过程、PAGE 租约和候选预览，保存后核对文件、索引和 SVN diff。SVN MCP 需要清单式工作副本。
  • DATABASE 使用 database_ 工具。以索引记录、源码 ID 和路径定位对象，从 source/readonly 或现有工作副本读取；按原文哈希和候选哈希校验，只保存到 source/workcopy，随后独立回读。

首次为 DATABASE PAGE 创建工作副本时，database_create_workcopy 使用 database_read_workcopy 返回的 readonly sourceHash 作为 baselineSourceHash，并携带相同的 workspaceKey、recordId、sourceId 和 sourcePath。创建成功返回 CREATED 和三个文件的 writeArtifacts（raw.json、meta.json、source-meta.json）。支持此回执的 Guard 核对对象及磁盘哈希，内容检查仍覆盖实际修改的源码。已有副本返回 EXISTS，保留原文件且不签发创建回执。Nexus 和受控保存可直接修改 Workcopy JSON 中的片段，不依赖实体脚本投影。

向导预览后合并新服务，保留其他条目和 JSONC 注释，覆盖前核对原文件并备份。迁移时先确认新服务可用，再移除客户端的旧 guthon-svn 条目。向导只读探测工作区和工具清单，客户端审批、实际工具调用及平台连接分别核验。Codex 的接入命令见Codex 配置步骤。

API 的 open_document 遇到批量导出的结构化 PAGE 时，使用对应 Nexus 登录会话定向读取平台原生模型。只在本地原文与基线一致、没有待处理冲突或编辑器草稿且平台提供可编辑的原生版本时，才切换本地基线并返回新的租约和源码哈希。候选以该租约返回的原文为准。原生基线已存在时可离线申请租约。使用“允许受控本地修改”即可准备该页，准备只读取平台并更新本地。批次编辑可先为这类 PAGE 取得新租约和预览，再将预览加入批次。

MCP 文档租约只返回有界正文前缀；大文件会给出截断与后续偏移，完整读取使用 read_source 分页并核对同一文件哈希。预览差异也标识截断，候选摘要始终绑定完整候选，不应把正文前缀当作完整文件写回。

支持该工具的构建可用 load_module_parameter 传入 workspaceKey、systemId 和 configId，只读请求平台详情并加载到本地缓存；需要完整正文时再用 read_source 分页读取并核对文件哈希。工具可用性以客户端实际发现的清单为准；该加载不上传或修改平台参数。

9.2 查询与受控修改

查询包含源码目录、内容、调用方、事实、PAGE 节点、字段与设计契约；查询结果需检查当前文件哈希、分页和覆盖边界。受控本地修改通过 open_document、preview_document、write_document 和 close_document 使用租约、预览和幂等键；结果未知且未取得操作编号时，用原 idempotencyKey 调用只读 find_document_operation 找回原操作，再以 verify_document_operation 核对；未找到不证明请求未派发，不能据此重发。宿主审批拒绝而尚无操作时，可明确确认调用 close_unstarted_source_request 关闭原幂等请求：单文档绑定原租约与预览，批次绑定原计划与摘要；关闭与写入使用同一派发锁。返回 CLOSED_BEFORE_WRITE 才证明原键已被持久关闭、迟到请求也不会写入；若返回已有操作编号，只继续核验，不撤销源码。文档原键查询也可取回关闭证明。后续写入须有当前授权、有效候选及新的幂等键。编辑租约仍有效且源码与继承父层未变化时，可用 renew_document 续期；已过期租约须重新打开。resume_document_operation 只恢复原操作的回读和索引，源码不符时保留现场，不重放写入。

单文档和批次的失败回执通过 error.mutation 携带 owner 核验的工作区、原请求选择字段及阶段：NOT_STARTED、PREPARED 表示本次尚未派发源码写入，后者可能已有操作编号；WRITE_STARTED 表示可能已写入，不能仅按错误码判断未写。REJECTED 仍须核对原记录和当前原文；Hook 仅在明确拒绝且回读匹配原文后解除对应未知状态，不清除其他操作。runtime descriptor 的 linterCommand 经后端 lint --home 委派到已安装 Linter，保留参数与退出码，适用于源码、pyz 和发行应用入口。

批量读取与跨文件修改

read_objects_batch 一次读取 1 至 20 个本地对象或 PAGE 节点，所有对象共用最多 50000 字符的正文预算；逐项返回内容、错误和截断状态，按各项偏移继续读取时核对 sourceHash。对象分别读取，不构成跨对象原子快照。get_index_health 查询索引健康状态，get_definition 解析唯一源码定义，query_table_references 查询表访问和显式 PAGE 字段映射；结果受索引覆盖限制，列筛选不覆盖动态引用和 SQL 列访问，不能据此证明删除安全。get_source_diff 按页读取 API 基线与本地文件的原文或 PAGE 可读差异，并返回基线和源码哈希。

preview_source_batch 接收 1 至 200 个文件对象；同一 PAGE 的多个节点修改须合并到该页面的一项中，不能在同一批次重复路径。每项由 Schema 严格三选一：path+content、path+operations（前两类可加 expectedHash），或仅 leaseId+previewId。直接候选由批次入口取得租约，不要求额外逐个打开文档；已有预览项不得再带路径、候选或预期哈希。非法混合在调用 producer 前拒绝；CLI 入口继续执行同等互斥校验。apply_source_batch 绑定计划、摘要和幂等键，写入前检查全部候选、项目范围、源码状态和未保存编辑；预检未通过不开始批量写入。写入异常时尝试恢复原文并回读，恢复失败会报告 ROLLBACK_INCOMPLETE，不能假定已经全部回滚。

中断或结果未知时使用 get_source_batch_operation 和 verify_source_batch 检查原操作及逐文件状态，再使用 recover_source_batch 核对或修复索引；需恢复原文时须明确传入 rollback: true 和 confirm: true。原批次为原文与候选混合状态时，Hook 须先完成全部分页及当前哈希核验，才能放行同一操作的明确 rollback；不会因此放行新批次。存在外部修改或未保存编辑时保留现场并拒绝覆盖；恢复不会重新应用候选。批量操作只修改本地 checkout，不上传平台。单次 MCP 整体请求上限为 1048576 字符，可能先于单项或 200 对象上限触发，应按实际请求大小分批。

整页新建、复制与删除

固定 API provider 的平台整页操作使用 get_page_lifecycle_context 查询配对的平台上下文，open_page_lifecycle_edit 冻结目标，preview_page_lifecycle 审阅，再由 apply_page_lifecycle 使用候选摘要和幂等键派发平台操作。get_page_lifecycle_operation 和 list_page_lifecycle_operations 查询原操作，resume_page_lifecycle_operation 只查询原请求回执，不重复新建、复制或删除。

需要已配对 Bridge、当前项目匹配的平台页面会话和平台支持的接口；多个上下文须选定唯一目标。新建身份由平台分配；复制或删除核对原页面身份和源码版本，产品 PAGE 不允许删除，目标模块须在当前项目范围中。整页操作直接作用于平台。平台写入应答后，Bridge 单独回读原生页面：新建或复制核对返回的页面身份及所属系统、模块，删除核对页面已不存在。平台应答不等同回读成功；回读失败或身份、模块不符时返回 APPLIED_UNVERIFIED。UNKNOWN 表示派发或回执中断后结果未确认。这两种状态均须先查原操作及平台实际状态，不重新派发写入；恢复入口仅查询已有原请求回执，不能保证再次执行平台回读。操作不自动同步本地 checkout；平台结果明确后另行更新源码并核对。

CLI 使用 api source-batch 的 preview/apply/verify/recover，api page-lifecycle 的 context/open/preview/apply/status/resume/history，以及 api read-batch、api document、api index-health 和 api table-references；均通过 --stdin 提供 JSON。源码差异使用 api diff 的 view、分页参数；具体输入和当前工具清单以帮助和工具发现为准。

PAGE 结构编辑

可先检查设计契约和候选，再预览字段、按钮、事件、数据源及布局调整；具体可操作范围以返回契约为准。修改与平台上传分开，引用、平台往返保存和业务行为需要核验。

9.3 验证边界

本地索引、文件写入与 API 回读均不能单独证明平台编译、发布或业务执行。客户端接线、真实目标和安装包需分别验证。

10. guthon-team 治理

10.1 安装与更新

Nexus 初始化从团队内网仓库的 main 获取发布载荷，使用 guthon-team 独立安装器预检并同步根 AGENTS.md、规范、API 索引、Linter 和 Git pre-commit。全新开发根使用 rules/。已有根缺少 rules/ 时继续使用原 docs/。文件或现有 Git Hook 配置冲突会暂停同步，保留原有内容。手动同步使用相同的安装器，作用于当前连接的统一工作空间。Nexus 优先使用该空间已记住的地址，其次使用 GUTHON_TEAM_MARKETPLACE_URL 或 Windows 安装助手配置的地址。后台同步通过 Git 现有凭据访问仓库。需要交互认证时，可在 IDE 终端运行同一次同步，由 Git 处理凭据。

CLI setup 可通过 --team-source 指定团队 Git URL 或本地 Git 仓库的绝对路径，也可以使用上述环境变量。团队同步使用 Git 和 Python 3。单独准备目录时可用 --no-team-sync。部署 guthon-guard 并信任其 Hook 后，可以启用 Agent 生命周期检查和会话启动时的规范维护。初始化步骤见使用手册。

Release 中的 guthon-testing.zip 可单独安装到客户端 Skills 目录；普通用户可使用工具内置只读连接器，无需为此安装 DBX/MCP。首次在 Nexus 为目标工作区配置专用只读数据库账号，Skill 安装不代替连接与环境身份配置。其源码与适用范围见 Guthon Testing Skill。

10.2 规范门禁

规范层AGENTS 与权威标准说明业务语义、开发模式、方言 API 和允许的写入范围。
判定层guthon-lint 用稳定诊断码检查受保护路径、非法 API、Velocity 结构、赋值、重复保存和 SQL 兼容性。
时机层Agent Hook 在任务与工具生命周期检查，Git Hook 在提交前兜底；需要时可把同一 CLI 接入 CI。

版本清单和文件哈希用于判断规范是否完整、是否被本地修改以及升级是否安全。人工修改不会被静默覆盖；强制更新前先备份。私有 API 索引使工具能明确判断函数是否存在，避免用通用语言经验猜测谷神方言。

治理采用“语义规范 + 可执行 Linter + 生命周期 Hook + Git/CI 兜底”，因为提示词只能提醒，不能稳定证明每次修改都经过同一规则。Linter 通过只代表已覆盖的静态规则通过，不代表数据库、平台编译、上传或业务流程已经验证。

普通源码任务检查本次目标的路径和内容。需要审查工作区整体变更时使用 --changed，Git pre-commit 的 --staged 检查整个暂存集合。使用 runtime descriptor 的明确入口，静态检查结果只覆盖对应文件和检查范围。

提交 Hook 通过 workspace-resolve 识别有明确边界的注册项目指称。参考项目或普通词组中的偶然子串不会自动绑定。明确切换后的续问沿用新目标，相对路径仍由宿主 cwd 解释。写入 Hook 核对当前轮次绑定与请求的 workspaceKey、同步方式或文件归属。显式选择工具与写入 Hook 共用状态目录，以当前 Hook 提供的会话和轮次定位绑定。缺少该上下文时只能只读解析项目。

11. 构建、发布与验证

11.1 发行物

Windows 一键安装器内置后端、Nexus、Bridge、独立 Python 和安装指南。安装器通过 Windows 注册表、常见安装目录和 PATH 查找可用的 VSIX 安装入口，支持 VS Code、CodeBuddy 国内版和国际版、Trae、Qoder。安装时逐一核对所选 IDE 的 Nexus 版本，并生成配置好后端与数据目录的 Guthon.code-workspace。找不到可用 IDE 时，安装向导提供 CodeBuddy 国内版官网下载入口。缺少 Git 时从固定官方 HTTPS 地址下载并校验 SHA-256，离线构建可以内置 Git 安装包。公开包的团队地址可留空，已放入开发根的部门规则会保留。安装步骤和手动修复入口见 Windows 安装步骤。

Python 应用使用 PyInstaller 构建，并内置公开配置模板与版本信息。Windows 发行单文件 EXE，macOS ARM64 的发行 ZIP 内只有一个自包含的 GuthonCodeTool。Nexus 可从开发目录的上一级识别可执行文件。构建在对应的目标系统执行。发布流程同时完成：

  • 运行 Python、Nexus 与 Bridge 的相关测试。
  • 打包 Guthon Nexus VSIX 和 Guthon Bridge Chrome ZIP。
  • 打包公开的 guthon-testing Skill。
  • 为应用与组件生成摘要和签名元数据并发布 GitHub Release。

Release 不包含真实配置、凭据、业务源码、私有索引、日志或 guthon-team 内容。工具应用可以替换升级，用户的 toolHome 保持不动。

调试模式运行环境

Nexus 用稳定发行的签名验证 pyz 和依赖清单，再发现本机架构匹配且支持 venv 的 Python 3.12+。macOS 调试入口接受 Apple Silicon 的 arm64 和 Intel 的 x86_64，依赖安装需要当前 Python 与系统可用的预编译包。它在扩展的托管存储中按 Python 入口与依赖清单复用隔离环境，安装预构建依赖包。pyz 可以与 config/ 和开发根放在同一本地数据目录下。pyz 自检与 ToolHost 握手成功后才切换入口。组件更新使用同一准备流程。已有手工配置仍可运行，重新选择调试模式入口会准备托管环境。操作见初始化调试模式。

平台支持与发行完整性

独立可执行应用面向 macOS Apple Silicon 和 Windows x64。Intel Mac 可使用上节所述的调试入口。根目录 VERSION 是统一版本来源；GitHub Actions 构建两平台应用、Python zipapp、依赖清单、VSIX、Chrome 扩展、Skill、checksum 及签名元数据。发布说明按私有模板准备，不把私有草稿提交到公开仓库；CI 使用经检查可公开的提交说明或手动传入正文。

更新仅允许 HTTPS 和受约束重定向，下载与哈希流式处理，核对 API digest、checksum 和实际文件。Nexus 从 data/release-trust.json 加载固定 Ed25519 公钥（当前 key ID 为 guthon-release-20261004），员工无需配置。签名缺失、伪造或哈希不一致时阻止新候选执行，保留已有安装；维护者的本机 globalStorage/release-trust.json 信任文件只能增加明确公钥，不可替换已有 key ID 或放宽包内强制策略。后端没有配置公钥的独立校验路径须明确报告“签名未验证”，不能冒充 Nexus 强制验签。

签名 CI 使用 GUTHON_RELEASE_SIGNING_PRIVATE_KEY 与 GUTHON_RELEASE_SIGNING_KEY_ID，私钥与包内公钥不匹配、或强制策略所需密钥缺失时拒绝发行。签名覆盖应用、pyz、VSIX、Chrome 扩展和 Skill；scripts/verify_release.mjs 可用从可信渠道取得的公钥离线验收。首次安装仍需可信分发渠道，发行签名不等同于 macOS/Windows 系统代码签名，也不能证明程序无漏洞。

发行清单包含 Nexus 与 Chrome Bridge 的构建标识。同一组件版本有新构建时，支持该清单的 Nexus 会提示更新。Nexus 重载及托管 Chrome 重载后分别核对实际运行的构建；较旧的发行清单沿用版本比较。

GitHub Release 发布后自动触发独立的 Gitee 镜像任务。镜像任务逐项回验附件与发行说明，并单独报告结果。补同步、配额和重试流程见镜像同步说明，Windows 构建入口见统一安装器构建说明。
