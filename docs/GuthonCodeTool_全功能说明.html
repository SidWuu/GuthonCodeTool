1. 定位与边界

GuthonCodeTool 把谷神平台中的 PAGE、过程函数、表结构、单据类型、视图和系统脚本整理到本地，形成可检索、可比较、可供 AI 分析的私有开发工作区。

  • 工具负责读取、整理和索引源码；DATABASE 生成安全 Workcopy，SVN 由 Nexus 提供受控虚拟编辑。
  • 每个工作区显式选择 database 或 svn provider；SVN 只有用户执行初始化后才按授权清单中的精确 URL 检出。
  • DATABASE 开发只修改 source/workcopy；SVN 不生成额外代码副本，虚拟文档直接回写授权 checkout 原文件。
  • SVN 的“管理本地源码变更”提供类 Git 差异、多选/全选保存和撤销；SCM 支持全部/单文件提交 Nexus 修改和更新远程变更。“保存到谷神”固定可用，跨 working copy 分组执行精确文件 svn commit，成功仍表示“待谷神平台最终提交”。
  • 数据库连接、源码、业务文档和运行索引均为本地私有内容，不进入公开仓库或 Release。
  • Python 脚本继续作为开发与测试入口；普通用户只使用打包应用、VSIX 和 Bridge。

2. 整体架构

2.1 组件关系

text
VS Code 侧边栏 ──spawn──▶ GuthonCodeTool 应用
                                  │
Chrome 扩展 ──HTTP──▶ Bridge ─────┘
                                  │
                                  ▼
	                    数据库 / 源码表 或 SVN working copy
                                  │
                                  ▼
                   workspace / nexus
GuthonCodeTool 应用以同一 Python 入口执行 DATABASE 同步和 SVN checkout、虚拟编辑、SCM、索引操作。
VS Code 扩展：Guthon Nexus提供双源码模式、多项目功能树、“谷神源码”与每个 SVN 工作区的单一 SCM provider。
Chrome 扩展：Guthon Bridge把谷神网页上下文转换为本地工具调用，并提供字段复制等页面能力。

2.2 运行链路

  1. VS Code 扩展保存应用路径和本地数据目录。
  2. 用户确认操作后，扩展使用 spawn 启动应用并传入 --home。
  3. 应用设置 GUTHON_HOME，所有配置和私有输出均相对于该目录解析。
  4. Nexus 节点和 CLI 显式传入 workspaceKey；DATABASE 解析 readonly/Workcopy，SVN 解析授权 working copy 与独立 context/index.db。
  5. Bridge 使用显式工作区或页面身份路由；所有同步操作进入全局串行队列。

3. 可执行应用

3.1 统一命令入口

scripts/guthon_tool.py 是打包应用入口。macOS 与 Windows 仅文件格式不同，命令和业务逻辑相同。

text
setup                 创建缺失配置，不覆盖已有文件
workspaces            列出全部产品、项目和同步状态
route                 按 Bridge 页面身份解析工作区
workspace-summary     返回源码模式和有效 capabilities
svn                   从签出脚本管理精确授权 working copy，或执行更新、状态与差异操作
sync-source-all       拉取所有源码并重建索引
sync-source           拉取显式工作区源码
sync-all              依次同步源码、表结构、单据类型、系统脚本和视图
reindex               从 DATABASE readonly 或 SVN 授权 checkout 重建索引
export-markdown       导出源码索引文档
export-schema         导出表结构
export-bill-type      导出单据类型
export-system-script  导出系统脚本
export-view           导出视图
query / diagnose      查询局部上下文 / 执行只读排查
create-workcopy       按索引创建或打开对象 Workcopy
workcopy              查看状态、生成差异/交付物，或预检/执行 save-svn

除 setup、doctor、workspaces、route 等全局命令外，均要求 --workspace products.<id> 或 --workspace projects.<id>。

3.2 打包方式

scripts/build_guthon_tool.py 使用 PyInstaller --onefile，内置配置模板和运行所需 Python 模块。构建必须在目标系统执行：Windows 生成 EXE，macOS 生成 ARM64 Mach-O。

  • Windows 发行物：GuthonCodeTool-windows-x64.exe。
  • macOS 发行物：GuthonCodeTool-macos-arm64.zip，支持 M1 及后续型号。
  • 应用本身不保存用户配置，升级时直接替换应用文件即可。

Guthon Nexus 默认使用发行模式调用应用。维护者可切换到调试模式，直接运行源码仓库的虚拟环境和 Python 入口；面板命令与 Bridge 请求都会在每次执行时加载最新脚本，因此日常修改无需重建应用。切换模式不会改变本地数据目录。

4. 配置与本地数据

4.1 配置职责

  • datasource.yaml：产品、项目和只读排查数据源；敏感值可引用环境变量。
  • products.yaml：产品名称、数据源、子系统范围、可选页面来源和可选 SVN 契约；不配置源码模式。
  • projects.yaml：项目名称、数据源、继承产品、子系统范围、可选页面来源和可选 SVN 契约；不配置源码模式。
  • source-tables.yaml：PAGE、过程函数和系统脚本的语义字段映射；公开模板只保留占位符，真实表名和字段名由内部配置提供。
  • sync.yaml：全局同步窗口、未签入源码白名单和拉取规则，不保存当前或默认工作区。

setup 只补齐缺失文件，不覆盖用户配置。产品和项目在 systems.include.mappings 中以 alias 为键，每项只配置一对一的 system_id、data_source_id。DATABASE 查询结果缓存到 config/system-data.json；SVN 不读取该缓存。

4.2 目录契约

text
<本地数据目录>/
├── config/
│   ├── datasource.yaml
│   ├── products.yaml
│   ├── projects.yaml
│   ├── source-tables.yaml
│   └── sync.yaml
└── var/
    ├── AGENTS.md
    ├── docs/
    ├── tools/
    ├── nexus/{bridge,tool-runtime.json}
    ├── checkout/<配置 ID>/            # SVN 唯一源码事实来源
    └── workspace/
        └── <PRD或PRJ 工程>/
            ├── docs/
            ├── source/{readonly,workcopy}/       # 仅 DATABASE
            ├── database/{schema,billtype,views}/ # 仅 DATABASE
            └── context/{README.md,source-mode.json,index.db,state.json,logs}/

PRD、PRJ 只控制目录和 Nexus 展示顺序，真实身份始终来自配置中的 workspaceKey。

Nexus 同时展示全部产品和项目；每个节点的“源码来源：DATABASE/SVN”只切换当前工作区，并把结果写入该工程 context/source-mode.json。YAML 不配置模式，未设置时默认 DATABASE。SVN 工作区在 macOS/Linux 使用谷神下载的 svnCheckoutHere.sh，Windows 使用 svnCheckoutHere.bat，两种文件均为正式支持格式。对应产品或项目的 systems.include.mappings 维护 alias、SYSTEM_ID 与 DATA_SOURCE_ID 的一对一关系；项目不得复用产品的数据源 ID。Nexus 据此预览范围并生成脱敏清单、用同一份工作区认证检出或更新脚本中的仓库。SVN 不创建 readonly 和 database 镜像，checkout 与 workspace 分离，签出脚本不会被执行，凭据不会写入清单、YAML 或日志。

scripts/providers/svn/import_svn_scope.py 与打包工具的 import-svn-scope 命令负责把谷神平台下载的 checkout shell/BAT 脚本转换为授权清单。它支持 shell 的反斜杠续行和 BAT 的插入符续行，只接受字面量精确 URL 与安全相对目录，忽略认证参数且不执行脚本、SVN checkout 或旧 working copy 清理；变量、绝对目录、URL/目录重叠和未知分类会阻断。已有清单不同必须显式 --replace 原子替换。

5. 源码同步与索引

scripts/common/gusen_hub.py 是工作区路由与索引的共享实现；scripts/providers/database/ 保存数据库源码、metadata 导出和只读诊断，scripts/providers/svn/ 保存授权清单、working copy、虚拟编辑和 SCM。数据库 provider 按 datasource 查询源码表并维护 readonly；SVN provider 按 authorized-scope.json 聚合 systems/<SYSTEM_ID> 与 datasources/<DATA_SOURCE_ID> 等精确 URL working copy，读取 pages/index.md 与 procedures/index.md 构建业务目录，并以文件 hash、BASE revision、scope entry、源路径和 JSON Pointer 建立同一套对象/调用索引。

5.1 PAGE 导出

PAGE 保存到 {子系统}/page/{模型序号}_{模型}/{模块序号}_{模块}/{页面名 页面ID}。完整 JSON 写入 raw.json，页面脚本、SQL、事件和组件脚本拆入 scripts/。

  • 模型和模块序号补齐三位，并按父模型链还原目录。
  • 项目脚本的独立 @inherit(); 使用相应产品快照字段。
  • 空的服务组件 compScript 仍生成空 compScript.vm。

5.2 过程函数导出

过程函数保存到 {子系统}/procedure/{过程别名}/{函数名}/source.vm。项目继承标记使用配置映射的产品脚本；多个子系统共用数据源时只保存一份实体源码，其余目录使用链接。

5.3 调用索引

每个工作区使用自己的 context/index.db。索引记录源码对象、静态调用、低置信动态调用、PAGE 片段定位、字段与表列映射、单据路由、表读写及条件/赋值/异常事实；Nexus 的 SVN 虚拟文档使用它提供 F12/转到定义和查找引用，AI 仍以显式 workspaceKey 查询局部上下文。

调用边表只保存 source_record_id、目标身份和脚本定位字段，来源产品、项目、对象身份、名称和时间由源码主表按显式唯一整数 record_id 关联，不依赖可能被 SQLite 整理改写的隐式 rowid，也不再逐边重复。目标覆盖索引用于调用方查询，来源索引用于被调用关系和增量重建；兼容视图维持原查询与导出字段。旧索引首次连接时事务迁移并整理空闲页，无需删除本地索引。

SVN PAGE、过程函数、系统脚本、表和视图直接从授权 checkout 流式派生索引。虚拟保存、原文件变化、revert 和 commit 按物理文件增量刷新；update 无法安全识别结构变化时退回全量扫描。全量扫描在单事务内完成，失败回滚并保留旧索引。索引只保存有界证据、hash、真实相对路径、JSON Pointer 和关系，不保存第二份可编辑源码，也不建立源码全文倒排。

AI 查询分两步：svn facts 按关键词、表或源码身份返回少量事实；svn explain 按表或单据号返回写入位置、控制条件和有界调用者链，并用 continuation token 续查。默认结果不携带完整源码，事实不足或实际修改前才按返回的路径和片段读取 checkout。

“谷神源码”的 catalog 只读取该 SQLite 索引，展开单个 PAGE 时才懒解析目标 JSON 的方法、事件、字段和 SQL。PAGE/系统脚本根目录的 $.<中文子系统名> 作为中文分组；PAGE 层级及末级名使用 index.md，过程函数、系统脚本、表和视图保留原源码目录。全量 source-index.md、invoke-index.md 和 dynamic-invoke-points.md 只在显式执行 export-markdown 时生成，不属于普通扫描和运行时查询链路。

6. 平台元数据导出

  • 表结构：scripts/providers/database/export_table_schema_sql.py 查询 gd_tables、gd_tables_field 和 gd_system。
  • 单据类型：scripts/providers/database/export_bill_type_sql.py 查询 gd_bill_type 和 gd_system。
  • 视图：scripts/providers/database/export_view_sql.py 读取 gdp_tables_views.VIEW_SQL。
  • 系统脚本：scripts/providers/database/export_system_script_sql.py 按本机语义映射查询；项目 JavaScript 同时存在产品快照与项目覆盖时，固定按产品在前、项目在后合并。

四类导出均复用目标工作区的数据源与子系统范围。sync-all 固定按“源码 → 表结构 → 单据类型 → 系统脚本 → 视图”执行；任一步失败或同步期间配置摘要变化即停止。五步全部成功后才把该工作区标为 SYNCED。

本段导出命令仅适用于数据库模式。SVN 模式把 tables/、views/ 作为只读索引对象，系统脚本可投影/写回；当前仓库没有正式 billtype 数据，因此 SVN 模式不伪造单据类型导出，也不提供业务 diagnose。

7. DATABASE Workcopy 与 SVN 编辑安全模型

  1. 从 readonly 创建 Workcopy，同时保存用于定位 readonly 的 source-meta.json。
  2. 再次拉取时直接比较最新 readonly 与 workcopy；存在差异时保留 workcopy 并生成差异报告。
  3. readonly 与 workcopy 的任何差异都统一保留 workcopy；需要接受 readonly 覆盖时关闭拉取校验。
  4. workcopy status 查看状态，diff 更新差异，package 生成交付清单。

sync.yaml 的 rules.pull_diff_check 缺省为 true。设为 false 后，Bridge 每次拉取都会直接覆盖目标工作区的 readonly/workcopy，且不生成 source-meta.json 或差异文件。

pull_auto_add_git 只暂存本次新生成、未跟踪且未被忽略的文件，不暂存已有文件修改，也不强制添加忽略文件。

以上 Workcopy 规则只属于 DATABASE。SVN 不保留 readonly/workcopy 代码副本；Nexus 会话账本只保存对象身份、源 hash、BASE revision、编码/BOM/换行和 JSON Pointer。虚拟保存前验证授权路径与目标文件 hash，随后最小化原子回写原文件；SCM 按业务状态聚合多个 working copy。安全的外部已跟踪文本修改可进入变更管理器审阅、保存或撤销；冲突、新增、删除、未跟踪和属性变化会被阻断。跨 working copy 的保存按组依次提交并产生多个 revision，不伪装成原子提交。

8. VS Code 扩展：Guthon Nexus

扩展入口为 plugins/GuthonVSCodeExtension/gushen-vscode-completion/src/extension.js。

  • 全局保存 gushenCompletion.toolPath 和 gushenCompletion.toolHome。
  • 每个产品或项目的“源码来源：DATABASE / SVN”与发行/调试运行模式正交；DATABASE/SVN 工作区始终混合展示。
  • 每个节点绑定自己的 workspaceKey 和状态，菜单完全由 workspace summary 返回的有效 capabilities 生成。
  • “谷神源码”树按业务类别展示 SVN 模式的 PAGE 脚本/SQL/字段、过程函数、系统脚本、表和视图；PAGE 与过程函数的层级和同级顺序来自各自 index.md，未编入索引的对象排在已索引内容之后。PAGE raw.json 的 serviceEvents（如 beforeSaveScript、afterSaveScript、beforeSqlSelectScript）按 GSS 后端分块展示，可写虚拟文档直接回写 checkout。
  • SVN 目录 catalog 从本地索引加载并在扩展内缓存；PAGE 分块按页面懒加载，树展开不触发整个 checkout 的 SVN 和文件扫描。
  • 虚拟文档打开和保存的 SVN 安全检查限定为目标文件和会话 hash，不用同 working copy 的无关变更阻断当前文件。
  • PAGE 独立 GSS 服务组件保存时严格保护自动生成身份头，只忽略 VS Code 造成的等价换行差异，并分别保留原始头部和正文的换行布局。
  • “谷神源码”树顶部“跳转”接受模块及其方法、字段、SQL、事件等任意子节点，沿父级解析所属模块后按 workspaceKey + checkoutPath + sourcePath 精确显示到资源管理器，并拒绝越出当前 checkout 的路径；同一命令保留在右键菜单，取消名称末尾的行内图标。
  • 顶部“定位”把当前打开的 SVN 虚拟分块或 checkout 物理文件反向映射到 Nexus 树，自动展开父级并选中节点；PAGE 定位只懒解析目标页面。
  • “谷神源码”树还提供展开所选、收缩所选、直接显示的原生搜索框、刷新和水平滚动；搜索默认使用模糊过滤，只查询当前树缓存，不重新扫描 checkout。
  • 每个 SVN workspace 只注册一个 SCM provider，提供基于 SQLite/index.md 业务名称的本地/远程变更、历史、全部/单文件提交与更新、部分物理文件保存和放弃修改；底层多个 working copy 不拆成多个顶层项目。单文件更新只作用于授权范围内且仍为远程变更的精确物理路径。PAGE 默认使用脚本、SQL、字段可读双栏差异，原始 JSON 差异仍可显式打开；左侧为内存型只读 SVN BASE，右侧为当前 working copy，不生成临时源码副本。
  • .gss 注册为独立 Guthon GSS 语言，在 Java grammar 上注入 Velocity/GSS 指令与变量，并继续接入 Nexus 补全、悬停、定义和引用；兼容 .vm 保持 Java。远端状态只在显式云操作时查询；更新发现 incomplete 或 working-copy 管理锁时只执行无删除/还原参数的标准 svn cleanup 后复检。
  • var 私有 Git 明确忽略根级 checkout/，只管理配置、上下文、索引资料和 DATABASE 工作区；SVN 源码只在 Nexus/SVN SCM 中审阅和提交，不形成第二套 Git 历史。
  • 虚拟保存只等待目标文件校验、原子写回和单文件增量索引；SCM 使用保存结果增量刷新，受控文件监听事件不重复索引，完整扫描留给手工刷新、更新和提交前检查。
  • 受控虚拟保存不再发出伪外部变更事件，因此同一文档可连续保存；真实 checkout 外部变化仍推进虚拟版本并保留后端 hash 覆盖保护。
  • 放弃本地修改只验证 selection token、会话 hash 和本地 SVN 状态后回退到 BASE，不被远端较新 revision 阻断；保存到谷神仍要求远端状态安全。
  • 侧边栏所有执行型操作均先弹出确认；打开配置和目录保持单击。
  • 未配置时显示“设置工作空间”，已配置时自动显示“切换工作空间”；只有确认并选中新目录后才更新全局 toolHome，取消时保留原工作空间。
  • 使用 spawn 直接传递命令、--home 和 --workspace，不经过 Shell，因此 macOS 与 Windows 参数一致。
  • 提供 Java、JavaScript、SQL 补全和 API 悬浮说明；.gss 与兼容保留的 .vm 都关联 Java 语言模式和 Java 高亮，并通过 workspace 调用索引提供过程函数转到定义和查找引用。
  • 补全数据在 data/index.json，手工片段在 data/manual.json，路由规则在 rules.json。

9. Chrome 扩展：Guthon Bridge

Bridge 由 Chrome 扩展和监听 127.0.0.1:17361 的本地服务组成。服务入口为 plugins/GuthonBridge/bridge/server.js，随 VSIX 打包并由 Guthon Nexus 使用 VS Code 自带的 Node 运行环境启停。

  • Nexus 直接把当前系统应用和本地数据目录传给 Bridge；用户不需要手工设置 GUTHON_TOOL_PATH 或 GUTHON_TOOL_HOME。
  • 请求携带 workspaceKey 时验证页面身份；未携带时按 pageOrigin + dataSourceId + systemId 匹配，多个候选由 Chrome 只为当前请求选择。
  • 页面提供过程函数/PAGE 拉取、表结构、单据类型、视图、系统脚本、复制模式和字段平移。
  • 源码拉取和数据库导出只在数据库工作区显示；SVN 工作区前端隐藏、服务端旧接口再次拒绝，复制与跳转能力保留。
  • 允许访问的平台范围由 extension/host-config.js 的 CIDR、域名后缀和路径前缀控制。
  • Bridge 不提供 SVN 第二条源码拉取或写入链路；Nexus 的受控 SVN commit 也不代替谷神平台最终提交。

普通用户不需要单独安装 Node.js。GuthonCodeTool-chrome.zip 只负责安装 Chrome 扩展，本地服务由 Guthon Nexus 启动；命令行启动仅保留给仓库源码调试。
