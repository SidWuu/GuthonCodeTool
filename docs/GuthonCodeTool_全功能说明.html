1. 产品定位与设计原则

1.1 功能边界

GuthonCodeTool 通过谷神项目 API 接入源码，在各项目独立的本地目录中编辑、检索并按需上传；Nexus 提供开发界面，Bridge 提供浏览器增强。数据库诊断和测试是独立能力，需要明确连接和目标身份。

本地保存、API 上传回读、平台编译发布与业务验证分别确认。当前源码分支仍在集成，运行入口和端到端效果以实际构建与验证为准。

1.2 核心设计选择

每个产品或项目使用明确的 workspaceKey 和独立的源码目录、索引、API 配置与基线。拉取按选择的子系统和数据源执行；本地编辑与远端变更冲突时保留内容并要求处理。操作结果不代替业务验收。

2. 运行架构

2.1 组件职责

CLI 和 ToolHost 使用共享 API 服务；Nexus 负责项目配置、源码界面、编辑与状态，Bridge 负责受信任页面的定位与辅助，MCP 提供按工作区限定的本地查询和编辑。数据库诊断通过独立连接或 DBX 操作。

API 接入与范围

API 支持项目地址、账号登录及验证码；用户可选择仅本次会话，或使用系统凭据库记住登录。选择全部或指定子系统，并按需选择共享数据源；空选择不自动扩大范围。PAGE、过程函数、系统脚本、表与视图按各自系统或数据源归属处理；公共文件及项目配置按范围设置获取。

发行后端内置 HTTPS CA 证书资源，并保留系统信任设置；项目平台与谷神登录服务分别连接。证书校验失败会明确标识 API_TLS_CERTIFICATE_ERROR 和失败的服务，不会关闭证书验证。

2.2 目录与调用链

<toolHome>/
├── config/                         # 本地配置
└── var/
    ├── checkout/<配置 ID>/          # API 当前源码
    ├── workspace/<工作区>/context/ # 索引、API 配置和基线
    └── nexus/                       # 本机工具状态

checkout 根可按项目显式配置；真实配置、凭据和业务源码不放入公开工具仓库。系统关联的数据源以及显式选择的共享数据源可能包含共享对象，应确认范围后拉取。

公开仓库与业务开发入口

工具源码和工作数据分别管理；在业务窗口使用明确的 toolHome、workspaceKey 与项目目录，不从目录名猜测目标。

3. 工作区与配置

3.1 稳定身份与配置

产品与项目分别使用 products.<id>、projects.<id>；注册表中的配置 ID 跨两类工作区保持唯一。每个项目配置独立 API 地址、系统与数据源范围。checkout、基线和操作记录绑定该平台身份；已有基线后更换平台地址需要另建项目或明确迁移，不能复用原项目源码向其他平台上传。多个项目分别在各自窗口打开。

配置字段与故障隔离

products.yaml、projects.yaml 保存注册信息；API 项目配置和基线位于目标工作区的 context/api。datasource.yaml、database-testing.yaml 用于独立数据库诊断与测试；sync.yaml 的 guthon_api 用于方言文档资源。真实地址、密码和业务内容不应写入公开示例。

3.2 创建、切换与删除

在 Nexus 创建项目并明确选择目标；删除前核对预览及保留的数据。任务开始时按明确目标或路径解析 workspaceKey，不依赖全局默认项目。

3.3 命令与运行描述

CLI 与 runtime descriptor 参考

使用 api <action> --stdin 传递结构化输入，CLI 与 ToolHost 共用工作区身份。动作包括配置、登录、拉取、定向刷新、状态、目录、读取、编辑、差异、冲突处理、上传、回读核对、索引和查询；完整参数以当前命令帮助为准。凭据通过标准输入传递，不放入命令参数。

Nexus 刷新状态时只请求完整范围的汇总和非干净文件清单，避免大项目状态超出传输预算；api status 默认仍返回完整文件列表，changesOnly: true 可仅返回变更项及 summary 计数。状态扫描复用已登记的远端摘要，并在单次扫描内固定范围，不重复读取基线正文；同项目同时触发的状态请求共用一次扫描，后续请求仍重新核对本地文件。API 元数据与原文摘要匹配的极简 PAGE、无 SQL 视图会被识别为元数据型源码，不作为格式失败，也不生成不存在的结构或 SQL 事实。真正的身份冲突或无法解析内容保留原文与诊断，其他可解析对象继续处理。重新打开窗口后，可直接从源码树查看已保存的目录诊断，无需再次重建整个索引。

运行描述使用显式 toolHome 和命令数组；发行、源码及调试模式的入口不同。实际能力以当前安装版本为准。

4. 数据库诊断与测试

4.1 只读数据库排查

工具可按工作区、开发/测试环境和私有目标配置解析数据库连接，支持 MySQL、PostgreSQL 与 Oracle。查询必须核对 database/schema 和实际可见表；正式测试计划另有声明的验证范围。密码默认写入系统凭据库，配置只保存连接引用。

  • database-probe：验证驱动、连接和只读能力。
  • database-describe：核对目标 database/schema 后读取可见表结构，避免猜测字段；快速排查不以静态表列表代替目标身份和实际可见性验证。
  • database-query-readonly：只接受单条 SELECT，限制返回行数并始终回滚事务。
  • 可选 DBX 连接只在配置了 connectionId 时使用；缺失绑定会明确报告，不自动猜测其他连接。

diagnose 还提供配置驱动的源码逻辑排查：它只允许显式标记为测试、启用只读诊断并声明数据库白名单的数据源，按模板逐步执行绑定参数的单条 SELECT，在首个不满足条件的位置停止并生成本地排查报告。该能力适合重复执行的固定检查链；临时问题则使用目标解析、结构描述和有界查询逐步取证。

数据库快速排查从当前工作区和开发/测试环境解析明确目标；未指定环境时使用配置中的诊断默认目标，而“测试一下”只是连接探测，不代表已切换到测试库。功能验收、回归和交付应使用正式测试目标与测试计划/结果证据，不能把一次只读查询当作完整验证。可选的 Guthon Testing Skill 提供该工作流指导，其安装与数据库连接配置是两个独立步骤。

Nexus 的“配置数据库只读目标”区分快速排查与正式只读验证。正式目标向导收集系统、数据源、租户字段及范围/身份核验证据，不要求表名单；更新已有目标时不重写旧表名提示字段。Oracle 登录 schema 与业务 schema 分别核验；生成 DBX 交接文件只说明交接信息已准备，不能作为查询已执行的证据。

“查看最近诊断历史”读取已有记录，不重新执行查询。查询可导出 CSV 或带证据页的 XLSX，结果与目标、SQL、执行时点一并保存到当前私有工作区。

这些限制使数据库能力适合诊断和验证，而不会把开发工具变成任意 SQL 执行器。查询命中只证明数据库证据，不等同于页面结果或已部署版本验证。

目标、凭据与适配器

database-target-list 列出工作区目标；database-connect-test 测试明确环境的连接，database-probe 核验目标身份和只读能力；database-target-resolve 及 runtime descriptor 按 cwd 和环境解析默认目标：未指定环境用 defaults.diagnosisTargetId，明确开发/测试环境用 defaults.byEnvironment.dev/test。显式 --workspace 优先于 --path。database-target-configure 可更新已有目标的密码或属性；database-target-remove --check 先预览，正式移除确认精确 target ID，只清理不再被引用的连接和凭据。

有 connectionRef 时优先用内置只读连接器；仅有 connectionId 时使用当前实际可用的 DBX。database-dbx-import 只导入有来源说明的公开连接元数据，database-dbx-handoff 生成先核身份的调用交接，不读取 DBX 密码或伪装查询已执行。--profile 可选择已有目标配置。

密码默认保存在 keyring；维护者可显式配置 passwordEnv 环境变量或 passwordFile 绝对路径密码文件。更换来源不会自动删除旧 keyring 记录。database-credentials-export/import 要求明确工作区、已注册凭据引用和确认，使用 AES-GCM 加密迁移，不把解密明文落盘；加密文件也应保存在私有位置。

查询、输出与诊断历史

database-diagnose 默认只探测身份；提供 --sql、--sql-file 或 --stdin 才执行查询。快速排查使用 database-*，固定源码诊断案例使用 diagnose。内置查询只接受经验证的单条 SELECT，最多返回 100 行，并回滚只读事务。

SQL 校验支持普通字符串中的邮箱、分号和井号、SELECT CTE 及对应引擎的允许函数/类型，包括 Oracle/MySQL 的 INSTR 字符串定位；拒绝跨库、未知副作用函数、注释、引用标识符和不支持的转义。Oracle 替代引号、PostgreSQL dollar-quote、嵌套 WITH 与反斜线字面量仍不支持，复杂值应使用绑定参数。MySQL/PostgreSQL 可用 --explain 读取有界估计计划，不执行 ANALYZE，返回 queryExecuted=false；Oracle 因需计划表写入而拒绝该操作。估计计划返回完整 JSON，不按普通业务单元格长度截断；行上限仍保留，普通查询的单元格与行数截断规则不变。

查询结果保留行列截断位置；CSV/表格输出还在 stderr 提示截断。--format xlsx --output <私有文件.xlsx> 生成“结果”和“证据”两页，字符串按文本保存、长整数保留精度；空列名或重复列名明确拒绝。连接探测和 DBX 交接不生成伪空结果。导出摘要最多保留最近 100 条。

database-history-list/show 提供脱敏查询历史，database-compare 提供目标间计数对比，diagnosis-template 生成查询模板；计数不同不直接代表功能错误。描述缓存绑定完整目标摘要、TTL 及 probe 失效 epoch。diagnosis-list/show 供 Nexus 查看最近最多 100 条诊断摘要或精确详情，不读取 SQL、参数或结果行，也不重新运行查询。固定案例报告默认隐藏绑定参数，只有明确 --include-params 才写入原文；报告位于私有 var/docs/业务排查文档/，模板见公开的 source-diagnosis 示例。

正式只读验证计划

database-test-artifacts 提供 validate-config、init-plan、run-readonly、export-dbx-plan 和 import-dbx-results 等子命令。正式目标和计划需声明系统、数据源与租户证据，计划 SQL 按实际源码和业务键限定范围。allowedTables 是兼容旧配置的可选表名提示，用于生成计划草案，不作为查询授权名单。配置与 SQL 仍须满足已核验目标的 database/schema，内置查询对每个物理表核验实际可见元数据；DBX 交接由调用方先核验身份和表结构。静态工件校验不能代替真实身份、业务用户行权限或 WHERE 业务语义核验。执行器先核身份，前置条件失败或结果截断时停止相应用例；平台结果用例还需与源码和目标绑定的版本及触发证据。内置连接可执行只读计划，DBX-only 目标通过交接、结果导入和本地 evaluate 完成证据处理。

bash
.venv/bin/python scripts/guthon_tool.py database-test-artifacts -- \
  run-readonly /absolute/private/plan.json \
  --config /absolute/toolHome/config/database-testing.yaml \
  --out-dir /absolute/private/new-run

每次运行使用新的私有目录，保存结果和报告，不覆盖旧运行；执行器不发布、不触发平台或清理数据。diagnose case.json --dry-run 只做未绑定 SQL 的静态校验，不连接也不写报告。模板的 --case-out 产生不能直接执行的案例草稿，并保留调用方的 --max-rows。

5. API 源码与本地编辑

5.1 拉取与合并

拉取使用远端基线、本地文件和平台版本比较，能安全合并的非重叠修改保留；无法合并的冲突保留本地内容并报告。局部拉取只处理已请求范围，不删除范围外文件。范围变更同步调整已下载对象的索引；索引指纹与当前平台/范围不一致时拒绝查询，避免显示旧范围的结果。定向刷新需要唯一对象，找不到或不唯一时报错，不退回全量拉取。

编辑器未保存内容和 PAGE 草稿需先保存或处理；不同进程的协调状态以实际运行结果为准，不把后端检查等同于客户端验收。

迁移本地修改：变更包 CLI

api export-changes --stdin 将当前项目范围内已登记、可写且有本地修改的对象导出为 JSON；请求必须给出 checkout 之外、尚不存在的绝对 output 路径，可选 paths 数组按源码相对路径筛选。不提供 paths 时导出当前范围内符合条件的对象。筛选是交集，返回的 fileCount 需与预期对象清单核对；没有可导出对象时报错。

变更包顶层包含 schemaVersion: 1、workspaceKey 和 files；每个对象包含 path、metadata、baseContent、localContent、baseHash 和 localHash。身份字段按对象类型包括 sourceType、pageId、systemId、procedureId、funId、dataSourceId、tableId、viewId、scriptType；正文摘要按 UTF-8 计算 SHA-256。正文可能包含私有源码，应保存在受控私有位置。导出只读取当前 API 工作区，不自动上传或修改原工作区。

api import-changes --stdin 接收绝对 input 路径，默认预览；输入文件不超过 64 MB，包内包含 1 至 200 个对象；超过导入上限时，应在导出前用 paths 分批选择并逐批核对。先在目标项目完成 API 范围配置与拉取，并确保目标是同一 workspaceKey 下已登记的可写对象。导入按包内相对路径读取当前已登记对象，再核对身份和正文摘要；不会仅凭身份自动匹配不同路径。预览按变更包的基线、本地修改与目标当前文件生成三方合并，返回 planHash、changes、conflicts 和 complete；changes 仅含路径和前后摘要，不包含合并后的正文或文本差异，因此预览不能直接审阅合并正文。预览不写源码。

审阅完整对象清单和无冲突结果后，使用相同输入文件、apply: true 和该次 planHash 应用。输入或目标状态发生变化时必须重新预览；存在冲突不能应用。应用前还会检查编辑器状态与文件哈希，随后逐项写入当前 checkout 并更新索引；它不会自动上传。中途中断、写入或后续索引更新失败时先检查操作记录与实际文件，核对已应用范围，再处理索引；不假定批次自动回滚或盲目重试。

bash
# 使用私有绝对路径；按实际项目替换 workspaceKey。
printf '%s' '{"output":"/absolute/private/changes.json"}' | .venv/bin/python scripts/guthon_tool.py api --home "$GUTHON_HOME" --workspace projects.demo -- export-changes --stdin
printf '%s' '{"input":"/absolute/private/changes.json"}' | .venv/bin/python scripts/guthon_tool.py api --home "$GUTHON_HOME" --workspace projects.demo -- import-changes --stdin
# 审阅预览并确认无冲突后，将下方占位符替换为本次返回的 planHash。
printf '%s' '{"input":"/absolute/private/changes.json","apply":true,"planHash":"<planHash>"}' | .venv/bin/python scripts/guthon_tool.py api --home "$GUTHON_HOME" --workspace projects.demo -- import-changes --stdin

旧工作区迁移缺口：当前分支不包含旧源码传输运行时，也没有自动读取旧工作区或提取旧基线的入口。旧侧必须先以可核验方式提供逐对象的身份、路径、共同基线与本地修改，并由迁移流程生成符合当前变更包契约的材料；仅有文件快照或差异不足以证明共同基线。缺少身份、无法映射、目标已删除或不受支持的对象应暂停处理，不得猜测映射或当作已迁移。已在平台删除的导入目标会被拒绝；complete=true 只表示当前合并预览无冲突，仍须核对完整对象清单、身份及类型。此流程只作用于显式选定的当前 API checkout，原始真实工作区不应被改写。旧侧材料生成与完整迁移验证仍需另行完成。

源码资料与单据类型导出

export-schema、export-view 和 export-system-script 使用当前 API checkout 的已获取资料，输出到独立导出目录，导出结果不作为可上传源码。单据类型不在 API 源码目录中；export-bill-type 使用单独配置的数据库连接，先核对目标和数据源范围。

5.2 上传、冲突与回执

上传前重新读取平台对象并预合并，检查身份和本地状态；确认后逐项上传并回读。平台应答必须包含当前对象的源码，独立回读须与应答正文一致；平台格式化或补充字段后的正文会同步回同一 checkout，并保留提交后的本地修改，重叠变化进入冲突处理。回执分别保存提交、平台接受及回读摘要。应答丢失时，只有回读与原提交完全一致才自动确认，否则保留未知状态，不重发上传。回执可表示部分完成、失败或结果未知，未知时先查原操作和平台状态，不重复提交。上传回读与平台最终提交、编译、发布及业务结果是不同阶段。

表与视图支持明确确认后的平台结构同步，会执行 DDL；需核对数值身份和已上传状态，再独立验证数据库结果。过程函数创建同样需要明确身份、确认和平台回读。

5.3 本地页面编辑与预览

原生 XML 与 JSON PAGE 均可在 Nexus 本地页面编辑器中查看和调整字段、按钮、属性、事件、SQL、顺序及受支持布局。XML 页面投影为共享页面模型供编辑与索引使用，保存仍保留原生 XML；未改动节点的原文、CDATA、未知属性和结构由映射保留并回读核对。页面草稿支持撤销、比较和恢复；保存前通过租约、快照与候选预检保护本地文件。代码标签的未保存内容由编辑器管理，外部修改需要核对后处理。

页面编辑范围

可浏览页面区域和字段集合，在受支持的控件中调整字段、按钮、已有事件和属性，并对字段顺序、数据源及原生布局使用相应设计操作。PAGE 结构操作由后端契约定义：字段和按钮可按支持的集合新增或复制，事件和数据源须符合所属控件的约束；删除或移动前应检查引用。未识别的控件、属性和继承片段不应推断为可写。

内容能力和边界
字段与按钮查看所属区域和已有属性，调整受支持属性与同集合顺序；新增或复制采用设计契约并核对生成身份。
事件与 SQL查看已有节点并通过代码入口编辑；结构操作按控件支持的事件归属预览，不执行 SQL 或业务脚本。
数据源与布局受控操作可调整原生数据源定义、行列布局及栅格；按页面契约维护字段与单元格关系，不自动修改其他业务引用。
继承内容产品层保留只读来源；处理继承标记时核对原文、父层和当前项目内容，无法确认时保留原稿并提示。

保存、比较与冲突

页面保存写入当前本地源码；与平台基线的差异和窗口未保存草稿是不同视角。来源变化、身份不唯一或冲突时保留草稿，按提示检查和选择，不将本地保存视为上传。

原版设计器资源

原版布局预览需要对应平台资源；字段和代码管理不以此为前提。资源按平台和构建隔离，可准备、导入或选择已校验缓存；浏览器登录不等于 Nexus 可以下载受保护资源。资源准备、校验及缓存不证明平台显示和业务行为一致；在线设计器依赖平台登录及相应资源访问条件。

限制

服务组件或不支持的 PAGE 格式使用代码编辑器；未知控件和未开放属性需以实际支持范围为准。静态资源、页面保存和平台运行需分别验证。修改继承内容时应核对来源及父层身份，不能直接将只读父层当作当前项目可写文件。字段与按钮集合可通过虚拟 JSON 文档编辑，正文只替换明确的集合；项目过程函数可展开父层并在原文标记或物化方式下保存，保存前复核父层哈希，控制流不等价的物化需明确核对。

6. 索引与 AI 上下文

6.1 工作区事实索引

每个工作区在 context/index.db 建立派生索引，覆盖已拉取源码的对象、PAGE 节点和静态调用等可识别事实。查询结果有范围和截断边界；无法识别的动态行为需继续核验源码与平台。

索引空间

索引可重建；清理或重建前核对工作区并保留源码和基线。索引结果不代表平台或业务执行结果。

6.2 检索与有界上下文

有界查询入口

API 提供 catalog、search、context、callers、facts 和 explain；MCP 对同一工作区提供查询。读取时检查路径、源码哈希、覆盖范围与分页，不把未检出对象视为不存在。

7. Guthon Nexus

7.1 工作区与源码

Nexus 提供项目配置、API 登录、范围选择、源码树、差异、上传和冲突入口；项目状态与实际能力以安装构建和当前工作区为准。项目与项目各用自己的窗口。源码树使用系统、数据源名称及菜单层级组织 PAGE，目录名称来自同一项目缓存；原始目录与文件路径保持不变。菜单缓存独立保存，登录或查询菜单后更新。

项目详情卡片

Nexus 侧栏顶部的“项目详情”面向当前窗口中的单个项目。未登录时，卡片提供平台地址、账号、密码、“保存密码”和“登录”；平台要求验证码时显示验证码输入。登录后紧凑显示项目、版本、地址和用户，版本与用户来自当前会话或最近登录记录；窗口无法唯一确定项目时显示打开项目源码目录的提示。

登录后的卡片提供“更新源码”和“上传代码”，并显示子系统范围、源码数和修改数；范围选择及项目状态仍从项目树进入。源码数统计当前范围内的文件状态项，修改数统计其中非 CLEAN 状态，可能包含冲突、缺失等状态，须查看项目状态核对。更新按钮要求已配置地址并选择子系统；上传按钮要求范围内存在可写的已修改文件。按钮可用不代表上传回读或业务验收已通过。

7.2 语言与导航

GSS、JavaScript 和 SQL 的补全、悬停及定位结合官方语言资源和 Nexus 快捷输入。PAGE 与过程函数可按精确身份定位；浏览器相关能力需要配对 Bridge。

视图 SQL 编辑

打开视图默认显示 SQL 虚拟文档，使用 SQL 语言服务、定位和行内差异。保存前核对视图编码、原文件哈希、租约和候选，只修改原文件的 /viewSql，其余 XML 或 JSON 原文保留；不会生成另一套可上传 SQL 文件。缺少 SQL 节点的官方视图默认展示原始 XML，不生成空 SQL；需要显式编辑完整定义时使用原始源码入口，并校验当前对象身份。真正的继承文件或身份冲突继续只读。保存只更新本地 checkout，上传与结构同步仍是独立操作。

7.3 工具更新

工具、Nexus 和 Bridge 按各自更新流程核验并生效。官方语言能力更新从 Open VSX 检查资源，临时编辑器展示版本、兼容性和结果；该入口仅替换经验证的资源，不安装官方扩展或替换后端协议。下载、启用和实际生效分别确认。

8. Guthon Bridge

8.1 页面能力

Chrome 扩展提供字段复制、列表滚动、页签排序、网页导航和当前对象定位；按需通过本机 Bridge 定向刷新已匹配的 API 对象。当前对象导出到独立目录，已有不同内容的同名文件不会被覆盖。API 核心使用不要求安装 Chrome 扩展。

标签排序

拖动顶部功能标签或 PAGE、过程函数编辑标签可调整同一行内顺序，首页和菜单固定。上层顺序按平台来源保存在扩展中，下层仅保留本次页面会话；只移动标签头，不重建编辑器。仅支持已识别的标签栏。

8.2 路由与安全边界

服务使用本机 Bearer 配对；浏览器扩展校验来源，页面上下文和工作区路由需匹配。PAGE ID、过程包名和函数名通过 Nexus URI 传递，候选需由当前项目目录消歧；Nexus URI 接线和已安装客户端仍需验证。未知或未匹配对象不扩大刷新范围。

9. API MCP

9.1 入口与能力

AI 客户端可通过 mcp --stdio --home <toolHome> 启动 API MCP；使用 --read-only 限制为查询。每次请求使用明确 workspaceKey，按当前项目索引和文件读取，具体工具以客户端发现的清单为准。

MCP 文档租约只返回有界正文前缀；大文件会给出截断与后续偏移，完整读取使用 read_source 分页并核对同一文件哈希。预览差异也标识截断，候选摘要始终绑定完整候选，不应把正文前缀当作完整文件写回。

9.2 查询与受控修改

查询包含源码目录、内容、调用方、事实、PAGE 节点、字段与设计契约；查询结果需检查当前文件哈希、分页和覆盖边界。受控本地修改通过 open_document、preview_document、write_document 和 close_document 使用租约、预览和幂等键；结果未知时查询原操作，不盲目重放。

PAGE 结构编辑

可先检查设计契约和候选，再预览字段、按钮、事件、数据源及布局调整；具体可操作范围以返回契约为准。修改与平台上传分开，引用、平台往返保存和业务行为需要核验。

9.3 验证边界

本地索引、文件写入与 API 回读均不能单独证明平台编译、发布或业务执行。客户端接线、真实目标和安装包需分别验证。

10. guthon-team 治理

10.1 安装与更新

团队治理通过团队 Marketplace 中的 guthon-guard 插件分发。插件在新任务的 SessionStart 阶段检查工作区并幂等初始化：已是当前版本时不重复写入，缺失或版本更新时补齐规范、Linter、API 索引和配置。支持 Hook 的客户端还需对插件 Hook 完成信任；不支持 Marketplace 或 Hook 的环境可使用同一发行物中的独立安装器。

治理安装面向业务 var 工作区，不写入 GuthonCodeTool 源码仓库。核心 AGENTS、规范正文和 guthon-lint 即使没有 Marketplace 或 Hook 也能使用，Hook 只负责自动选择检查时机。

Release 中的 guthon-testing.zip 可单独安装到客户端 Skills 目录；普通用户可使用工具内置只读连接器，无需为此安装 DBX/MCP。首次在 Nexus 为目标工作区配置专用只读数据库账号，Skill 安装不代替连接与环境身份配置。其源码与适用范围见 Guthon Testing Skill。

10.2 规范门禁

规范层AGENTS 与权威标准说明业务语义、开发模式、方言 API 和允许的写入范围。
判定层guthon-lint 用稳定诊断码检查受保护路径、非法 API、Velocity 结构、赋值、重复保存和 SQL 兼容性。
时机层Agent Hook 在任务与工具生命周期检查，Git Hook 在提交前兜底；需要时可把同一 CLI 接入 CI。

版本清单和文件哈希用于判断规范是否完整、是否被本地修改以及升级是否安全。人工修改不会被静默覆盖；强制更新前先备份。私有 API 索引使工具能明确判断函数是否存在，避免用通用语言经验猜测谷神方言。

治理采用“语义规范 + 可执行 Linter + 生命周期 Hook + Git/CI 兜底”，因为提示词只能提醒，不能稳定证明每次修改都经过同一规则。Linter 通过只代表已覆盖的静态规则通过，不代表数据库、平台编译、上传或业务流程已经验证。

从业务 cwd 执行 Linter 的 --changed 时只检查当前工作区；Git pre-commit 的 --staged 检查整个暂存集合。两者使用 runtime descriptor 的明确入口，静态门禁不扩大业务源码的发布或数据写入权限。

11. 构建、发布与验证

11.1 发行物

Windows 的 GuthonCodeSetup 下载清单与首次配置统一见 Windows 安装步骤第一章：一键安装配置。默认一键安装器采用精简联网模式：内置后端、Nexus、Bridge、独立 Python 与安装指南；复用已有 CodeBuddy、Git，仅对缺失工具从固定官方 HTTPS 地址下载并校验 SHA-256。下载失败可重新运行，已校验缓存会复用。首次安装缺失工具时需要联网；离线完整包仍可由维护者按原流程构建。单独安装或修复仍可采用手动流程。

Python 应用使用 PyInstaller 构建，并内置公开配置模板与版本信息：Windows 为单文件 EXE，macOS 为目录形态（onedir）。Nexus 发行模式统一选择可执行文件：Windows 选择 EXE，macOS 进入完整应用目录选择同名启动文件。构建必须在目标系统执行，以生成 Windows x64 应用和 macOS ARM64 应用。发布流程同时完成：

  • 运行 Python、Nexus 与 Bridge 的相关测试。
  • 打包 Guthon Nexus VSIX 和 Guthon Bridge Chrome ZIP。
  • 打包公开的 guthon-testing Skill。
  • 为应用与组件生成摘要和签名元数据，并发布 GitHub Release；Gitee 镜像单独同步并核验附件完整性。

Release 不包含真实配置、凭据、业务源码、私有索引、日志或 guthon-team 内容。工具应用可以替换升级，用户的 toolHome 保持不动。

平台支持与发行完整性

正式发行面向 macOS Apple Silicon 和 Windows x64，不提供 Intel Mac 包。根目录 VERSION 是统一版本来源；GitHub Actions 构建两平台应用、Python zipapp、依赖清单、VSIX、Chrome 扩展、Skill、checksum 及签名元数据。发布说明按私有模板准备，不把私有草稿提交到公开仓库；CI 使用经检查可公开的提交说明或手动传入正文。

更新仅允许 HTTPS 和受约束重定向，下载与哈希流式处理，核对 API digest、checksum 和实际文件。Nexus 从 data/release-trust.json 加载固定 Ed25519 公钥（当前 key ID 为 guthon-release-20261004），员工无需配置。签名缺失、伪造或哈希不一致时阻止新候选执行，保留已有安装；维护者的本机 globalStorage/release-trust.json 信任文件只能增加明确公钥，不可替换已有 key ID 或放宽包内强制策略。后端没有配置公钥的独立校验路径须明确报告“签名未验证”，不能冒充 Nexus 强制验签。

签名 CI 使用 GUTHON_RELEASE_SIGNING_PRIVATE_KEY 与 GUTHON_RELEASE_SIGNING_KEY_ID，私钥与包内公钥不匹配、或强制策略所需密钥缺失时拒绝发行。签名覆盖应用、pyz、VSIX、Chrome 扩展和 Skill；scripts/verify_release.mjs 可用从可信渠道取得的公钥离线验收。首次安装仍需可信分发渠道，发行签名不等同于 macOS/Windows 系统代码签名，也不能证明程序无漏洞。

Gitee 镜像与 GitHub 发行独立同步：scripts/sync_release_to_gitee.py --tag <tag> 先验签，补传缺失附件，再逐项下载核验 hash；中断可按同一 tag 继续，不重建已发布资产。令牌保存于系统钥匙串；维护流程和备用工作流见 镜像同步说明，Windows 构建入口见 统一安装器构建说明。

11.2 验证边界

验证证据能够证明的范围
Python、Nexus 或 Bridge 自动化测试源码级命令、路由和组件行为；不能证明已安装 VSIX、真实浏览器或远端服务。
MCP stdio 协议与临时项目夹具协议握手、工具发现及夹具中受控读写的结果；不能证明 AI 自动路由、已安装 VSIX、Windows 或真实平台运行。
打包应用 self-test发行物可启动、可解析内置资源并能在临时目录完成基础设置。
SQLite 索引与静态事实当前本地源码快照中的对象、关系和可识别规则；不能证明运行时分支一定执行。
数据库只读查询指定目标和时点的数据库记录；不能证明页面版本、缓存或业务流程结果。
API 上传与回读回执记录各对象的上传与回读状态；部分完成或未知状态需继续核对，平台最终提交、编译、发布和运行另行取证。
guthon-lint 通过已实现的静态治理规则没有发现问题；不能替代平台或业务验证。
