一、一键安装配置

Windows 用户使用 GuthonCodeSetup 安装 GuthonCodeTool、GuthonNexus 和 GuthonBridge。安装时可以选择一个或多个本机 IDE。首次打开 Guthon 工作区时确认信任。团队规则和浏览器增强按需配置。

推荐阅读路线：

优先使用 GuthonCodeSetup。完成本章安装及首次配置向导后，无需重复第二至第四章的手动安装和工具初始化；这些章节用于单独安装或修复。第六章是后续在 GuthonNexus 接入业务工作区的参考，按工作需要使用。

个人账号登录和工作区信任按本章完成。需要团队同步时再授权内网仓库，需要网页增强时再加载 Chrome 扩展。安装完成后按第五章检查核对；业务接入见第六章，安装问题见第七章。

1.1 从 GitHub Release 下载哪些文件

打开 GitHub Releases，进入同一个版本的 Assets（发行附件）。安装器内置后端、Nexus、Bridge 和所需 Python。缺少 Git 时按提示联网安装。先下载下表文件。

文件是否需要用途
GuthonCodeSetup.exe必需统一 Windows x64 安装与首次配置入口。
GuthonCodeSetup.sha256必需同一发行版安装器的 SHA-256 校验文件。
guthon-testing.zip按需仅在需要独立安装数据库排查 Skill 的 Agent 中使用；按对应 Agent 的 Skill 安装方式配置。

使用统一安装器时，GuthonCodeTool-windows-x64.exe、guthon-nexus-vscode.vsix 和 GuthonCodeTool-chrome.zip 已包含在套件中。有团队 Git 地址时，可在安装助手中授权并同步。

安装前核对下载文件

将安装器和同版校验文件放在同一目录，在 PowerShell 执行：

$expected = ((Get-Content .\GuthonCodeSetup.sha256 -Raw).Trim() -split '\s+')[0]
$actual = (Get-FileHash .\GuthonCodeSetup.exe -Algorithm SHA256).Hash
if ($actual.ToLower() -ne $expected.ToLower()) { throw '安装器校验不匹配，请重新下载' }

摘要匹配用于检查文件完整性；下载来源和正式发行签名仍需按团队分发说明核对。

手动安装或单独修复时下载哪些文件（可选）

仅在采用第二至第四章手动流程或单独修复组件时，在同一个 Release 下载以下文件：

  • GuthonCodeTool-windows-x64.exe：后端应用。
  • guthon-nexus-vscode.vsix：GuthonNexus 扩展。
  • GuthonCodeTool-chrome.zip：Chrome 的 Bridge 扩展。
  • GuthonCodeTool-checksums.txt、GuthonCodeTool-checksums.signature.json、GuthonCodeTool-release.json：同版摘要、签名和组件清单，供离线核验和更新流程使用。

需要独立数据库排查 Skill 时再取 guthon-testing.zip。CodeBuddy、Git 从各自官网安装；团队插件仍从内网市场安装。

1.2 运行安装器并打开安装助手

  1. 双击 GuthonCodeSetup.exe，在“选择 IDE”勾选要安装 GuthonNexus 的编辑器。可多选已检测到的 VS Code、CodeBuddy 国内版或国际版、Trae、Qoder。若提示未检测到 IDE，点击“打开 CodeBuddy 国内版官网”，安装 Windows 版后重新运行 GuthonCodeSetup。
  2. 选择工作数据目录，通常使用默认值。公开包的“团队插件市场”地址可留空。团队提供地址时可填写，或由团队通过 GUTHON_TEAM_MARKETPLACE_URL 预置。
  3. 点击“安装”，等待安装器把 GuthonNexus 安装到所有勾选的 IDE，完成后查看安装结果。若系统要求为 Git 安装授权或重启，按提示操作，重启后重新运行同一个安装包。
  4. 打开已安装 GuthonNexus 的 IDE，从“文件”菜单打开工作数据目录下的 Guthon.code-workspace。完成页的“查看安装结果”也会列出完整路径。按 IDE 提示登录并信任工作区，再从活动栏打开 Guthon Nexus，在安装配置助手中检查运行环境。

检查标准：GuthonCodeTool 与 GuthonNexus 卡片显示通过。无需自己安装 Python 或配置系统环境变量。

1.3 配置部门规则（按需）

公开安装包的团队 Git 地址留空时，工具检查通过后即可点击“完成配置”。需要使用部门现有规则时，从助手点击“打开开发目录”，按部门说明把 AGENTS.md、rules/ 等放在这里。安装前已放入的规则会保留。已配置团队 Git 地址时，按以下步骤同步：

  1. 连接公司网络或团队提供的 VPN。点“打开内网 Git 网站”，填写团队网站地址并登录；没有账号或没有仓库权限时，先联系管理员开通。
  2. 如果市场使用 SSH 地址：点击“生成或复制 SSH 公钥”。向导保留已有密钥，只把公钥复制到剪贴板；到 Git 网站“用户设置 → SSH/GPG 公钥”新增并粘贴保存。私钥不上传、不发给别人。
  3. 点击“首次连接授权”。终端提示服务器指纹时，先与团队提供的指纹核对，再确认信任。HTTPS 来源按终端或 Git 凭据管理器提示登录，跳过 SSH 公钥步骤。
  4. 点击“同步团队规范”。仓库访问通过后，助手直接安装规则、Linter 和 Git pre-commit。此卡片显示通过后可以完成配置。

需要 Agent 生命周期检查时，按手动安装团队插件安装 guthon-guard 0.5.0 或更新版本，并用“检查 Hook 运行”核对实际触发。

1.4 在现有 Chrome 加载 GuthonBridge（可选）

需要网页增强时继续本节。

  1. 需要额外平台主机规则时可点“平台地址规则（按需）”；否则使用已配置的默认规则。此项不作为安装完成条件。
  2. 点“打开 Chrome 扩展管理”，打开后启用右上角“开发者模式”。
  3. 点向导“定位并复制扩展目录”。回到 Chrome 点击“加载已解压的扩展”，在文件夹选择器粘贴该目录并选择。
  4. 在 Chrome 工具栏的扩展按钮中打开 GuthonBridge；可以将它固定到工具栏。
  5. 回到向导点“复制配对令牌”。在 GuthonBridge 展开“本机 Bridge 配对”，粘贴令牌，点击“保存并连接”。令牌只用于你的本机，不发送给别人。
  6. 点“检查浏览器连接”。基础检查和已配置的团队同步通过后，点“完成配置”。

检查标准：本地 Bridge 服务运行，当前托管扩展发出了认证连接心跳。扩展文件存在、或浏览器显示“已加载”，都不能单独替代此项检查。

已有 Chrome 的首次加载需要本人操作；安装器不修改浏览器策略。已经加载后改变平台地址，需要到扩展管理页重新加载 GuthonBridge。后续版本通过 Nexus 更新固定托管目录。

1.5 完成安装，后续使用 GuthonNexus

日常使用时，在任一已安装 Nexus 的 IDE 中打开 Guthon 工作区，从活动栏进入 Guthon Nexus。IDE 的“打开最近的项目”菜单可用于重新打开此前使用过的工作区。

完成本页检查后，可按安装后接入工作区继续连接 API、SVN 或 DATABASE 项目。

1.6 自动安装失败时的手动恢复

现象处理
Git 自动安装失败按安装结果页的官网链接手动安装 Git，然后重新运行 GuthonCodeSetup。
内网仓库访问失败确认公司网络、账号仓库权限、公钥登记和首次服务器信任。到“首次连接授权”终端查看具体提示。
插件已安装但 Hook 仍待完成确认工作区与 Hook 信任，更新市场插件，重载插件并开始新聊天。当前市场需要包含支持向导回执的版本。
Chrome 无法加载扩展选择“定位并复制扩展目录”给出的完整目录，确认该目录直接包含 manifest.json。
Chrome 开发者模式被公司策略禁用由管理员按公司的扩展部署方式安装 GuthonBridge；向导不会绕过浏览器策略。安装后继续配对与连接检查。
配对后没有连接保持运行 Nexus 的 IDE 窗口打开，重新复制本机令牌并保存连接；确认两边端口一致，然后再次检查。
发现人工配置冲突保留原文件，请维护者合并；不要直接删除配置或强制覆盖。

官网下载：CodeBuddy 国内版 · Git · Chrome

安装完成后应看到什么

以当前安装助手显示的工具和插件检查结果完成配置；网页辅助需要时再核对浏览器连接。需要接入项目时，继续查看安装后接入工作区。截图仅说明按钮位置，版本和状态以本机界面为准。

二、手动创建并信任工作区目录

本章为手动安装参考。已完成第一章工具及插件环境配置时可跳过；单独安装或修复时再使用。

1

新建目录并在 CodeBuddy 中信任 操作示例

  1. 手动配置时，在 D:\Develop\GuthonWork 中新建开发目录，例如 var，也可使用自定义目录名。
  2. 在 IDE 选择「文件 → 打开文件夹」，直接打开这个开发目录。出现工作区信任提示时核对目录。
  3. 把后端 EXE 放在本地数据目录，IDE 打开其中的开发目录。例如 D:\Develop\GuthonWork\GuthonCodeTool-windows-x64.exe、D:\Develop\GuthonWork\var。

三、手动安装并设置 Guthon Nexus

本章为手动安装参考。已完成第一章工具及插件环境配置时可跳过；单独安装或修复时再使用。

从 最新 Release 下载同版 GuthonCodeTool-windows-x64.exe 与 guthon-nexus-vscode.vsix，放入 D:\Develop\GuthonWork。配置生成在上一级目录的 config 下，继续使用已打开的开发目录。

3

图形界面安装 VSIX 操作示例

  1. 在 CodeBuddy 左侧点击「扩展」图标，点击扩展栏右上角 … → 从 VSIX 安装…。
  2. 选择 D:\Develop\GuthonWork\guthon-nexus-vscode.vsix。安装结束后在 CodeBuddy 扩展列表确认出现 Guthon Nexus，版本与下载的同版 VSIX 一致。
  3. 如图标未立即出现，在 CodeBuddy 使用「开发人员: 重新加载窗口」或关闭后重新打开 CodeBuddy。
4

在 Nexus 中初始化数据目录 操作示例

  1. 确认 Git 可用，打开 Nexus 并点击“初始化此文件夹”。核对显示的开发目录及其上一级数据目录。
  2. 接入已有项目时，通过“连接已有数据目录”选择原数据目录并核对同步方式。首次初始化会自动识别上一级的 GuthonCodeTool-windows-x64.exe；缺少后端时选择其运行目录。已配置的窗口可从“项目总览 → … → 工具设置 → 切换本地数据目录”更换目录。取消选择或确认时，保留原入口和数据目录配置。
  3. 新目录初始化时，按提示确认并同步团队规则。查看 Nexus 完成提示，再检查开发根的规则和 Linter；已有目录核对总览能读取项目。
  4. 全新目录初始化后，开发根的上一级应出现 config\guthon.json。准备使用 SVN 时，运行 svn --version --quiet 核对本机客户端，并从 Nexus 的“环境检查”确认工具能找到它。

四、手动安装团队插件

已完成一键安装向导的用户可以跳过。这里是 CodeBuddy Agent 插件市场，和安装 Nexus 的 VSIX 扩展面板不同。

  1. 连接团队要求的内网或 VPN，取得个人 Git 账号及团队 Marketplace 地址。
  2. 按团队的 SSH 或 HTTPS 方式建立访问；SSH 只登记本机公钥，私钥不上传。使用团队地址核对首次服务器指纹。
  3. 在 CodeBuddy 打开“插件 → 插件市场”，添加团队提供的插件源，选择 guthon-team 并安装 guthon-guard。通常选择“用户”范围。
  4. 确认插件和 Hook 信任，重载插件，并从本地数据目录的 var/ 打开新聊天。
  5. 按使用手册的治理检查步骤确认状态为 ready，以及新聊天中的 Hook 已运行。非 Git 工作区也可以安装规范和 Linter，无需为此创建 Git 仓库。

未使用 Marketplace 或自动初始化失败时，按手动与无 Hook 安装处理；不要套用旧截图中的账号、仓库地址或业务路径。

五、安装完成检查

  • 已选 IDE 的扩展面板中可找到 GuthonNexus，Guthon 工作区已信任。
  • 同版后端与 Nexus 就绪，Nexus 能启动工具并读取本地数据目录。
  • 已配置团队 Git 地址时，确认规则和 Linter 已同步。使用部门手工规则时，按部门要求检查文件位置及客户端生效情况。需要 Agent 自动检查时，在新聊天中确认 Hook 运行。
  • 按需完成浏览器增强配置。在安装助手点击“检查浏览器连接”，确认 Chrome 扩展加载和配对成功。详见首次加载和配对步骤。

使用统一安装器时，以安装助手的检查结果为准。采用手动安装时，分别核对上述结果。业务连接、项目源码索引、Git 提交时的检查结果、API 上传和平台运行按实际任务另行检查。

六、安装后接入工作区

在 CodeBuddy 或 VS Code 打开已配置的开发目录，确认 Nexus 的“项目总览”能读取登记。新数据目录的总览为空，接入已有数据目录时可核对原项目与同步方式。

  • 添加并登录 API、SVN 或 DATABASE 项目
  • 保存同步范围后手动更新源码
  • 迁移已有数据目录或项目

后续日常使用

在 Nexus 总览选择项目，按使用手册操作。需要给 Agent 接入源码时，查看源码 MCP 配置。

七、安装问题入口

先看安装结果页或“输出 → GuthonCodeTool / Guthon Bridge”的首条失败信息，再按现象查对应问答：

  • Windows 权限、架构、Git 命令与安全软件问题
  • Nexus 不显示或后端启动失败
  • 初始化团队规范提示 9009 或找不到 Python
  • 团队市场访问、插件或 Hook 问题
  • Chrome 扩展与 Bridge 配对问题
