# API 工作空间客户端隔离验收

本记录区分原生客户端事件、源码开发宿主、插件安装与平台验收，不将它们合并为发布结论。

## 测试环境与方法

- Codex CLI/TUI 0.169.1：独立临时 Codex 数据目录，使用本地 guthon-team 候选 0.5.0，通过原生 Hook 审阅并信任；未使用跳过 Hook 信任或关闭子进程沙箱的参数。
- CodeBuddy CN 1.106.1：Nexus 2.8.1 源码开发宿主，构建摘要 `c3ef4db14c0dcd429939af30ed8dfa13edaaf4b5baecb3244754f72eb79ec909`，使用现有编辑器账户。临时工作区配置独立 toolHome，禁用自动 Bridge 和更新检查。
- 两种临时空间分别覆盖首次创建的 rules 布局、既有 docs 布局；各有稳定 key 的两个假工作区，目录名包含 checkout 和用户自定义中文名称。平台地址为不可连接的 fixture.invalid，全部源码为本地夹具。
- 根 AGENTS 在团队受管块外放置独立随机标记，要求客户端在不调用读取工具时报告标记；标记不出现在用户提问中。原生 Hook 外层仅记录事件并透传输入、输出与退出码，业务门禁仍执行原脚本。

## 已观察到的结果

| 检查 | 实际证据与边界 |
|---|---|
| Codex 父规则加载 | 从具体工作区目录启动，原生 prompt-input 包含父 AGENTS；模型分别报告新、旧空间的正确随机标记，未读取文件。 |
| Codex 原生 Hook | TUI 捕获 SessionStart、UserPromptSubmit、apply_patch 的 PreToolUse/PostToolUse 及 Stop，临时文档写入和独立回读通过。exec 的文件写入结果单独记录，不以其成功代替完整 Hook 证据。 |
| CodeBuddy 根规则加载 | 打开旧布局 var 根，新对话报告正确标记；普通文档使用内置 Write/Edit 完成，未调用 shell 或平台。 |
| Nexus 项目切换 | 根窗口未选择时提示选择；同一窗口切换两个工作区，打开源码内容和物理路径分别匹配各自 key，var 根不变；重新加载窗口后恢复已选工作区。 |
| CodeBuddy 保护反例 | 原生 Write 试图写入假工作区 checkout，PreToolUse 返回 GUTHON000，客户端显示生成失败；独立文件检查确认目标未创建。 |

## 本轮发现与修复

CodeBuddy IDE 的会话事件 cwd 是 var，文件工具 Write/Edit 的事件 cwd 却可能是 `/`；Hook 命令本身的启动目录仍为 var。旧实现只按事件 cwd 查找治理入口，会跳过写前、写后检查。现在在该位置找不到 Guthon 工作区时，通过 Hook 实际启动目录定位治理和状态；工具相对路径仍以原事件 cwd 为基准。回归同时覆盖受保护路径、写后至 Stop 的检查、相对路径语义及没有文件路径的 MCP 调用。

当前 CodeBuddy IDE 普通聊天未执行 CLI 的 `/reload-plugins`；维护说明改用宿主“开发人员: 重新加载窗口”后新建对话。

## 尚未覆盖与安装注意

本机 CodeBuddy 的旧已安装团队插件仍可能执行旧规范安装逻辑，仅配置本地 Marketplace 目录没有替换其已安装内容。隔离验收在项目配置中禁用旧插件，并接入同一候选源码的项目 Hook；没有改写日常插件缓存。该证据验证了原生事件与当前门禁脚本，不证明候选插件已通过 Marketplace 安装或分发。

Codex 桌面应用、Windows、正式安装包、真实 API 登录、拉取、上传及平台业务效果未在此轮验收。保持既有源码修改；未暂存、提交、推送或发布。

## 入口选择专项验收（2026-11-19）

本次使用 CodeBuddy 的 Nexus 源码开发宿主和独立临时工作区。两个临时可执行包装入口分别启动真实 SVN/main 与 api-sync 后端源码，两者都通过 Nexus 的版本检查及 self-test；全部 --home 指向假数据目录，没有读取业务 var、执行 SVN 提交或连接平台。

- 已有有效旧 SVN 后端时，设置新数据目录仍弹出后端选择框。
- 取消目录选择、取消后端选择时，旧目录文件、配置和运行描述与初始字节摘要一致，新目标仍为空。
- 真实窗口发现最后“执行”确认取消时曾提前保存新 toolPath，留下旧目录与新入口混用。已将运行入口选择改为准备结果，初始化或目标读取成功后再保存；修复后在确认框出现前设置未变，取消后全部旧文件摘要一致。
- 执行成功后，当前窗口保存新 API 入口与新 toolHome，新目录生成 schema 2、var Git 根和空规则目录；旧 SVN 业务配置、文档及旧运行描述保留。核心修复在真实开发宿主构建 `4cf853baf53c034d26cb3420eaed2e0060820643f8b7db369bd6dc9b4c8e1666` 中验证。
- Native MCP 向导在仍打开旧 var 时拒绝写入新配置；在新 var 中生成 guthon-api，命令和 --home 均属于新目录，其他服务及旧 SVN 条目保留，旧 var 的 .mcp.json 未变。
- CodeBuddy 首次实际对话无法看到新服务。原生 MCP 页面及日志确认原因是项目审批状态 pending，而非配置路径错误；核对只读入口后选择“仅本次允许”，新对话实际调用 guthon-api/read_source 并返回新目录夹具的唯一随机标记。向导提示与使用说明已补充审批和客户端回读要求，不自动批准服务。
- 在旧目录运行的隔离 Bridge 随成功切换重启，状态中的 exportRoot 属于新目录；旧令牌访问新服务返回 401，新令牌访问通过。打开新 var 后再次从 Nexus 启动，仍指向新目录。没有改动日常 Chrome 的配对设置。

以上是源码开发宿主及本地假数据的运行证据，不替代正式 VSIX、Windows、真实平台登录、源码拉取或上传验收。全局 CodeBuddy 运行设置保持不变；未暂存、提交或发布。


## PAGE 编辑器主题实测（2026-11-19）

按本轮用户要求，在已经打开的 CodeBuddy CN 1.106.1 窗口安装并重新加载本地 VSIX，使用原有 API 后端与现有 PAGE 验证。最终已加载 Nexus 2.8.1，构建标识为 `sha256:60db1562e80b9df9696427b2ba7bba910a54f94c05a155a3cbf925ef4ed887b4`；安装目录的页面样式及入口代码与本轮源码逐字节一致。此轮主题结论来自现有客户端窗口，不来自临时工作区或静态预览。

- **浅色+**：普通按钮和项目卡片操作使用浅灰表面、主题文字和细边框；主操作保留主题主色。选中页面按钮及对应树节点的文字与高亮背景清晰可辨。
- **深色+**：普通按钮继续使用主题提供的次要按钮配色；页面按钮及树节点选中高亮正常，属性面板不可上移按钮保持禁用显示。
- **只读比较**：两种主题中，保存到本地、撤销和重做均由实际页面状态禁用，仍能辨认文字并与可用按钮区分。
- **恢复现场**：退出只读比较，恢复原“浅色+”主题及当前页面编辑视图；页面状态仍为已保存到本地，本地比较没有内容差异。未执行源码保存、上传或平台业务动作。

实测同时发现，前端曾把 `guthon.json` 文件存在性当成所有已配置后端的运行前提，使能够正常列出项目的旧 API 后端被隐藏。已将该入口改为核对显式 toolHome 和可执行入口，具体配置有效性由所选后端校验；新工作空间初始化的 schema 2 规则保留。原后端、业务目录和旧配置未转换，原项目重新显示并可打开 PAGE。

以上证明本轮 VSIX 在当前 macOS CodeBuddy 中的 PAGE 主题显示和旧 API 后端入口恢复；不代表新的 API 后端能读取旧配置，也不替代 Windows、平台拉取、保存、上传和业务运行验收。既有未提交改动保留，本轮未提交或发布。

## V1.1 多项目与 SVN→API 隔离验收（2026-11-20）

CodeBuddy CN 1.106.1 在独立用户数据目录加载从 VSIX 解出的 Nexus 2.8.1，构建标识为 `sha256:b3ef3d69228b44bf6f71e6ab55e9a5b85b5e9984371da6b024f23719c0c25511`。测试使用本地 SVN 仓库、合成 DATABASE 索引和回环 HTTP API，通过扩展宿主记录 CodeBuddy 实际请求的树节点、Webview 渲染和编辑器打开结果。

- 打开临时 `var/` 根，检查项目总览、当前项目卡片和当前项目源码。总览显示四个有效项目及一个配置异常项目。切换 API、DATABASE 和 SVN 后，三个视图的项目归属与操作一致。API 登录后可更新源码，干净状态的上传按钮禁用。DATABASE 显示本项目过程函数与工作副本入口。SVN 显示本项目源码树与提交入口。
- 选择配置异常项目后，卡片显示已登记名称和 `CONFIG_INVALID`，提供检查配置与刷新入口，源码操作停止。点击检查配置打开临时数据目录实际使用的 `config/guthon.json`。修复了首屏加载时提前显示空列表、异常项目名称丢失及搜索无法按异常项目名称命中的问题。
- 关闭临时 CodeBuddy 后，用正式迁移命令对一个 SVN 夹具执行候选准备与切换，再用同一隔离配置重开 `var/`。窗口恢复原 `workspaceKey`，总览仍有同一个项目且同步方式变为 API。未登录时可展开本地源码树。登录后从源码树打开新 checkout 中的过程函数，核对正文及原 SVN 文件均与预期一致。修复了未登录时源码树误报菜单加载失败的问题，实际的菜单请求错误仍会显示。
- Nexus 向导写入临时根目录的 CodeBuddy `.mcp.json`。按其中的只读命令和参数启动 MCP，发现 37 个工具，通过 Nexus 当前项目会话完成模拟平台的在线只读探测，并用 `read_source` 回读相同 key、路径、正文和摘要。本次回读使用该配置的 stdio 服务，未发起 CodeBuddy 业务聊天。
- 相关 Python 回归 51 项和 Nexus 全量回归 648 项通过。Windows、真实平台和正式业务目录未参与本轮验收。
