# 发行模式新增 SVN 产品或项目

## 操作步骤

1. 在 Guthon Nexus 的“工作区”或“项目”区域点击“添加产品或项目”。
2. 选择产品或项目，填写名称和稳定 ID。
3. 选择源码来源“SVN”。Nexus 创建工作区后结束向导，不会读取其他产品或项目的 checkout 脚本。
4. 展开新建的 Nexus，点击“设置工作区 SVN 登录”保存公共用户名。密码在首次远程操作时输入，由 SVN 原生认证缓存管理，不写入 YAML。
5. 点击“导入/粘贴 SVN checkout 配置”：
   - 选择“粘贴 SVN 地址或命令”，在临时多行编辑器中逐行粘贴一个或多个纯 URL、`<url> <localSubdir>` 或完整 `svn checkout` 命令；支持从 Markdown 复制的 `- `、`* `、`+ ` 列表前缀。粘贴后保存并关闭编辑器，再在提示框中选择“解析 SVN 范围”或“编辑配置 SVN 范围”；输入过程不会触发解析，空内容也不会报解析错误。命令中的用户名等认证参数不会写入配置。
   - 选择“导入 checkout 脚本”，再选择当前产品或项目自己的 `.sh` 或 `.bat` 文件；Nexus 只解析 checkout 命令，不执行脚本。
   - 同一产品的多个 checkout 地址会归并为一个公共 `svn.url`；每条地址去掉公共前缀后的唯一相对路径逐条写入 `svn.scope`，重复行只保留一次。
6. 点击“编辑 SVN 范围配置”核对全部精确 scope。`systems.include.mappings` 可不配置，此时检出所有地址，并根据 `$.中文名称` 与系统、数据源 `index.md` 自动推断 SCM 业务分组；证据不足的系统或数据源各自单独成组。配置 mappings 后则按 alias、`system_id` 和 `data_source_id` 筛选范围并使用显式关系。SVN 模式不使用 Bridge 拉取。
7. 再次点击“设置工作区 SVN 登录”并输入密码，然后执行“从 SVN 范围配置检出/更新”。核对预览中的地址、条目数和增删改数量，确认后检出并建立索引。若账号只缺少个别 scope 的权限，Nexus 会记录并跳过这些项，继续处理其余地址；网络中断或整体认证失败仍会报错停止。
8. 索引完成后展开“谷神源码”。不同数据源对应不同数据库 schema，表、视图和过程函数允许同名；Nexus 会按数据源 working copy 精确区分并打开。PAGE_ID 仍按产品或项目工作区全局去重。

## 删除不再需要的工作区

在产品或项目节点上右键选择“删除产品或项目”。确认框会列出要删除的配置和目录；确认后目录移入系统废纸篓，并移除对应工作区配置、独占数据源和数据库排查配置。取消确认不会修改任何文件。

## 常见检查

- `svn.url` 应为所有 scope 的公共根地址，`svn.scope` 应保留粘贴或导入的全部去重相对路径。
- 没有 `systems.include.mappings` 时，精确 scope 不会被过滤；该配置仍保留分类简写、显式筛选、命名和旧流程兼容能力。
- 单项无权限或远端不存在会显示为已跳过，后续重新检出会再次尝试。
- “谷神源码”为空或索引过期时，执行“扫描/重建本地 SVN 索引”。
