## 改进建议

1. **优先修正验证环境与夹具。** 从本地通用 Python 测试发现中排除已移出的独立 `guthon-guard` 旧测试，或迁到其所属仓库；补齐驾驶舱夹具的 `datasourceReady`。随后重跑 Python 全套，恢复一个可解释的绿色基线。
2. **给文档发布增加自动校验。** `.github/workflows/pages.yml` 当前只复制三份 HTML 并检查非空；建议在部署前校验 HTML 内部与跨页锚点、QA 数据项 ID 唯一、分类值有效、内嵌 JavaScript 语法和公开内容脱敏。此次 QA 的旧链接和旧安装命令正是这类检查应捕获的例子。
3. **统一版本与模式提示。** Nexus `extension.js` 的“检查更新”在任一非发行模式都提示“调试模式直接使用源码”，但开发模式使用源码、调试模式使用 Release pyz。建议按实际模式给出准确提示，并在 UI 中直接显示当前入口、版本与 toolHome，降低路径切换后的误判。
4. **补足安装后的跨组件验收。** 为正式发行流程建立 macOS/Windows 的应用、VSIX、Chrome 扩展和 MCP 小型冒烟矩阵，分别验证 ToolHost、工作区列表、Bridge health 与实际页面、MCP 握手和工具数；数据库和 SVN 路径使用受控测试目标。源码测试通过后仍需这层证据。
5. **改善故障定位。** 让 Nexus 的失败反馈提供当前运行模式、目标 workspaceKey、失败阶段和对应输出通道；对索引 `PARTIAL` / `REBUILD_REQUIRED` 提供明确的单文件或工作区重建入口，对 MCP 幂等写入失败突出原操作查询。这样 QA 的处理步骤可直接从错误跳转。
6. **定位 SQLite 资源警告。** 为索引连接和相关测试夹具检查关闭边界；仅在找到真实未关闭路径后修改代码，避免把测试警告误修成新的连接管理分支。

1. **跨 PAGE 表列契约与有证据补全。** 已有跨 PAGE UI 字段发现，但 `tableId/columnId` 仅来自 PAGE 自身配置，不能证明数据字典的真实表列或页面间引用。需要真实平台 API/Schema 及样例验证后，才考虑跨 PAGE/表列自动补全，并标注来源、置信度和未解析关系。
2. **变更前后证据对比：已实现受控预检的第一步。** `preview_page_nodes` 与 `preview_page_field_insert` 在同一租约绑定源码快照上复用索引事实提取器，对比候选源码的表访问和显式字段关系，返回有界增减、工作副本及前后哈希。尚未提供 Nexus 普通虚拟编辑器里的交互式候选预检；平台实际运行仍需单独验证。
3. **浏览器到 Nexus 的一键定位：源码层已实现。** Bridge 从激活 PAGE 页签传递编码，Nexus URI handler 复用既有精确定位流程并要求当次选择 SVN 工作区与多候选源码。受控 SVN 测试工作区的实机样例证明编码与索引可匹配；新扩展尚未重新安装并联调外部协议打开过程。
4. **平台与运行验证证据回填。** 成功提交目标文件并取得 SVN revision 即完成源码交付；后续编译、发布和业务运行可按需要分别取证。接入这些证据前，应先确定平台事件、结果标识和来源，避免把源码交付回执误写成运行结果。
5. **索引事实质量反馈。** 对误报、未解析关系和动态调用线索收集“源码片段 + 解析器版本 + 预期解释”的本地复现样例；扩展索引器前以有界夹具验证，避免把业务特例硬编码进通用方言规则。

## 已安装环境的 PAGE 跳转排查续记

用户在 Chrome 模块开发页点击“在 Nexus 定位当前 PAGE”后，Chrome 唤起 VS Code，但 Nexus 没有响应。本机原安装的 Nexus 2.3.0 是旧构建：安装目录中的 `package.json` 缺少 `onUri`，`src/svn/activate.js` 缺少 URI handler；源码与已安装扩展同为 2.3.0，因此版本号不能单独证明能力已安装。已从当前工作树重新打包 VSIX，强制安装并重载 VS Code；新安装目录已核对包含上述入口。

随后在已安装 Nexus 的命令面板用平台当前 PAGE ID 验证，工作区选择正常出现，但选择目标 SVN 工作区后后端返回 `requestKind does not match command`。根因是 Nexus ToolHost 客户端的 SVN 只读动作清单漏掉 `page-query`，而 Python ToolHost 已将其定义为只读；同一个 PAGE 定位动作因此在协议边界被拒绝。已补齐客户端动作分类与回归断言。该错误也会影响复用 `page-query` 的 PAGE 语义浏览、影响证据上下文和跨 PAGE 字段查询，不能仅作为浏览器问题处理。

修正后的 VSIX 已再次打包、强制安装并重载。在已安装 Nexus 的命令面板输入平台当前 PAGE ID，选择用户指定的 PRD SVN 工作区后，源码树定位到同 ID 的 JSON，并实际打开该 PAGE 的 `.sql` 虚拟分块；原协议错误不再出现。Nexus 全套 177 项测试通过，其中新增了 `page-query` 的只读分类断言。

## 左下角按钮组加载时机优化

用户反馈首次打开谷神开发平台后左下角按钮组出现很慢。源码检查发现扩展原在 `document_idle` 注入，首次检查又可能早于 SPA 开发页签生成；原实现仅监听 URL 变化，页签在同一路由内异步出现时只靠 30 秒轮询补救，而且刷新会先等待页面桥接，再插入按钮。现改为 DOM 解析完成时注入、监听页面页签变化并合并触发刷新；按钮组先挂载，页面桥接与工作区模式按需异步确认，原轮询保留作兜底。新增晚到页签触发的回归检查。已验证源码逻辑，真实 Chrome 安装态仍需刷新扩展后观察首屏耗时。
