macOS M1 及后续型号与 Windows 的 Nexus 操作相同。GuthonCodeTool 本身不要求克隆源码、安装 Python、安装 Node.js 或创建虚拟环境。

1. 安装

1.1 准备与下载

Windows 的 GuthonCodeSetup 下载清单与首次配置统一见 Windows 安装步骤第一章：一键安装配置。使用统一安装器的用户先完成该页向导；本章后续步骤用于 macOS 或手动安装。

下载前确认：

  • 手动安装需准备 VS Code 或 CodeBuddy，以及对应系统的应用；需要网页辅助时再准备 Chrome。
  • 使用 guthon-team 治理时，另需内网 Git 个人账号和团队 Marketplace 权限，详见第 3 章。
  • 接入源码时准备谷神平台账号；使用数据库诊断时另准备明确的数据库目标和只读连接。

打开 GitHub Releases 或 Gitee Releases ，在同一个版本下载：

  • macOS M1 及后续型号：GuthonCodeTool-macos-arm64.zip，解压得到单文件 GuthonCodeTool
  • Windows x64：GuthonCodeTool-windows-x64.exe
  • VS Code 双模式扩展 Guthon Nexus：guthon-nexus-vscode.vsix
  • Chrome 扩展 Guthon Bridge：GuthonCodeTool-chrome.zip
  • 按需使用数据库开发/测试库验证时，下载 guthon-testing.zip 并按 Skill 说明安装。
  • 团队规范与开发门禁由独立的团队 Marketplace 分发 guthon-guard，不在 GuthonCodeTool Release 中。

将应用和 VSIX 放在同一个上级目录，在其中自建开发目录。首次就在 VS Code 打开开发目录。初始化后，配置保存在其上一级。图文步骤见Windows 安装步骤。

text 
GuthonWork/
├── GuthonCodeTool              # macOS 单文件，Windows 放 GuthonCodeTool-windows-x64.exe
├── guthon-nexus-vscode.vsix     # 从 VSIX 安装时选择
├── config/                     # 初始化后生成
└── 研发源码/                    # 第一次就用 VS Code 打开这里，也可命名为 var

1.2 安装应用

macOS

  1. 确认 Mac 为 M1 或后续型号：可在“关于本机”中查看。
  2. 解压下载的 ZIP，将其中的 GuthonCodeTool 放到开发目录的上一级。
  3. 在当前开发目录点击“初始化此文件夹”，Nexus 会在上一级自动识别 GuthonCodeTool。
  4. 如果启动文件没有执行权限，在终端执行：
bash
chmod +x "/你的数据目录/GuthonCodeTool"

若系统阻止运行，请先确认文件来自本项目 Release，再打开“系统设置 → 隐私与安全性”，对被阻止的 GuthonCodeTool 选择“仍要打开”。

Windows

  1. 把 GuthonCodeTool-windows-x64.exe 放到工作区根目录，例如 D:\Develop\GuthonWork\。
  2. 不要放进经常清理的“下载”或临时目录。
  3. 若 SmartScreen 拦截，先确认文件来自本项目 Release，再选择“更多信息 → 仍要运行”。

1.3 安装 Nexus

  1. 打开 VS Code 的“扩展”面板。
  2. 点击右上角 ...，选择“从 VSIX 安装...”。
  3. 选择 guthon-nexus-vscode.vsix。
  4. 安装后执行“Developer: Reload Window”或重新启动 VS Code。
  5. 确认左侧活动栏出现“Guthon Nexus”图标。
  6. 使用旧版 Nexus 的用户可先从 VSIX 安装同版新扩展，再选用单文件后端。

1.4 设置工作空间

首次使用 Nexus 时，先在本地数据目录下新建一个开发目录。目录可叫 var，也可用自己的名称。用 VS Code 或 CodeBuddy 直接打开这个开发目录，在 Nexus 点击“初始化此文件夹”。初始化需要 Git，会把当前打开的目录建为 Git 根，并在它的上一级生成配置。

  1. 已连接的窗口可从“项目总览 → … → 工具设置 → 切换本地数据目录”更换目录。刷新项目总览可重新读取已登记项目。
  2. 从当前开发目录初始化时，卡片会列出开发目录及其上一级数据目录。接入已有工作空间时，通过“连接已有数据目录”选择包含 config/ 的上一级目录。如果选中了已绑定的开发根，Nexus 会连接其上一级数据目录。每个数据目录绑定一个开发根，已有绑定继续使用原路径。
  3. 点击“初始化此文件夹”，Nexus 会检查开发目录上一级的 GuthonCodeTool 或 Windows EXE。如果还没有选定入口、上一级也没有运行文件，先选运行方式，再按提示选择对应入口。使用发行模式时，macOS 选择解压后的 GuthonCodeTool，Windows 选择 EXE。初始化成功后，当前工作区会关联上一级数据目录。
  4. 确认信任当前目录并连接公司网络。按提示输入团队提供的 Git 克隆地址。首次访问按内网 Git 接入步骤开通权限。等待 Nexus 显示“工作区已初始化，团队规则和开发门禁已同步”。此时即可在根目录查看 AGENTS.md、rules/ 和 tools/guthon-lint。
  5. 初始化后留在当前开发目录，点击“立即添加”，或在“项目总览”点击“添加项目”。日常继续打开这个目录。

切换到另一个文件夹时，Nexus 会核对当前文件夹与全局数据目录的归属。当前窗口若明确连接另一个位置的数据目录，该连接保存在这个窗口的工作区设置中。

从“项目总览 → … → 工具设置 → 选择运行方式”切换当前工作区的运行方式。切换到“发行模式”时，核对当前数据目录中的应用，或按提示选择解压后的可执行文件。需要调试 pyz 时按下节操作。源码开发的入口见运行模式参考。在另一 IDE 中继续使用同一工作空间时，连接原来的本地数据目录。

初始化调试模式

  1. 确认本机装有与 Nexus 架构相同的 64 位 Python 3.12 或更新版本。Intel Mac 使用 x86_64 Python。首次准备依赖时需要联网。
  2. 从同一个正式发行版下载以下四个文件并放在同一目录：GuthonCodeTool-python.pyz、GuthonCodeTool-python-requirements.txt、GuthonCodeTool-checksums.txt 和 GuthonCodeTool-checksums.signature.json。
  3. 在“项目总览 → … → 工具设置 → 选择运行方式”选择“调试模式”，只选择 GuthonCodeTool-python.pyz。Nexus 会校验附件、创建隔离环境并安装依赖。等待“已切换为调试模式”后继续操作。

新工作空间初始化完成后，项目总览为空。团队规则和开发门禁已同步到开发根，可用“项目总览 → … → 工具设置 → 团队规则同步”手动更新。接下来添加项目。

2. Nexus

以下截图实拍于 VS Code 的「PRD 期现产品」。点击截图可放大。平台地址、账号及内部编码已遮盖。

2.1 添加项目并登录

  1. 用 VS Code 或 CodeBuddy 打开已初始化的开发目录。在 Nexus 的“项目总览”点“添加项目”，输入项目名称。如果已在开发根的 workspace/ 下准备好项目目录，输入相同的目录名。
  2. 选择 API、SVN 或 DATABASE。登记成功后，已有 docs/ 及其中的文档会保留在原处。点击总览中的项目行打开“当前项目”卡片。
  3. 在卡片填写对应来源，点击“登录”。
  • API填写谷神开发平台地址、账号和密码，按提示填写验证码。希望后端重启后恢复会话时勾选“保存密码”。升级后如需继续使用以前保存的账号，可在此重新登录。
  • SVN填写有权访问的 SVN 仓库地址、用户名和密码。需要先安装 SVN 客户端时，可从“环境检查”确认。
  • DATABASE填写谷神主库的 MySQL 或 PostgreSQL 地址、只读用户名和密码。标准谷神主库可使用新数据目录的默认字段映射。自定义表结构见源码连接与范围参考。

旧项目或配置需要调整时，先查看迁移路径。

选择同步范围并更新源码

  1. 登录后，在当前项目卡片点“同步范围”。API 选择全部或指定子系统，DATABASE 选择主库中的子系统。SVN 按数据源名称选择关联的子系统，“公共源码”和“开发建议”可单独选择。
  2. 保存选择，再手动点击“更新源码”。首次选择和之后调整范围都按此顺序。在“输出 → GuthonCodeTool”查看进度。操作结束后，到“项目源码”浏览结果。
  3. 缩小范围时，“更新源码”会清理退出范围内的同步副本。API 或 SVN 提示有本地修改、草稿或冲突时，先处理提示中的文件，再点击“更新源码”。DATABASE 的 Workcopy 保留。

只更新一部分源码时，在“项目源码”右键相应节点，选择“同步此节点源码”。共享数据源、退出范围清理和异常处理见范围参考。

2.2 切换和管理项目

从上到下查看“项目总览”“当前项目”和“项目源码”。点击项目行同步切换卡片和源码树。总览筛选只影响列表，已打开的编辑器和草稿继续属于原项目。

当前项目卡片

从卡片查看同步范围、源码数量和本地修改，打开搜索源码、本地修改、操作记录、同步范围、索引管理和环境检查。

点击“搜索源码”并输入关键词。API、SVN 清单模式和 DATABASE 项目可点搜索框右上角的漏斗，选择“页面”“过程函数”“表”或其他类型。切换类型会保留关键词并重新查询，选“全部类型”可清除筛选。API 项目可在列表末尾选择“加载更多结果”。在 DATABASE 项目选中带脚本路径的结果并回车，Nexus 会打开对应的代码编辑器并定位到命中行。

  • 看本次拉取和索引结果时，打开“操作记录”或 GuthonCodeTool 输出。SVN 首次签出中断后，可在原项目重新点击“更新源码”。如仍失败，查看SVN 签出中断问答。
  • 需要重新解析全部本地源码时，在“索引管理”选择“重建索引”。API 源码树出现“索引不完整”时，左键查看诊断，右键选择“修复索引”重试有诊断的项，或选择“重建索引”做全量重建。另有“等待索引更新”提示时，可点击提示重试该批文件。
  • 出现“配置异常”时，先查看当前项目卡片的错误码。提示“状态扫描期间源码已变化”时，查看状态扫描问答。卡片提示配置有误时，点“检查配置文件”，处理后刷新项目总览。

项目设置

从“当前项目 → … → 项目设置”配置源码连接、查看项目配置或修改同步方式。尚无源码、索引或操作记录的项目可以直接换模式。已有源码的 SVN 或 DATABASE 项目可切换到 API 并重新拉取。API 退出登录前，先保存并关闭打开的在线页面编辑器，再在同一菜单选择“退出登录”。在原窗口重新登录时，先核对卡片回填的账号。需要换账号时，直接编辑账号输入框。

在项目总览右键选择“删除工作区”。先保存项目文件和页面草稿，再核对预览并确认。目录仍在时会先移入废纸篓。若已在 IDE 外移走项目目录，同一入口可清理项目登记。删除当前项目后，卡片和源码树会清空，可回到总览选择其他项目。

标题栏更多功能

点击相应面板标题栏右侧的「…」。带右箭头的菜单项可展开，截图中的「项目设置」和「源码工具」以 API 项目为例。

项目总览
当前项目

登录当前 API 项目后，选择「当前项目 → … → 源码工具 → 检查系统菜单结构」。此操作会拉取平台菜单、打开菜单 JSON，并刷新项目源码树中的菜单归类。已拉取但未挂到菜单的页面，可在对应子系统下的“未归入菜单”打开。

项目源码

智能体或外部编辑器保存源码后，如果变更标记没有更新，点击“项目源码”标题栏的刷新按钮（悬停显示“刷新当前源码视图”），然后在树中核对本地修改标记。

选择 AI 任务目标

在 Agent 会话中明确指定项目名称或 workspaceKey，同名项目用 key 区分。使用源码 MCP 时先查询这个 key 对应的源码工具组。CodeBuddy 可继续打开开发根，Codex 可打开具体项目目录。

已启用并信任 guthon-guard Hook 时，如果提示任务目标冲突，在原业务会话中单独发送 /guthon-use <注册名称或 workspaceKey>。看到 Hook 回显期望的「Guthon 任务目标」后，继续受控保存。显式切换后的续问沿用所选项目。若编辑器还开在原项目目录，引用文件时使用所选项目的绝对路径。机制和适用条件见规范门禁。

3. guthon-team

Nexus 初始化会把团队规则和本地开发门禁同步到工作区。需要 Agent 在新对话中自动准备和检查工作区时，在对应客户端安装团队市场里的 guthon-guard，然后审阅并信任 Hook。

3.1 从插件市场安装

从公司网络或 VPN 访问团队市场。首次添加时使用团队提供的 Marketplace 地址和个人仓库权限。Windows 可先按首次连接授权完成 Git 认证。

Codex 安装

  1. 在 Codex 桌面端打开插件目录，切换到团队市场 guthon-team，安装并启用 guthon-guard。
  2. 列表中没有团队市场，或正在使用 Codex CLI 时，查看首次登记市场与 CLI 安装。
  3. 安装后按信任 Hook 并新建对话操作。

CodeBuddy IDE 图形化安装

  1. 用 CodeBuddy IDE 打开 Guthon 开发根。在 CodeBuddy 面板进入「插件 → 插件市场」。
  2. 第一次安装时点击「＋」打开「添加插件源」，填入团队提供的 CodeBuddy 市场地址并提交。市场列表已有 guthon-team 时，直接选择它。
  3. 在 guthon-team 找到 guthon-guard，点安装。日常使用可选「安装（用户）」，需要限定在当前项目时选「安装（项目）」。
  4. 确认插件显示已安装。通过命令面板执行「开发人员: 重新加载窗口」，再打开新对话并核对 Hook 状态。

带自定义端口的内网 SSH 市场需要 CodeBuddy 可识别的地址。团队若提供 SSH 主机别名，按原样填入；添加失败时看内网连接补救。使用 CodeBuddy Code CLI 的用户可查看CLI 安装。

3.2 信任 Hook 并新建对话自动安装

  1. 在 Codex 桌面端从输入区的「审阅 Hook」或「设置 → Hooks」进入审阅。Codex CLI 使用 /hooks。CodeBuddy IDE 按宿主提示打开插件或 Hook 审阅入口。
  2. 核对 Hook 来自团队市场里的 guthon-guard，审阅实际命令后点击信任。插件更新后如再次提示审阅，按同样步骤确认。
  3. 在已用 Nexus 初始化或接入的开发根（默认 var/）或其中已登记的项目目录发起一个新的本地 Codex 对话。
  4. 新对话的 SessionStart 会识别 Guthon 工作区，并自动安装或更新团队规则、API 方法索引和本地 Linter。开发根本身是 Git 根且配置无冲突时，也会安装 Git pre-commit。文件已经就绪时，可能没有重复安装提示。

首次自动安装如果更新了 AGENTS.md，再新建一次对话，让 Codex 从启动阶段读取最新入口。Codex 的审阅入口及事件定义见Hooks 官方说明。

3.3 确认安装和 Hook 已生效

  • 核对插件在当前客户端已启用，并且新对话打开的是正确的工作区。查看工作区根的 AGENTS.md、适用的 rules/ 或 docs/ 规范目录和 tools/guthon-lint。
  • 新对话中看到自动安装或更新提示后，核对入口文件。如规则原本已就绪，可在对话中请 Agent 检查当前工作区治理状态，只查看，不修改。需要确认 Hook 本次确已执行时，核对客户端记录或 .guthon/hook-runtime.json 中对应新对话时间的 SessionStart 回执。
  • 如提示人工文件冲突或使用其他 Git Hook 路径，保留已有文件，并按提示核对冲突。已有 CODEBUDDY.md 的项目也应确认客户端实际读取了开发根规则。

安装成功、客户端读取规则和 Hook 执行分别检查。更多排查见团队规范问答。

3.4 手动补救与无 Hook 安装

4. Bridge 网页辅助

4.1 安装 Chrome 扩展

需要网页辅助时加载 GuthonBridge 扩展；Windows 首次加载见安装步骤。日常源码同步、编辑和检查可以直接在 Nexus 完成。需要已登录页签的操作会指明当前动作；按下节完成配对后继续。

4.2 启动与配对

  1. 更换本地数据目录前，在持有旧 Bridge 服务的 Nexus 窗口点击“项目总览 → … → 停止浏览器增强”，等待停止；同一端口不能同时监听两套数据目录。端口仍被占用时，按端口占用问答核对原窗口和进程。
  2. 在目标数据目录对应的 Nexus 窗口点击“项目总览 → … → 启动浏览器增强”（命令面板名称为“Guthon Nexus: 启动 Guthon Bridge”），等待启动成功，再点击“复制配对令牌”。
  3. 在 Chrome 扩展弹窗的配对设置中填写与 Nexus 相同的端口、粘贴配对令牌，点击“保存并连接”。确认显示“Bridge 配对成功”；默认导出目录应属于当前本地数据目录，若使用自定义导出目录则核对已配置的位置。
  4. 更新或重新加载 Chrome 扩展后，先保存平台编辑再刷新平台页面；执行一次所需的只读定位，核对返回工作区与对象。

4.3 使用网页辅助

在受支持的谷神页面，可以复制字段、滚动列表和拖动标签排序。与 Nexus 配对后，可定位当前 PAGE 或过程函数，并按需定向刷新 API 源码。适用范围见Bridge 功能说明。

在模块开发的页面后台脚本中，按住 Ctrl（macOS 为 Cmd）点击可识别的过程函数调用。过程函数打开后，点击页面顶部浮条的“返回页面”，回到发起跳转的 PAGE。

5. 源码 MCP（按需）

5.1 准备索引

在 Nexus 选中目标 API、SVN 或 DATABASE 项目，完成同步范围设置和源码更新，确认“项目源码”可用。SVN 源码 MCP 需要清单式工作副本。

5.2 配置客户端

  1. 在 CodeBuddy、Trae 或 VS Code 打开开发根、目标项目目录或 checkout，从“当前项目 → … → 配置 MCP”选择正在使用的客户端。
  2. 选择所需能力。只查源码选“仅查询”，需要本地编辑选“允许受控本地修改”，任务涉及可用的平台工具时选“完整 MCP 能力”。具体能力见源码 MCP 参考。
  3. 核对配置预览中的目录和能力，确认合并 guthon-source-helper 服务。

让 AI 编辑 API PAGE 时，在当前 Nexus 项目登录。AI 打开编辑租约时会按需加载该页的原生源码，再用租约返回的版本预览和保存。已有本地差异或冲突时，先在 Nexus 核对目标页，再请 AI 重新读取。原生 PAGE 准备条件。

Codex 的 MCP 配置与切换

Codex 使用原生 MCP 配置。将示例中的路径替换为发行应用启动文件及本地数据目录。开发模式和 pyz 模式使用 Python 可执行文件，并在 mcp 前传入脚本或 pyz 路径。

text
codex mcp add guthon-source-helper -- "<后端启动文件绝对路径>" mcp --home "<本地数据目录>" -- --stdio --provider auto --read-only
codex mcp get guthon-source-helper

有本地编辑授权时可省略 --read-only。需要平台工具时按平台工具启动选项配置。Agent 的 Hook 信任按团队治理步骤操作。

重连并确认切换结果

  1. 在客户端信任并重连新服务。CodeBuddy 从“我的 MCP”核对并批准项目的 guthon-source-helper。
  2. 新建对话，传入目标 workspaceKey。先调用 get_workspace_source_capabilities 核对同步方式及工具，再回读一个已同步的对象。
  3. 从旧 MCP 迁移时，确认新服务覆盖所需工作流后，再移除同一客户端里已经不用的旧入口。

5.3 查询与受控修改

查询时使用返回的工具组定位对象。编辑时先检查目标与预览，再保存并回读。平台上传、提交及生效按对应工作流执行。无法连接服务或识别工作区时，查看源码 MCP 问答。

使用 Agent 首次创建 DATABASE PAGE 的 Workcopy 时，先读取目标 PAGE 的只读基线，再调用 database_create_workcopy。返回 CREATED 后即可编辑和回读；返回 EXISTS 时继续使用已有副本。启用团队写入门禁时，后端与 Guard 都需支持Workcopy 创建回执。

6. 日常工作流

6.1 更新、编辑与交付源码

开始修改前，从总览选中项目，核对来源和同步范围。需要从远端更新时点击“更新源码”，或只同步目标节点。查看操作记录并处理冲突后开始编辑。

  • API

    如果更新后文件显示“冲突”，在“项目源码”中右键点击冲突文件，选择“处理 API 源码冲突”。在“源代码管理”的“谷神 API 源码”存储库中，直接点击文件名前有“【冲突】”的条目，或从右键选择同一命令。需要原生 PAGE 时，Nexus 会自动更新选中的页面。若更新后仍有冲突，会继续打开对比。左侧是本地已保存的版本，右侧是同步记录的平台版本。结构化 PAGE 默认显示可读差异，需要核对 XML 时，选择“查看原始源码对比”。核对后选择“保留本地内容”或“采用平台内容”并确认。如果要合并两边的改动，选择“打开原始源码手工合并”，保存后再打开冲突并选择“保留本地内容”。处理完成后核对本地差异，按需上传。冲突处理参考

    1. 保存改动后，在“源代码管理”选中当前项目的“谷神 API 源码”存储库。点击文件查看差异。右键选择“查看原始路径”，可以查看和复制原始的相对路径或绝对路径。
    2. 如需只上传部分文件，可在“本地变更”选中已审阅的文件，点击所选文件行右侧的“+”，或右键选择“暂存 API 源码”。要暂存本组全部可上传源码，点击组标题右侧的“全部暂存”。文件会移到“暂存区”。
    3. 在面板顶部填写上传备注（可选），点击“更改”标题栏的“上传源码”。有暂存文件时列出暂存区文件，暂存区为空时列出全部可上传的未暂存文件。需要单独上传未暂存文件时，右键“本地变更”组并选择“上传全部未暂存”。核对确认框中的项目、文件和备注，再点击“上传”。
    4. 上传后核对逐项回执与平台回读。PAGE 待核对时可先点“更新源码”。若报告确认该页已保存，只需审阅和上传剩余改动。结果仍未知时，查询原操作记录并核对平台。按业务要求在平台完成最终提交、编译和运行验证。

    两组的文件行都可打开原文件。暂存区的“−”会取消所选文件的暂存，本地变更的“还原”会列出所选文件并等待确认。组标题右侧可打开该组全部原文件、取消全部暂存或还原全部本地变更。也可右键审阅并上传所选修改，或从项目卡片的“上传代码”选择文件。模块参数使用独立的预览上传入口。支持的文件类型和暂存限制见API 源代码管理参考。

  • SVN在“源代码管理”中选择当前项目的“谷神 SVN 源码变更”，点击文件，在左右两栏核对修改。PAGE 脚本按行展开，核对原文时右键选“查看 SVN 原始差异”。文件右侧的撤回或提交图标用于操作当前文件。子系统右侧的图标用于操作该组，“更改”标题栏的图标用于当前 SVN 项目。点击更新后确认远端变更范围，批量撤回或提交前勾选文件。提交时填写说明并核对确认框中的文件清单。完成后从操作记录查看回执，并按项目流程核对谷神平台生效。已同步公共源码时可浏览单据类型和下拉组件，继承过程函数可从右键查看父层源码。SVN 差异与操作范围
  • DATABASE在源码树点击服务组件，直接在 GSS 编辑器中查看或编辑 compScript。点击普通页面打开本地页面编辑器，也可展开页面并打开事件脚本、SQL 或过程函数。首次保存会建立对应工作副本。重新打开普通页面时，Nexus 会读取磁盘上的工作副本并保留窗口草稿。若提示“外部修改冲突”，先核对磁盘内容和草稿再保存。保存后，“项目源码”中的 M 标出本地修改，打开代码可查看相对只读基线的行标记。普通页面可在“比较改动”中按组件复制字段改动，也可在脚本或 SQL 的差异条目中点击“复制修改后片段”，到谷神平台对应节点粘贴。点击项目卡片的“查看工作副本”可另行生成交付材料。执行“导出单据类型”后，在项目的 database/billtype/ 查看 JSON，也可在源码树浏览已索引的单据类型。本地改动标记的范围

平台表或视图的结构同步会执行 DDL，按提示确认并单独核验结果。

API 项目的“页面”分类用布局图标标记普通页面，用闪电图标标记服务组件。通过普通页面左侧的箭头展开脚本、SQL、字段或按钮。API 结构化 PAGE 的悬停说明如果显示“批量下载 XML · 只读”，点击该页的“编辑页面”会为它加载原生模型；可右键“打开原始源码”查看批量下载的 XML。顶层“过程函数”分类右键可切换“列表平铺”和“树形结构”；数据源、过程包和函数节点没有此切换。函数节点左侧显示业务名称，右侧较小字号显示函数编码及可解析的签名，确认启用返回值时显示返回表达式，例如 [return $result]；无法可靠确定表达式时显示 [return 无]；() 表示确认无参数，(无) 表示无法可靠确定参数。格式及来源见过程函数展示说明。页面或过程函数右键选择“查看使用位置”可打开已索引的引用。新建函数从目标过程包右键进入，核对名称和选项后确认创建。

更新或上传期间打开“输出”，选择“GuthonCodeTool”，查看实际执行步骤和耗时；结果未知时从操作记录核对原编号。

审阅与手动上传 DATABASE 过程函数

  1. 在 Nexus 保存过程函数的工作副本。从“当前项目 → 本地修改”选择目标函数，点击“查看本地差异”或“检查上传候选（仅本地）”。没有可信编辑基线的历史副本可以比较或导出。
  2. 选择检查候选后，核对差异并点击“确认当前候选”。连接 Bridge 后，可选择“只读核对平台基线”。在已配对的浏览器中保留一个对应项目、系统和数据源的已登录谷神页签。
  3. 平台已启用手动上传时，先在谷神签出该函数。核对 Nexus 显示的平台、过程函数和版本，再点击“确认手动上传”。出现“平台与镜像均已核验”后，刷新源码树查看本地修改状态。按项目流程在谷神确认签入及运行结果。
  4. 显示“保存结果未知”或“平台已核验，等待镜像回拉”时，从“本地修改 → 核验原发布操作”继续核验该次操作。

手动上传适用于已有的非继承过程函数正文。平台配置和回拉条件见DATABASE 手动上传参考。

批量粘贴 DATABASE 页面字段改动

  1. 在 Nexus 保存 PAGE 工作副本，点击“比较改动 → 与 DATABASE 只读源码比较”。在比较标题下、第一条差异上方找到目标组件，点击“复制字段改动”。
  2. 在谷神模块开发中打开同一页面，选中对应查询表单、输入表单或表格组件。点击 Bridge 的“粘贴本地改动”，将剪贴板内容粘贴进输入框后点击“预览”。
  3. 核对页面、组件和预计改动，点击“应用到设计器”。检查平台编辑器中的字段和配置，再使用谷神设计器的“保存”。如预览报告冲突，按字段和属性核对平台与本地值后重新预览。

可批量应用的字段及限制

过滤和定位源码

点击源码树标题栏的过滤按钮，输入名称、编码或相对路径；匹配项及父目录会保留。清除过滤后恢复完整目录，过滤不改变拉取范围或上传集合。源码树右键可复制文件名、绝对路径、相对路径，或在系统文件管理器显示所属物理文件；原生资源管理器同步显示本地修改、冲突和名称提示。

在过程函数或服务组件原文的 @inherit() 上悬停可查看说明，按 Ctrl/Cmd 点击打开只读产品源码。继承已展开的代码标签提供“打开只读产品源码”入口；本地函数声明和调用可悬停查看紧邻注释。在 API、SVN 或 DATABASE 源码编辑器中，按住 Ctrl（macOS 为 Cmd）悬停在调用处的函数名上。看到下划线后单击，打开已索引的过程函数。查看支持的调用形式。

编辑 PAGE

  1. 在源码树右键目标页面，选择“编辑页面”；也可从资源管理器右键“用本地页面编辑器打开”，或在“重新打开方式”选择谷神本地页面编辑器。两种入口使用同一份页面草稿。已同步源码可离线编辑，无需登录平台。
  2. 编辑字段或代码，按需撤销、恢复和比较，然后保存并确认源代码管理中的本地差异。
  3. 需要使用官方在线设计器时，登录当前 API 项目并点击“在线编辑器”。如有未保存草稿，须先成功保存到本地；保存失败时处理提示后再打开。无需下载、导入或配置设计器资源缓存。
  4. 本地或在线编辑器的保存都只写入本地；需要提交到平台时，确认保存完成且没有后续修改，关闭在线编辑器，再使用“上传代码”，核对回读结果并到平台验证。

如提示源码已变化，先保留当前编辑并比较原文件。服务组件或不支持设计的页面使用源码入口；能力与限制见PAGE 编辑参考。

编辑视图 SQL

在当前项目源码树中打开视图，直接编辑 SQL 并保存；保存结果写回同一份视图源码。需要查看完整定义时使用“原始源码”入口。上传后若平台格式化或补充字段，核对更新后的本地差异；同步数据库结构仍需单独执行并确认。

源码树按页面、过程函数、表、视图、系统脚本、模块参数及已同步的单据类型、下拉组件和开发参考分类，再使用系统名称、菜单及数据源组织，可直接打开页面、过程函数和视图。仅含元数据的 PAGE 或没有 SQL 节点的视图默认展示原文；需要编辑原始定义时，右键选择“打开原始源码”。身份冲突或继承原文保持只读。

编辑、预览和上传模块参数

在“源码工具”选择“同步模块参数”，或从模块参数分类右键同步，先取得所选子系统的参数清单；按子系统展开后点击参数，联网加载该条详情并打开 data JSON 编辑器。可按编码或名称查找条目；参数内容以已加载的详情为准。需要查看模板和其他元数据时，右键打开原始源码，完整原文保持只读。

  1. 在 data 编辑器修改所需参数；模板和对象身份不在编辑范围内。
  2. 从参数右键选择“预览模块参数差异”，核对平台基线与当前输入；按 Ctrl+S（macOS 为 ⌘S）仅保存到本地，完成后检查源代码管理差异。
  3. 需要同步到平台时，右键选择“审阅并上传模块参数”，或使用“上传代码”选择模块参数范围。核对数量和签出提示，需要核对改动时点击“查看差异”，准备好后点击“确认上传”。
  4. 查看上传回读结果。需要时工具会普通签出，但不强制覆盖他人的签出、不自动签入。结果未知时从操作记录核对原编号，不直接重试；平台最终签入仍在原生平台完成。

平台参数或模板已变化、存在未保存输入、他人签出或旧操作待核对时，先保留本地输入并按提示处理。差异较长被截断时，应通过参数差异预览或源代码管理核对完整内容。详细边界见模块参数参考。

展开单据类型的数据源或下拉组件列表，点击条目可查看原文对应行；搜索可使用编码、名称和关联表。需要更新时，在条目或相应分组上选择“更新指定 API 源码”，完成后重新查看结果。导出时右键对应分类、数据源或对象；导出源码说明从源码视图标题菜单进入。单据类型完整定义导出需要数据库连接。选择开发参考分类的右键入口，再选择 API、页面结构或事件分组，查看当前项目的说明与示例；属性说明可在属性标签上悬停查看。资料缺失时先从“项目设置 → 配置官方参考资料”启用，再从“源码工具”选择“同步官方参考资料”；不同的本地内容会保留，处理方式见参考资料问答。

保存页面修改

页面编辑器保存到本地后，检查源代码管理差异；结构化页面的上传使用原生源码并独立回读，源码条目悬停可查看来源。原文来源待核验时先刷新并审阅差异；尚无原生源码版本的页面先在平台初始化，再重新同步。未保存代码或外部修改冲突应先保留并处理。需要直接整理字段或按钮集合时，使用“浏览 PAGE 代码节点”中的集合 JSON 编辑入口。项目过程函数展开继承源码时会在保存前核对父层；父层变化后重新展开。

检查在线编辑器连接

打开在线编辑器时，确认已登录当前 API 项目并能连接其平台地址。连接或草稿保存问题见页面编辑器问答。

比较修改并到平台验收

在本地修改或上传审阅中打开 PAGE 差异；可读差异展示页面内容变化，若需要核对格式或键顺序，选择“查看原始源码对比”。区分平台基线与本地已保存内容，以及本地文件与窗口草稿；存在冲突先处理再继续上传。平台效果按实际页面和业务过程验证。

6.2 数据库诊断与测试

需要排查时选择明确工作区和开发或测试目标，核对身份、连接与只读权限，再按计划执行查询或导出结果。详见数据库诊断参考。

6.3 更新工作流

通过 Nexus 核对工具组件的下载、安装与生效状态。官方语言资源更新会在临时编辑器显示版本与兼容结果；它不安装官方扩展。团队治理按其插件市场流程更新。

7. 迁移与使用检查

7.1 系统支持

按实际发行构建选择受支持系统；浏览器增强与数据库驱动根据使用需要单独配置。

7.2 迁移与删除

按需选择迁移方式。已有改动在平台生效、只想在原项目重新拉取时，使用切换到 API 并重新拉取。要保留 SVN 工作副本和交付历史时，使用对照迁移。要从空开发目录重新接入时，使用重新登记并迁移文档。

清理 SVN 工作副本锁

源代码管理出现“SVN 工作副本锁”时，先等其他 SVN 操作结束，再点击对应锁提示。确认锁已清理并核对本地修改后再继续提交。需要检查远端更新时，仍会先显示范围并等待确认。

重新登记项目并迁移文档

  1. 备份前保存并核对旧项目的本地修改。API 按原流程上传并回读，SVN 按原流程提交并确认谷神平台生效，DATABASE 将 workcopy/ 的修改按原流程交付并回写谷神平台。
  2. 关闭原工作区的写入工具。在本地数据目录下创建 backup/，将原 var/ 的全部内容（包括隐藏目录）移入其中，保留空的 var/。要在同一本地数据目录从空登记开始，使用已有的空白统一配置，或先将仍在生效的旧 config/ 单独备份到 backup-config/，再初始化新工作区。配置位置见配置参考。
  3. 打开新 var/，重新添加项目并选择 API、SVN 或 DATABASE。连接原源码来源，选择同步范围，点击“更新源码”，再通过“索引管理 → 重建索引”确认源码树可用。
  4. 选中新项目，从“当前项目 → … → 从原目录迁移”选择 backup/workspace/ 下的对应原项目目录。迁移后检查新项目的 docs/，再让各 AI 工具打开新目录。

若目标已有同名不同内容，先比较备份和新项目中的文档，处理冲突后重试。更多规则见文档迁移参考。

将已有项目切换到 API 并重新拉取

  1. 先把需要保留的源码改动同步到谷神平台，并保存项目里仍打开的文件和页面草稿。
  2. 从“当前项目 → … → 项目设置 → 修改同步方式”选择 API。使用旧 YAML 的项目会先预览并备份升级登记。
  3. 核对提示中的本地清理目录和保留的文档路径，确认已同步后点击“已同步，确认切换”。项目保留原登记身份及文档。旧源码、索引与运行目录会被移出项目并送入废纸篓。
  4. 在 API 项目卡片重新登录和选择同步范围，手动点击“更新源码”拉取并建立新索引。

保留旧 SVN 工作副本与交付历史的迁移

  1. 更新 GuthonCodeTool 后端和 Nexus，按需更新 Bridge 和团队插件。继续打开原数据目录的 var/，从“项目总览”选中原项目并记下 workspaceKey。先保存草稿、处理冲突和未知操作，按原流程提交 SVN 并在谷神平台完成上传和最终提交。记录 revision、平台生效结果及对应对象。

  2. 若使用旧 YAML 或 API schema 2，先按配置升级说明离线发布 schema 3，确认原项目仍为 SVN。用同一后端执行 svn-api-migration --home "<toolHome>" --workspace "<workspaceKey>" -- preflight，处理报告中的阻断项。

  3. 向同一命令的 prepare 动作通过标准输入传入目标地址 serverUrl、平台生效依据 platformEvidence 和 login 对象。login 包含 userId、password 和需要时的 randCode。使用支持遮蔽密码的输入方式；查看 plan，核对 key、API 地址、系统和数据源、候选覆盖、新旧路径以及每个待人工核对的对象。发现缺项或冲突时，先修正来源并重新准备。

  4. 关闭相关 IDE 窗口、旧 ToolHost、Bridge 和 MCP 会话及其他写入入口。执行 apply --offline --confirm "<planId>"；标准输入再次提供 login，并以 manualReview 对象逐项提供待核对的 SVN 相对路径及核对依据。平台或本机材料变化时重新执行 prepare、审阅新的 planId。中断后先运行 status；有待恢复事务时，停用写入入口并执行 recover --offline --confirm "<transactionId>"。动作参数均放在 -- 后。

  5. 重新打开原 var/。在总览确认同一个项目已显示为 API，检查当前卡片和源码树，登录并回读一个已核对的对象。按需配置当前模式的 MCP或重新配对 Bridge。AI 会话重新选择目标并确认实际加载的团队规则；日常修改按API 工作流保存、审阅、上传和回读。旧 SVN 工作副本和操作记录可继续用于历史追溯。

完整输入、核对范围和恢复机制见SVN 切换参考。

移动本地数据目录或删除工作区

移动已有 API 环境时，分别保存项目源码、本地数据目录、API 基线及所需凭据迁移材料；不要将密码直接复制到公开目录。升级后如 AI 客户端仍保留失效的旧源码服务配置，先核对该客户端的实际配置再移除；安装器保留已有人工配置。删除工作区前先审阅范围与保留内容。

索引空间

索引是派生数据；整理前核对项目并保留源码和基线。

7.3 遇到问题

查看当前构建、首条错误及目标身份，在问题解决中心按关键词搜索。

7.4 首次使用检查

分别确认工具启动、项目登录、范围、拉取与索引、编辑上传回读以及平台业务结果；各项互不替代。
