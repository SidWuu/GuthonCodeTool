i

macOS M1 及后续型号与 Windows 的 VS Code 操作相同；只有下载的应用和 SVN 签出文件不同。

普通使用不需要克隆仓库、安装 Python、安装 Node.js 或创建虚拟环境。

1. 准备与下载

开始前准备 VS Code、Chrome、产品/项目配置和公司提供的 AI 规范文件。DATABASE 模式还需要数据库只读账号；SVN 模式还需要 SVN 1.10+ 客户端、SVN 账号以及谷神平台下载的签出文件：macOS/Linux 使用 svnCheckoutHere.sh，Windows 使用 svnCheckoutHere.bat。两种文件均为正式支持格式。

打开 GitHub Releases 或 Gitee Releases ，在同一个版本下载：

  • macOS M1 及后续型号：GuthonCodeTool-macos-arm64.zip
  • Windows x64：GuthonCodeTool-windows-x64.exe
  • VS Code 双模式全功能扩展 Guthon Nexus All-in-One：guthon-nexus-all-in-one-vscode.vsix
  • Chrome 扩展 Guthon Bridge：GuthonCodeTool-chrome.zip
  • 内部配置文件和 AI 规范：从公司内部文档入口获取。

建议固定两个目录位置：

text 
应用目录：只放 GuthonCodeTool 应用、Guthon Bridge、Guthon Nexus
本地数据目录：长期保存 config、var、源码、索引和 Workcopy

2. 安装应用和 VS Code 扩展

2.1 macOS

  1. 确认 Mac 为 M1 或后续型号：可在“关于本机”中查看。
  2. 解压 GuthonCodeTool-macos-arm64.zip，将其中的 GuthonCodeTool 放入固定应用目录。
  3. 如果文件没有执行权限，在终端执行：
bash
chmod +x "/你的应用目录/GuthonCodeTool"

若系统阻止运行，请先确认文件来自本项目 Release，再打开“系统设置 → 隐私与安全性”，对被阻止的 GuthonCodeTool 选择“仍要打开”。

2.2 Windows

  1. 把 GuthonCodeTool-windows-x64.exe 放到固定目录，例如 D:\GuthonCodeTool\。
  2. 不要放进经常清理的“下载”或临时目录。
  3. 若 SmartScreen 拦截，先确认文件来自本项目 Release，再选择“更多信息 → 仍要运行”。

2.3 安装 VSIX

  1. 打开 VS Code 的“扩展”面板。
  2. 点击右上角 ...，选择“从 VSIX 安装...”。
  3. 选择 guthon-nexus-all-in-one-vscode.vsix。
  4. 安装后执行“Developer: Reload Window”或重新启动 VS Code。
  5. 确认左侧活动栏出现“Guthon Nexus”图标。

3. 设置工作空间

  1. 点击 VS Code 左侧“Guthon Nexus”。
  2. 展开“工作区”，单击“设置工作空间”。
  3. 在确认框点击“执行”。
  4. 选择当前系统的 GuthonCodeTool 应用。
  5. 选择长期保存私有数据的本地数据目录；可以选择空目录。
  6. 等待输出面板显示 GuthonCodeTool 完成：setup。

设置后，入口会变为“切换工作空间”。普通用户保持“发行模式”即可；只有工具维护人员才需要使用“调试模式”。切换工作空间不会删除原目录。

设置工作空间会创建缺失的五个配置模板，不会覆盖已经存在的配置。完成后目录为：

text
<本地数据目录>/
├── config/
│   ├── datasource.yaml
│   ├── products.yaml
│   ├── projects.yaml
│   ├── source-tables.yaml
│   └── sync.yaml
└── var/  # 第一次同步或放入 AI 规范后出现

4. 填写配置和放置 AI 规范

在“Guthon Nexus → 工作区 → 配置文件”中单击文件名即可编辑。优先使用公司提供的真实配置；不要把数据库密码、源码或配置提交到公开仓库。

  • datasource.yaml：填数据库连接；只用 SVN 时按公司模板保留。
  • products.yaml：填产品和子系统映射。
  • projects.yaml：填项目、所属产品和子系统映射。
  • source-tables.yaml：直接使用公司提供的文件。
  • sync.yaml：直接使用公司提供的文件，有特殊要求时再修改。

SVN 用户按下面操作：

  1. 在目标产品或项目上选择“源码来源：SVN”。
  2. 将 svnCheckoutHere.sh（macOS/Linux）或 svnCheckoutHere.bat（Windows）放到该工程的 context/ 目录。
  3. 点击“设置工作区 SVN 凭据”，输入同一份 SVN 账号密码。
  4. 点击“从签出脚本检出/更新 SVN”，核对范围后确认。
yaml
products:
  <产品ID>:
    name: <产品名称>
    datasource: <数据源键>
    systems:
      include:
        mappings:
          demo.system:
            system_id: SYS-DEMO
            data_source_id: "0000"
    page_origins: []

每个子系统只需填公司提供的 system_id 和 data_source_id。产品和项目要分别填写；不确定时请向配置管理人员确认，不要猜测或复制其他项目的 ID。

将内部 AI 规范保持原目录层级复制到本地数据目录，至少包括：

text
<本地数据目录>/var/AGENTS.md
<本地数据目录>/var/docs/GUSHEN_DEVELOPMENT_BASELINE.md
<本地数据目录>/var/docs/谷神模块开发规范.md
<本地数据目录>/var/docs/谷神方言API/custom.md
<本地数据目录>/var/docs/谷神方言API/java.md
<本地数据目录>/var/docs/谷神方言API/javascript.md
<本地数据目录>/var/docs/谷神方言API/sql.md

5. 首次初始化和同步

  1. 确认产品、项目各自的数据源和子系统范围正确。
  2. 点击“维护 → 检查本地环境”，确认输出没有 FAIL。
  3. 展开“项目”，确认产品显示为 PRD、项目显示为 PRJ。
  4. 在每个产品或项目节点选择“源码来源：DATABASE / SVN”；DATABASE 节点点击“同步工作区全部资料”，SVN 节点点击“从签出脚本检出/更新 SVN”。
  5. 等待输出面板显示“完成”；如果显示 FAIL，先按提示修正后再重试。

看到“完成”且项目树中没有红色错误即表示初始化成功。DATABASE 后续从 Workcopy 开发；SVN 后续从“谷神源码”开发。

6. 安装和启动 Bridge

只使用 VS Code 同步和导出功能时可以跳过本章。需要从谷神网页拉取当前对象、复制字段或快捷跳转时才需要 Bridge。

6.1 加载 Chrome 扩展

  1. 解压 GuthonCodeTool-chrome.zip 到固定目录。
  2. 按内部环境修改 extension/host-config.js，不要扩大到无关地址。
  3. 打开 chrome://extensions，开启“开发者模式”。
  4. 点击“加载已解压的扩展程序”，选择解压目录中的 extension。
  5. 把 Guthon Bridge 固定到 Chrome 工具栏。

6.2 启动本地服务

  1. 打开 VS Code 左侧“Guthon Nexus”面板。
  2. 单击“启动 Guthon Bridge”。Nexus 自动使用初始化时选择的应用和本地数据目录。
  3. 面板显示“运行中 · 127.0.0.1:17361”后即可使用；单击“停止 Guthon Bridge”可关闭服务。

普通用户不需要安装 Node.js 或打开终端。若 Bridge 无法使用，先点击“停止 Guthon Bridge”，再重新启动；仍失败时查看“输出 → Guthon Bridge”中的第一条错误。

7. 日常工作流

数据库模式

  1. 在“项目”树选择目标 PRD 或 PRJ。
  2. 点击“同步工作区全部资料”。
  3. 需要网页拉取时启动 Bridge，再从谷神页面拉取 Workcopy。
  4. 只修改 Workcopy，完成后点击“检查或打包 Workcopy”。
  5. 将确认后的内容复制回谷神平台，测试并提交。

SVN 模式

  1. 开始开发前，点击“从签出脚本检出/更新 SVN”。
  2. 从“谷神源码”打开 PAGE、过程函数或系统脚本。
  3. 修改后按 Ctrl+S（macOS 为 Cmd+S）保存到本地。
  4. 在 VS Code“源代码管理”中点击文件查看差异。
  5. 提交全部修改时点击分组上的提交按钮；只提交一个文件时点击该文件行的提交按钮。
  6. 更新全部或单个远端变更时，在“远程变更”分组使用对应的更新按钮。
  7. 看到 SVN revision 后，再到谷神平台完成最终提交。
!

Ctrl+S/Cmd+S 只保存到本地；出现冲突时不要强制提交，先联系负责人处理。SVN 提交成功也不等于谷神平台已最终提交。

“谷神源码”已按业务分组和 index.md 顺序排列，普通用户无需手工整理目录。可使用视图顶部的定位、跳转、搜索和刷新按钮。

首次重建索引后，AI 会先从索引定位页面事件、过程函数、单据对应表及写入条件，再按需要读取 checkout 中的局部源码；无需手工导出整套 Markdown 源码。

8. 系统差异和解决步骤

macOS

  • 当前支持 M1 及后续型号，Intel Mac 不支持。
  • 应用没有执行权限：执行 chmod +x 后重新选择应用。
  • Gatekeeper 阻止：确认下载来源后，在“隐私与安全性”中选择“仍要打开”。
  • 终端设置的数据库环境变量未被 VS Code 读取：从同一终端启动 VS Code，或按公司方式配置用户环境后重启 VS Code。

Windows

  • 当前只提供 Windows x64 EXE。
  • SmartScreen 阻止：确认下载来源后使用“更多信息 → 仍要运行”。
  • 目录链接失败：开启 Windows 开发人员模式，或由管理员完成首次同步。
  • 路径过长：使用 D:\GuthonCodeToolData 等短路径，并按公司策略启用长路径支持。
  • 终端环境变量未生效：关闭并重新打开 VS Code 和 PowerShell。

9. 升级和迁移

  1. 从最新 Release 下载当前系统应用、VSIX 和 GuthonBridge。
  2. 关闭正在运行的同步任务和 Bridge。
  3. 用新应用替换旧应用；路径不变时 VS Code 无需重新初始化。
  4. 从 VSIX 重新安装扩展，并重新加载 VS Code。
  5. 替换 Bridge 前备份自己的 extension/host-config.js，然后重新加载 Chrome 扩展。
  6. 运行“检查本地环境”，再选择一个产品和一个项目分别执行完整同步。

升级时不要删除“本地数据目录”。迁移电脑时，先安全复制整个本地数据目录，再在新电脑重新执行“设置工作空间”。

10. 常见问题与验收

左侧没有“Guthon Nexus”图标

确认 VSIX 已安装并启用，执行“Developer: Reload Window”；仍未出现时卸载旧版本后重新安装当前 Release 的 VSIX。

点击功能后提示启动失败

重新执行“设置/切换工作空间”，选择未改名、未移动且属于当前系统的应用。macOS 同时检查执行权限。

项目树没有显示某个产品或项目

打开 products.yaml 或 projects.yaml，检查 ID、名称和 datasource 是否填写正确，保存后点击 Nexus 刷新。

Bridge 显示无法连接

  1. 确认 Guthon Nexus 面板显示 Bridge“运行中”。
  2. 访问 http://127.0.0.1:17361/health。
  3. 停止后重新启动 Bridge，并在“输出 → Guthon Bridge”查看第一条错误。
  4. 若错误包含 EADDRINUSE，关闭其他终端或旧版工具中占用 17361 的 Bridge，再从 Nexus 启动。
  5. 重新加载 Chrome 扩展并刷新谷神页面。

Workcopy 与 readonly 不一致

先打开 diff.md 确认需要保留的内容。不确定时不要覆盖，请联系负责人处理。

SVN SCM 显示“外部修改”

点击“管理本地源码变更”查看差异，再选择保存或撤销。如果显示冲突、新增或删除，不要强制操作，请联系负责人处理。
