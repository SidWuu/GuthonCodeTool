i

macOS 与 Windows 的 VS Code 操作、配置结构和日常工作流相同；只有应用文件名和系统安全提示不同。

普通使用不需要克隆仓库、安装 Python、安装 Node.js 或创建虚拟环境。

1. 准备与下载

开始前准备 VS Code、Chrome、数据库只读连接信息、产品/项目配置，以及公司提供的 AI 规范文件。

打开 GitHub Releases 或 Gitee Releases ，在同一个版本下载：

  • macOS Apple Silicon：GuthonCodeTool-macos-arm64.zip
  • Windows x64：GuthonCodeTool-windows-x64.exe
  • VSCode扩展 Guthon Nexus：GuthonCodeTool-vscode.vsix
  • Chrome扩展 Guthon Bridge：GuthonCodeTool-chrome.zip
  • 内部配置文件/AI规范文件：http://192.168.15.110:8088/docs/

建议固定两个目录位置：

text 
应用目录：只放 GuthonCodeTool 应用、Guthon Bridge、Guthon Nexus
本地数据目录：长期保存 config、var、源码、索引和 Workcopy

2. 安装应用和 VS Code 扩展

2.1 macOS

  1. 确认 Mac 为 Apple 芯片：菜单“关于本机”中的芯片应为 M1、M2、M3、M4 或后续型号。
  2. 解压 GuthonCodeTool-macos-arm64.zip，将其中的 GuthonCodeTool 放入固定应用目录。
  3. 如果文件没有执行权限，在终端执行：
bash
chmod +x "/你的应用目录/GuthonCodeTool"

若系统阻止运行，请先确认文件来自本项目 Release，再打开“系统设置 → 隐私与安全性”，对被阻止的 GuthonCodeTool 选择“仍要打开”。

2.2 Windows

  1. 把 GuthonCodeTool-windows-x64.exe 放到固定目录，例如 D:\GuthonCodeTool\。
  2. 不要放进经常清理的“下载”或临时目录。
  3. 若 SmartScreen 拦截，先确认文件来自本项目 Release，再选择“更多信息 → 仍要运行”。

2.3 安装 VSIX

  1. 打开 VS Code 的“扩展”面板。
  2. 点击右上角 ...，选择“从 VSIX 安装...”。
  3. 选择 GuthonCodeTool-vscode.vsix。
  4. 安装后执行“Developer: Reload Window”或重新启动 VS Code。
  5. 确认左侧活动栏出现“Guthon Nexus”图标。

3. 初始化工作区

  1. 点击 VS Code 左侧“Guthon Nexus”。
  2. 展开“工作区”，单击“初始化工作区”。
  3. 在确认框点击“执行”。
  4. 选择当前系统的 GuthonCodeTool 应用。
  5. 选择长期保存私有数据的本地数据目录；可以选择空目录。
  6. 等待输出面板显示 GuthonCodeTool 完成：setup。

工作区已初始化后，再次点击“初始化工作区”会提示是否切换。确认后选择新的本地数据目录，工具会在新目录创建缺失配置；取消确认或目录选择时继续使用原工作区。切换不会删除、迁移或修改旧工作区。

普通用户保持“工作区 → 运行模式：发行模式”。需要随时修改 Python 脚本的维护者可单击该项切换为“调试模式”，首次选择 GuthonCodeTool 源码仓库根目录；仓库必须存在 .venv 和 scripts/guthon_tool.py。之后 Nexus 面板操作和 Bridge 拉取都会直接运行最新源码，无需重新构建应用。切回发行模式不会改变本地数据目录。

初始化会创建缺失的五个配置模板，不会覆盖已经存在的配置。完成后目录为：

text
<本地数据目录>/
├── config/
│   ├── datasource.yaml
│   ├── products.yaml
│   ├── projects.yaml
│   ├── source-tables.yaml
│   └── sync.yaml
└── var/  # 第一次同步或放入 AI 规范后出现

4. 填写配置和放置 AI 规范

在“Guthon Nexus → 工作区 → 配置文件”中单击文件名即可编辑。优先使用公司提供的真实配置；不要把数据库密码、源码或配置提交到公开仓库。

  • datasource.yaml：数据库连接。配置引用环境变量时，必须在启动 VS Code 前设置对应变量，并重启 VS Code。
  • products.yaml：产品 ID、名称和 datasource。
  • projects.yaml：项目 ID、名称、datasource 和继承产品。
  • source-tables.yaml：PAGE、过程函数和系统脚本的语义字段映射，通常直接使用公司提供版本；真实表名和字段名只保存在本机配置中。
  • sync.yaml：把 sync.ACTIVE 改为当前产品或项目，并填写子系统别名和未签入源码用户白名单。
yaml
sync:
  ACTIVE: products.<产品ID>
# 或
sync:
  ACTIVE: projects.<项目ID>

将内部 AI 规范保持原目录层级复制到本地数据目录，至少包括：

text
<本地数据目录>/var/AGENTS.md
<本地数据目录>/var/docs/GUSHEN_DEVELOPMENT_BASELINE.md
<本地数据目录>/var/docs/谷神模块开发规范.md
<本地数据目录>/var/docs/谷神方言API/custom.md
<本地数据目录>/var/docs/谷神方言API/java.md
<本地数据目录>/var/docs/谷神方言API/javascript.md
<本地数据目录>/var/docs/谷神方言API/sql.md

5. 首次初始化和同步

  1. 确认 sync.yaml 的 ACTIVE 和子系统范围正确。
  2. 点击“维护 → 检查本地环境”，确认输出没有 FAIL。
  3. 点击“源码 → 初始化源码索引”，确认后等待完成。
  4. 点击“配置数据 → 同步当前 ACTIVE 全部资料”。
  5. 检查输出依次出现源码与索引、数据库表结构、单据类型、系统脚本和视图。

同步期间不要修改 ACTIVE。任何一步失败，后续步骤会停止，应先按输出面板中的第一条错误处理。

结果集中保存在本地数据目录的 var/ 中。日常开发只修改 var/source/workcopy，不要修改 var/source/readonly。

6. 安装和启动 Bridge

只使用 VS Code 同步和导出功能时可以跳过本章。需要从谷神网页拉取当前对象、复制字段或快捷跳转时才需要 Bridge。

6.1 加载 Chrome 扩展

  1. 解压 GuthonCodeTool-chrome.zip 到固定目录。
  2. 按内部环境修改 extension/host-config.js，不要扩大到无关地址。
  3. 打开 chrome://extensions，开启“开发者模式”。
  4. 点击“加载已解压的扩展程序”，选择解压目录中的 extension。
  5. 把 Guthon Bridge 固定到 Chrome 工具栏。

6.2 启动本地服务

  1. 打开 VS Code 左侧“Guthon Nexus”面板。
  2. 单击“启动 Guthon Bridge”。Nexus 自动使用初始化时选择的应用和本地数据目录。
  3. 面板显示“运行中 · 127.0.0.1:17361”后即可使用；单击“停止 Guthon Bridge”可关闭服务。

Bridge 服务已经包含在 VSIX 中，由 Guthon Nexus 使用 VS Code 自带的 Node 运行时启动。普通用户无需安装 Node.js、设置环境变量或保持终端窗口运行。Bridge 运行中切换工作区时，Nexus 会自动使用新目录重启。也可以打开 http://127.0.0.1:17361/health，看到 {"ok":true} 即表示服务正常。

升级到该方式后，不要再同时从终端执行旧的 npm run start:bridge。如果输出出现 EADDRINUSE 127.0.0.1:17361，说明已有 Bridge 占用端口；先关闭原终端中的服务，再回到 Guthon Nexus 启动。

7. 日常工作流

text
确认或切换 sync.ACTIVE
        ↓
同步当前 ACTIVE 全部资料
        ↓
启动 Bridge，从谷神页面拉取目标 Workcopy
        ↓
VS Code / AI 只分析和修改 Workcopy
        ↓
“检查或打包 Workcopy”生成状态和差异
        ↓
人工复制回谷神平台并测试、提交、签入
        ↓
再次拉取，确认基线刷新
  1. 开始开发前，在侧边栏打开 sync.yaml，确认 ACTIVE。
  2. 切换产品或项目后，执行“同步当前 ACTIVE 全部资料”。
  3. 在谷神过程函数、模块、数据表、单据类型、视图或系统脚本页面使用 Bridge。
  4. 打开 Bridge 返回的 Workcopy 路径；AI 先读取 var/AGENTS.md 和命中的规范。
  5. 通过“维护 → 检查或打包 Workcopy”查看状态、生成差异报告或交付物。
  6. 在谷神平台人工签出并回写，完成测试、提交和签入。

工具不会自动回写平台，这是防止误覆盖的安全边界。

8. 系统差异和解决步骤

macOS

  • 当前只提供 Apple Silicon 应用，Intel Mac 暂不支持。
  • 应用没有执行权限：执行 chmod +x 后重新选择应用。
  • Gatekeeper 阻止：确认下载来源后，在“隐私与安全性”中选择“仍要打开”。
  • 终端设置的数据库环境变量未被 VS Code 读取：从同一终端启动 VS Code，或按公司方式配置用户环境后重启 VS Code。

Windows

  • 当前只提供 Windows x64 EXE。
  • SmartScreen 阻止：确认下载来源后使用“更多信息 → 仍要运行”。
  • 目录链接失败：开启 Windows 开发人员模式，或由管理员完成首次同步。
  • 路径过长：使用 D:\GuthonCodeToolData 等短路径，并按公司策略启用长路径支持。
  • 终端环境变量未生效：关闭并重新打开 VS Code 和 PowerShell。

9. 升级和迁移

  1. 从最新 Release 下载当前系统应用、VSIX 和 GuthonBridge。
  2. 关闭正在运行的同步任务和 Bridge。
  3. 用新应用替换旧应用；路径不变时 VS Code 无需重新初始化。
  4. 从 VSIX 重新安装扩展，并重新加载 VS Code。
  5. 替换 Bridge 前备份自己的 extension/host-config.js，然后重新加载 Chrome 扩展。
  6. 运行“检查本地环境”，再执行一次当前 ACTIVE 同步。

升级时不要删除本地数据目录。配置、AI 规范、readonly、Workcopy、SQLite 和日志都保存在该目录，与应用版本分离。

迁移电脑时，应安全复制整个本地数据目录，再在新电脑执行一次“初始化工作区”选择新应用和该目录；数据库凭据和系统环境变量需按公司要求重新配置。

10. 常见问题与验收

左侧没有“Guthon Nexus”图标

确认 VSIX 已安装并启用，执行“Developer: Reload Window”；仍未出现时卸载旧版本后重新安装当前 Release 的 VSIX。

点击功能后提示启动失败

重新执行“初始化工作区”，选择未改名、未移动且属于当前系统的应用。macOS 同时检查执行权限。

同步只得到一个产品或项目的数据

同步范围由 sync.ACTIVE 决定。切换 ACTIVE 后重新执行“同步当前 ACTIVE 全部资料”，工具不会把多个 ACTIVE 混到同一索引。

Bridge 显示无法连接

  1. 确认 Guthon Nexus 面板显示 Bridge“运行中”。
  2. 访问 http://127.0.0.1:17361/health。
  3. 停止后重新启动 Bridge，并在“输出 → Guthon Bridge”查看第一条错误。
  4. 若错误包含 EADDRINUSE，关闭其他终端或旧版工具中占用 17361 的 Bridge，再从 Nexus 启动。
  5. 重新加载 Chrome 扩展并刷新谷神页面。

Workcopy 显示冲突

不要删除基线或强制覆盖。比较本地修改与平台最新源码，确认需要保留的内容并人工处理后再拉取。
