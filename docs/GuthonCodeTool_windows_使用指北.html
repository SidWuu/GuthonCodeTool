0. 先看懂这个工具做什么

GuthonCodeTool 把谷神平台里的源码、调用索引、表结构、单据类型、系统脚本和视图拉到本机，形成适合本地编辑和 AI 分析的工作区。

完整工作流只有这一条：

text
配置当前产品/项目
    ↓
一键拉取源码、索引和平台元数据
    ↓
从 readonly 创建 workcopy
    ↓
VS Code / AI 只修改 workcopy
    ↓
检查 diff
    ↓
人工复制回谷神平台
    ↓
在平台保存、测试、提交、签入
    ↓
再次拉取，确认本地基线已刷新

务必记住：

  • var/source/readonly/ 是上游只读镜像，禁止修改。
  • var/source/workcopy/ 是本地开发副本，只改这里。
  • 工具不会自动把代码写回谷神平台，也不会自动签出、提交或签入。
  • var/、数据库账号、源码和业务资料都是私有内容，禁止提交到公开仓库。
  • 本地运行 AI 不代表源码一定不会发送给 AI 服务；只能使用公司批准的 AI 账号和产品。

1. 安装前需要准备的资料

公开仓库只包含工具代码。第一次安装前，从谷神开发平台和 192.168.15.110:8088 获取以下信息：

  1. 数据库连接信息：
    • 产品库地址、端口、库名、只读账号和密码。
    • 项目库地址、端口、库名、只读账号和密码。
  2. 公司已经填写好的配置，或以下配置值：
    • 产品 ID、产品名称。
    • 项目 ID、项目名称、继承的产品 ID。
    • 需要同步的子系统别名。
    • 谷神源码表和字段映射。
    • 你的谷神用户 ID。
  3. 谷神开发规范移植包，至少应包含：
text
var/
├── AGENTS.md
└── docs/
    ├── GUSHEN_DEVELOPMENT_BASELINE.md
    ├── 谷神模块开发规范.md
    ├── 谷神方言API/
    │   ├── java.md
    │   ├── javascript.md
    │   ├── sql.md
    │   └── custom.md
    └── 谷神开发模式/
        ├── 页面脚本模式.md
        ├── 后端脚本模式.md
        ├── SQL与报表模式.md
        └── 外部接口模式.md

如果拿不到源码表字段映射或开发规范，不要自己猜，先找负责人补齐。

2. 一次性安装前置工具

2.1 打开 PowerShell

按 Win 键，输入 PowerShell，打开“Windows PowerShell”或“终端”。

推荐安装 Windows Terminal

后续命令都粘贴到这个窗口中执行。

2.2 使用 winget 安装

逐条执行：

powershell
winget install --id Git.Git -e --source winget
winget install --id Python.Python.3.12 -e --source winget
winget install --id OpenJS.NodeJS.LTS -e --source winget
winget install --id Microsoft.VisualStudioCode -e --source winget
winget install --id Google.Chrome -e --source winget

如果系统提示是否同意协议，输入 Y。

如果没有 winget，分别从官网下载并安装：

  • Git：https://git-scm.com/download/win
  • Python：https://www.python.org/downloads/windows/
  • Node.js LTS：https://nodejs.org/
  • VS Code：https://code.visualstudio.com/Download
  • Chrome：https://www.google.com/chrome/

手动安装 Python 时必须勾选：

text
Add python.exe to PATH

2.3 关闭并重新打开 PowerShell

安装完成后关闭当前窗口，再打开一个新的 PowerShell。

执行：

powershell
git --version
python --version
node --version
npm --version
code --version

每条命令都能显示版本号才算通过。

最低要求：

  • Python 3.10 或更高。
  • Node.js 使用当前 LTS 版本。

如果 python 打开 Microsoft Store 或提示找不到命令，改用：

powershell
py -3.12 --version

后续创建虚拟环境时也把 python 换成 py -3.12。

3. 下载 GuthonCodeTool

3.1 创建一个短路径工作目录

不要放到 OneDrive、桌面或层级很深的中文目录中。推荐使用：

powershell
New-Item -ItemType Directory -Force C:\Work
Set-Location C:\Work

3.2 克隆仓库

powershell
git clone https://github.com/SidWuu/GuthonCodeTool.git
Set-Location C:\Work\GuthonCodeTool

确认当前目录：

powershell
Get-Location

应显示：

text
C:\Work\GuthonCodeTool

Windows 深层目录较多，建议允许 Git 处理长路径：

powershell
git config --global core.longpaths true

4. 创建 Python 环境

在仓库根目录执行：

powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install pymysql PyYAML

验证：

powershell
.\.venv\Scripts\python.exe --version
.\.venv\Scripts\python.exe -c "import pymysql, yaml; print('Python 依赖正常')"

看到 Python 依赖正常 即通过。

本工具的 Python 代码主要使用标准库：

  • pymysql 用于连接 MySQL。
  • PyYAML 用于读取 YAML 配置。
  • 不需要安装 requirements 文件。

5. 放入私有开发规范

公开仓库中的 var/ 默认只有说明文件。把负责人提供的移植包中 var/ 下的全部内容，合并复制到：

text
C:\Work\GuthonCodeTool\var\

复制后至少应存在：

text
C:\Work\GuthonCodeTool\var\AGENTS.md
C:\Work\GuthonCodeTool\var\docs\GUSHEN_DEVELOPMENT_BASELINE.md
C:\Work\GuthonCodeTool\var\docs\谷神模块开发规范.md
C:\Work\GuthonCodeTool\var\docs\谷神方言API\java.md
C:\Work\GuthonCodeTool\var\docs\谷神方言API\javascript.md
C:\Work\GuthonCodeTool\var\docs\谷神方言API\sql.md

PowerShell 检查：

powershell
Test-Path .\var\AGENTS.md
Test-Path .\var\docs\GUSHEN_DEVELOPMENT_BASELINE.md
Test-Path .\var\docs\谷神方言API\java.md

三条都返回 True 才继续。

建议把 var/ 初始化为本机私有 Git 仓库：

powershell
git -C var init

不要给 var 配置公开远端。

6. 创建并填写配置

6.1 从模板复制配置

在仓库根目录执行：

powershell
Copy-Item .\config\example\datasource.example.yaml .\config\datasource.yaml
Copy-Item .\config\example\products.example.yaml .\config\products.yaml
Copy-Item .\config\example\projects.example.yaml .\config\projects.yaml
Copy-Item .\config\example\source-tables.example.yaml .\config\source-tables.yaml
Copy-Item .\config\example\sync.example.yaml .\config\sync.yaml

这些真实配置已被根仓库 .gitignore 忽略，不应提交。

6.2 最省事的配置方式

优先让负责人提供已经脱敏分发、适合你所在项目的四个文件：

text
products.yaml
projects.yaml
source-tables.yaml
sync.yaml

你通常只需要调整：

  • sync.ACTIVE
  • systems.include.system_aliases
  • rules.allow_unchecked_check_out_user_ids
  • 本机数据库环境变量

不要自行猜测 source-tables.yaml 中的表名和字段名。

6.3 设置当前产品或项目

用 VS Code 打开：

text
config\sync.yaml

开发产品时：

yaml
sync:
  ACTIVE: products.demo-product

开发项目时：

yaml
sync:
  ACTIVE: projects.demo-project

把示例 ID 换成负责人提供的真实 ID。

ACTIVE 会同时决定：

  • 拉取哪个产品或项目。
  • 使用哪个 SQLite 索引库。
  • 从哪里创建工作副本。
  • 表结构、单据类型、系统脚本和视图连接哪个数据库及保存到哪个产品或项目目录。

每次切换 ACTIVE 后，都先确认配置，再执行统一同步脚本。

6.4 配置子系统

在 config\sync.yaml 中填写需要同步的子系统别名：

yaml
systems:
  include:
    system_aliases:
      - demo.system

有多个子系统时：

yaml
systems:
  include:
    system_aliases:
      - demo.system.one
      - demo.system.two

6.5 配置允许读取的未签入源码

把自己的谷神用户 ID 填入：

yaml
rules:
  allow_unchecked_check_out_user_ids:
    - U00000XXXX

工具只读取：

  • 已签入源码。
  • 或签出人位于该名单中的未签入源码。

6.6 设置数据库环境变量

config\datasource.yaml 默认从环境变量读取数据库凭据。先在当前 PowerShell 窗口设置：

powershell
$env:GUSEN_PRODUCT_DB_HOST = "产品库地址"
$env:GUSEN_PRODUCT_DB_PORT = "3306"
$env:GUSEN_PRODUCT_DB_NAME = "产品库名"
$env:GUSEN_PRODUCT_DB_READONLY_USER = "产品库只读用户名"
$env:GUSEN_PRODUCT_DB_READONLY_PASSWORD = "产品库只读密码"

$env:GUSEN_PROJECT_DB_HOST = "项目库地址"
$env:GUSEN_PROJECT_DB_PORT = "3306"
$env:GUSEN_PROJECT_DB_NAME = "项目库名"
$env:GUSEN_PROJECT_DB_READONLY_USER = "项目库只读用户名"
$env:GUSEN_PROJECT_DB_READONLY_PASSWORD = "项目库只读密码"

把引号中的中文占位内容替换为负责人提供的真实值。

这些设置只在当前 PowerShell 窗口有效。需要长期使用时，在 Windows 中搜索“编辑账户的环境变量”，把同名变量添加到“用户变量”，然后重新打开 PowerShell。

安全要求：

  • 不要把密码发到群聊、截图或 AI 对话中。
  • 不要把真实密码直接写进本文档。
  • 数据库账号必须是只读账号。

7. 首次环境检查和同步

7.1 先做只读诊断

在仓库根目录执行：

powershell
.\.venv\Scripts\python.exe .\scripts\doctor.py

正常结果至少应包含：

text
[PASS] python
[PASS] node
[PASS] config
[PASS] vscode-data
[WARN] bridge

Bridge 尚未启动时显示 WARN 是正常的。

任何 FAIL 都要先处理，不要继续同步。

7.2 初始化索引

powershell
.\.venv\Scripts\python.exe .\scripts\run_sync_once.py --init-only

7.3 首次一键同步

先确认已连接公司内网或 VPN，再执行：

powershell
.\.venv\Scripts\python.exe .\scripts\sync_active_all.py

脚本固定依次执行：源码拉取与 SQLite 建索引、数据库表结构、单据类型、系统脚本、视图。任一步失败立即停止；每一步开始前都会复核 ACTIVE。首次同步可能较慢。

7.4 检查同步结果

命令结束且没有报错后，检查：

powershell
Get-ChildItem .\var\source\readonly
Get-ChildItem .\var\runtime\index -Recurse -Filter *.db
Get-ChildItem .\var\database\schema
Get-ChildItem .\var\database\billtype
Get-ChildItem .\var\database\views

应看到：

  • 当前产品或项目的只读源码和系统脚本目录。
  • 当前 ACTIVE 对应的 SQLite 数据库。
  • 表结构、单据类型和视图输出目录。

需要单独重跑某一类内容时，才直接执行对应导出脚本：

powershell
.\.venv\Scripts\python.exe .\scripts\export_table_schema_sql.py
.\.venv\Scripts\python.exe .\scripts\export_bill_type_sql.py
.\.venv\Scripts\python.exe .\scripts\export_system_script_sql.py
.\.venv\Scripts\python.exe .\scripts\export_view_sql.py

输出通常位于：

text
var\database\schema\
var\database\billtype\
var\database\views\
var\source\readonly\...\scripts\

只想重跑或筛选部分内容时再使用单项脚本参数，不要把它们当成切换 ACTIVE 后的固定步骤。

8. 安装谷神 VS Code 离线补全扩展

这个扩展提供谷神 API 补全、悬浮说明和本地过程函数跳转。它和 AI 扩展不是同一个东西。

8.1 用界面安装

  1. 打开 VS Code。
  2. 按 Ctrl+Shift+X 打开扩展面板。
  3. 点击扩展面板右上角 ...。
  4. 选择 Install from VSIX...。
  5. 选择：
text
C:\Work\GuthonCodeTool\plugins\GuthonVSCodeExtension\gushen-vscode-completion\gushen-vscode-completion-0.1.0.vsix
  1. 按 Ctrl+Shift+P。
  2. 执行 Developer: Reload Window。

8.2 验证

用 VS Code 打开仓库：

powershell
Set-Location C:\Work\GuthonCodeTool
code .

打开一个 .vm 文件。如果语言模式不是 Java：

  1. 点击 VS Code 右下角语言名称。
  2. 选择 Configure File Association for '.vm'...。
  3. 选择 Java。

测试：

  • Java/VM 文件输入 sql、sqlh 或谷神 API 前缀，应看到补全。
  • 输入 baseTools.、dateTools.、decimalTools. 等前缀，应看到项目自定义工具 API 补全。
  • 把鼠标停在谷神 API 上，应看到签名和说明。
  • 光标放到静态过程函数调用的方法名上，按 Ctrl+Click 或 F12，应跳到本地 source.vm。

自定义 API 统一记录在 var\docs\谷神方言API\custom.md，不区分谷神 1.5 或 2.0；同步其他 API 文档时不会覆盖该文件。

9. 安装 Guthon Bridge Chrome 扩展

Guthon Bridge 由两部分组成：

  • Chrome 扩展：读取当前谷神开发页面。
  • 本地 Bridge 服务：把浏览器操作转成 GuthonCodeTool 命令。

两部分必须同时运行。

9.1 配置允许访问的谷神地址

用 VS Code 打开：

text
plugins\GuthonBridge\extension\host-config.js

根据负责人提供的开发平台地址修改：

javascript
const config = {
  protocols: ["http:", "https:"],
  ipRanges: ["192.168.0.0/16"],
  domainSuffixes: ["dev.example.com"],
  pathPrefixes: ["/guthon/"]
};

填写原则：

  • 内网 IP 使用 IPv4 CIDR，例如 192.168.0.0/16。
  • 域名填写后缀，例如 dev.example.com。
  • 路径按实际谷神地址填写。
  • 不要为了省事允许所有网站。

9.2 在 Chrome 中加载扩展

  1. Chrome 地址栏打开 chrome://extensions。
  2. 打开右上角“开发者模式”。
  3. 点击“加载已解压的扩展程序”。
  4. 选择：
text
C:\Work\GuthonCodeTool\plugins\GuthonBridge\extension
  1. 把 Guthon Bridge 固定到 Chrome 工具栏。

以后修改 host-config.js 或扩展代码后：

  1. 回到 chrome://extensions。
  2. 点击 Guthon Bridge 卡片上的“重新加载”。
  3. 刷新谷神开发平台页面。

9.3 在 Windows 中启动本地 Bridge

每次启动 Bridge 都使用下面三条命令：

powershell
Set-Location C:\Work\GuthonCodeTool
$env:GUTHON_HUB_PYTHON = (Resolve-Path .\.venv\Scripts\python.exe).Path
Set-Location .\plugins\GuthonBridge
npm run start:bridge

看到服务监听 127.0.0.1:17361 后，不要关闭这个 PowerShell 窗口。

这里必须显式设置 GUTHON_HUB_PYTHON，因为仓库当前默认 Python 路径是 POSIX 路径，Windows 需要指定 .venv\Scripts\python.exe。

9.4 验证 Bridge

Chrome 打开：

text
http://127.0.0.1:17361/health

应返回包含：

json
{"ok":true}

也可以新开一个 PowerShell，在仓库根目录执行：

powershell
.\.venv\Scripts\python.exe .\scripts\doctor.py

此时 bridge 应为 PASS。

10. Guthon Bridge 怎么用

10.1 拉取过程函数或页面源码

  1. 保持 Bridge PowerShell 窗口运行。
  2. 在 Chrome 打开谷神过程函数页或模块开发页。
  3. 点击 Guthon Bridge 图标。
  4. 确认扩展识别到正确对象。
  5. 点击“拉取源码表版本”。
  6. 成功后复制或记住返回的 workcopy 路径。
  7. 在 VS Code 中打开该 workcopy。

源码表拉取后，工具会：

  • 更新 readonly 上游镜像。
  • 创建或检查 workcopy。
  • 本地未修改时刷新基线。
  • 本地和远端分叉时拒绝覆盖并提示冲突。

10.2 拉取表结构

  1. 打开谷神数据表管理页。
  2. 选择数据源。
  3. 可选：勾选一个或多个数据表。
  4. 点击“拉取表结构”。

不勾选时拉取当前数据源下全部表；勾选时只拉取选中表。

10.3 拉取单据类型

  1. 打开谷神单据类型页。
  2. 选择数据源。
  3. 可选：勾选一个或多个单据类型。
  4. 点击“拉取单据类型”。

10.4 拉取视图源码

  1. 打开谷神视图管理页。
  2. 选择数据源。
  3. 可选：选择具体视图。
  4. 点击“拉取视图源码”。

未选择视图时拉取当前数据源下全部视图；选择后只拉取当前视图。源码保存到 var\database\views\{products|projects}\<名称>\。

10.5 拉取系统脚本

  1. 打开谷神系统脚本页。
  2. 在左侧选择应用系统。
  3. 单击脚本行选中需要修改的脚本。
  4. 点击悬浮按钮“选中拉取”；需要刷新当前应用系统全部脚本时，点击“全部拉取”。

“选中拉取”会更新 readonly，并在 var\source\workcopy\ 创建或安全刷新工作副本，适合本地修改；“全部拉取”只更新 readonly。目录名称采用 <脚本序号>-<脚本类型>[-<脚本描述>]，例如 20000-系统私有JAVASCRIPT-图片预览。

项目 JavaScript 同时存在产品源码和项目覆盖源码时，解析文件按“产品源码在上、项目覆盖源码在下”组合；独立 @inherit(); 或只有产品源码时直接使用产品源码。

config\sync.yaml 中启用 pull_auto_add_git 后，源码、视图和系统脚本拉取只会暂存本次新增且未被忽略的文件，不会暂存已有文件的本地修改，也不会强制添加被 .gitignore 忽略的文件。

10.6 复制模式

  1. 打开模块开发页面。
  2. 点击页面上的“复制模式”，或在扩展弹窗中点击“打开复制模式”。
  3. 查看页面块、表单字段和表格列。
  4. 从右侧文本框复制结构。

10.7 字段平移

  1. 在模块开发页选中来源组件。
  2. 点击“复制字段”。
  3. 勾选需要的字段并复制。
  4. 选中目标组件。
  5. 点击“粘贴字段”。
  6. 人工检查后在谷神平台保存。

字段缓存只保留到页面刷新前，Bridge 不会替你保存平台页面。

13. AI 应该怎样读取本地源码

仓库已经规定了正确顺序，正常情况下 AI 会自动遵守。人工也可以用以下命令求证。

13.1 查候选源码

powershell
.\.venv\Scripts\python.exe .\scripts\query_hub_context.py find "关键字"

例如查过程别名、函数名、页面名、表名或业务词。

13.2 查目标对象和一跳调用关系

powershell
.\.venv\Scripts\python.exe .\scripts\query_hub_context.py context --source-id "源码ID" --fun "函数名"

13.3 为什么不能直接读取全量索引

AI 应优先查询 SQLite 局部上下文，不要一次性读取：

text
source-index.md
invoke-index.md
dynamic-invoke-points.md

这样能减少无关内容和 Token 消耗，也不容易把不同产品或项目的源码混在一起。

13.4 六层知识读取顺序

AI 应按任务按需读取：

  1. var\AGENTS.md
  2. var\docs\GUSHEN_DEVELOPMENT_BASELINE.md
  3. var\docs\谷神模块开发规范.md
  4. var\docs\谷神方言API\
  5. var\docs\谷神开发模式\
  6. 当前业务文档、数据库结构、SQLite 索引、readonly 和 workcopy

不是每次把全部文档都塞给 AI，而是先判断任务类型，再读取命中的部分。

16. 产品和项目同时存在时怎么切换

产品和项目必须分开同步，不能在一个 ACTIVE 中混合。

开发产品：

yaml
sync:
  ACTIVE: products.demo-product

开发项目：

yaml
sync:
  ACTIVE: projects.demo-project

切换后执行：

powershell
.\.venv\Scripts\python.exe .\scripts\doctor.py
.\.venv\Scripts\python.exe .\scripts\sync_active_all.py

注意：

  • 每个 ACTIVE 使用独立 SQLite 索引。
  • 产品和项目有各自 readonly 和 workcopy。
  • 表结构、单据类型、系统脚本和视图也按当前 ACTIVE 分开保存。
  • 统一脚本执行期间如果 ACTIVE 改变，会立即停止后续步骤。
  • 手动拉取时，显式指定的产品或项目必须与 ACTIVE 一致。
  • 项目出现继承标记时，工具会按已配置规则读取产品快照，不要手工把产品源码复制成项目源码。

17. 常见问题

17.1 git、python、node 或 code 不是命令

原因：安装后旧 PowerShell 没有刷新 PATH。

处理：

  1. 关闭所有 PowerShell 和 VS Code。
  2. 重新打开 PowerShell。
  3. 再执行版本检查。
  4. 仍失败时重启 Windows。

17.2 PowerShell 不允许激活虚拟环境

本指南不要求执行 Activate.ps1，直接使用：

powershell
.\.venv\Scripts\python.exe

无需修改 PowerShell 执行策略。

17.3 Missing dependency: pip install pymysql

执行：

powershell
.\.venv\Scripts\python.exe -m pip install pymysql

17.4 YAML 配置报错

执行：

powershell
.\.venv\Scripts\python.exe -m pip install PyYAML

再检查：

  • 缩进只用空格。
  • 同一级字段缩进一致。
  • 列表项前使用 - 。
  • 冒号后有空格。
  • 不要用 Tab。

17.5 数据库连接超时

依次检查：

  1. 是否连接公司内网或 VPN。
  2. 主机、端口和库名是否正确。
  3. PowerShell 环境变量是否仍然存在。
  4. 只读账号是否有效。
  5. 当前 sync.ACTIVE 是否连接了正确的数据源。

不要为了排查把数据库密码发给 AI。

17.6 No gd_system rows match

原因通常是 systems.include.system_aliases 填错，或当前数据库没有对应子系统。

处理：

  1. 向负责人核对别名。
  2. 确认 ACTIVE 对应正确数据库。
  3. 删除自动缓存后重试：
powershell
Remove-Item .\config\system-data.json
.\.venv\Scripts\python.exe .\scripts\sync_active_all.py

删除的只是可重建缓存，不是源码。

17.7 Bridge 显示无法连接

检查：

  1. npm run start:bridge 的 PowerShell 窗口是否仍打开。
  2. http://127.0.0.1:17361/health 是否返回 {"ok":true}。
  3. 是否设置了：
powershell
$env:GUTHON_HUB_PYTHON = "C:\Work\GuthonCodeTool\.venv\Scripts\python.exe"
  1. Chrome 扩展是否已重新加载。
  2. 谷神页面是否刷新。

17.8 Bridge 能启动，但拉取时报 spawn python3 ENOENT

原因：Windows 找不到 Bridge 默认的 python3。

关闭 Bridge，在仓库根目录重新执行：

powershell
$env:GUTHON_HUB_PYTHON = (Resolve-Path .\.venv\Scripts\python.exe).Path
Set-Location .\plugins\GuthonBridge
npm run start:bridge

17.9 Chrome 页面没有按钮

检查：

  1. host-config.js 是否允许当前地址。
  2. Chrome 扩展是否启用。
  3. 修改配置后是否点击“重新加载”。
  4. 是否刷新谷神页面。
  5. 当前页面是否属于扩展支持的谷神开发页面。

17.10 Windows 创建过程函数目录链接失败

多个子系统共用一个数据源时，工具可能创建目录链接。Windows 未允许创建符号链接时会失败。

不要自行扩大系统权限。先让管理员确认以下任一方式：

  • 为 Windows 开启“开发人员模式”。
  • 使用管理员 PowerShell 执行首次同步。
  • 调整同步范围，避免重复子系统映射。

处理完后重新同步。

17.11 路径过长

仓库应放在短路径：

text
C:\Work\GuthonCodeTool

并执行：

powershell
git config --global core.longpaths true

不要放进 OneDrive 的深层目录。

17.12 workcopy 出现 CONFLICT

不要删除 workcopy，不要覆盖 readonly，也不要强制拉取。

处理：

  1. 执行 workcopy.py diff。
  2. 比较本地修改和上游最新代码。
  3. 确认哪一边应保留。
  4. 人工合并后再回写平台。

17.13 AI 修改了 readonly

立即停止，不要把修改复制回平台。

让 AI：

text
撤销本轮对 var/source/readonly 的修改。
只在对应 var/source/workcopy 中重新实现，并重新生成 diff。

如果修改范围不清楚，先用 Git 或文件比较工具核对，不要批量删除。

17.14 AI 给出了普通 Java/JavaScript 写法

text

请重新读取 var/AGENTS.md、命中的开发模式和 var/docs/谷神方言API。

18. 卸载或重装时不要误删的内容

text
config\datasource.yaml

其中 var\ 可能包含：

  • 私有开发规范。
  • 业务文档。
  • readonly 源码。
  • workcopy 本地修改。
  • 表结构和单据类型。
  • 本地 Git 历史。

不要直接删除整个旧目录。先确认 workcopy 已回写、配置已备份，再由负责人指导迁移。
